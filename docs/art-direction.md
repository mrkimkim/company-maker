## 0. 문서의 지위와 의존 전제

### 0.1 지위와 소유권

본 문서는 게임 "회사 경영 시뮬레이션"의 **비주얼 스타일·에셋 단일 정본**이다(README §2.3). 아트 필러, 렌더링 방식, 컬러 시스템, 캐릭터/환경/UI/아이콘의 시각 언어, 모션·VFX 원칙, 에셋 파이프라인을 소유한다. 본 문서와 충돌하는 시각 결정은 무효이며, 변경은 본 문서 개정으로만 이루어진다.

**본 문서는 규칙·화면·수치·톤을 만들지 않는다.** 다음은 명시적으로 범위 밖이며 각 정본을 참조·이행한다.

| 영역 | 정본 | 본 문서의 관계 |
|---|---|---|
| 게임 규칙·엔티티·자원 6종 | `game-design.md` | 시각으로 **표현**만 한다. 자원·규칙 신설 금지 |
| 톤·보이스·세계관·네이밍 | `narrative-tone.md` | 톤 헌장(§0.3)을 시각으로 이행. 모순 금지 |
| 화면 레이아웃·정보구조·플로우 | `ux-design.md` | 화면 구조에 입힐 **비주얼 랭귀지(스킨)**만 제공. 레이아웃은 정의하지 않음 |
| 사운드·음악·SFX | `audio-design.md` | VFX와 타이밍만 맞물림. 오디오는 정의하지 않음 |

### 0.2 의존 전제 (README §1)

- **P1 모바일 우선 · 세로 · 짧은 세션(1~5분) + 방치 플레이** → 세로 구도, 한 손 스캔 가능한 명료함, 저사양·저전력 VFX(§2, §8).
- **P2 F2P + IAP · 비 페이 투 윈** → 결제 재화(다이아)는 코스메틱·편의 표식으로만, 압박형 비주얼 금지(§7.2, 톤 §8).
- **P3 미드코어 · 밝고 경쾌한 스타일라이즈드 2D(플랫/세미플랫) · 친근한 캐릭터** → 본 문서 아트의 최상위 좌표(§1, §2).
- **P4 한/영 1차, 일/중 확장** → 텍스트 최소·아이콘 우선, 무국적 비주얼, 다국어 레이아웃 여백(§6, §7).

### 0.3 톤 헌장의 시각 번역 (narrative-tone.md §0.3 → 아트 이행)

| 톤 헌장 | 아트 이행 원칙 |
|---|---|
| 유능감·장악감, 죄책감·공포·처벌감 배제 | 밝은 명도, 따뜻한 채도, 위기조차 "회복 가능"으로 읽히는 절제된 경고색(§3.4, §8.5) |
| 밝은 오피스 성장 드라마 + 다정한 코미디 | 둥근 실루엣, 부드러운 그림자, 과장되되 상냥한 표정·연출 |
| 목소리는 리아 하나 | 리아를 유일한 상시 캐릭터 앵커로 일관 디자인(§4.6) |
| 직원은 캐릭터, 등급은 성장 여력 ≠ 인간 가치 | 등급별 캐릭터 아트 품질·크기 동일, 프레임 마감만 차등(§4.3) |
| 실패는 상태 | 청산·파산 연출은 담담·존엄, 폭발·조롱 없음(§8.5) |
| 자율 주행 = 믿고 맡긴 팀, AI 로봇 아님 | 위임 표현은 신뢰·안심의 언어, 톱니·로봇·회로 도상 금지(§8.6) |
| 무국적 현대 상업 세계 | 실존 국가·브랜드·랜드마크·민족 코드 배제(§4.5, §5.6) |
| 마일스톤 보상은 감정 비트 | 무보상 순간의 무게를 VFX·연출이 대신 실어 나름(§8.4) |

### 0.4 표기 규약

- **설계 결정:** — 원 요구·정본이 정하지 않은 시각 사항을 본 문서가 확정한 지점. 근거를 한 줄 붙인다. 규칙이 아니라 표현 결정이다.
- 색은 개념·의도로 서술하고, 확정 HEX 팔레트는 프로덕션 스타일 가이드에서 토큰화한다(본 문서는 색 역할·관계·대비 요구까지 확정, 정확한 색값은 §11 열린 질문/스타일 가이드 산출물).
- 수치(픽셀·프레임·MB)는 **아트 측 목표치**이며 하드 예산은 `technical-architecture.md` 소유.

## 1. 아트 필러와 레퍼런스

### 1.1 아트 필러 (4개 — 모든 시각 결정의 기준)

모든 에셋은 아래 4개 필러 중 최소 하나를 강하게 만족해야 하며, 어떤 것도 위반해서는 안 된다.

#### 필러 1 — **따뜻한 유능감 (Warm Competence)**
플레이어가 화면을 볼 때마다 "나는 유능하고, 이 판을 장악하고 있다"고 느끼게 한다. 밝은 명도, 따뜻하고 깨끗한 채도, 둥글고 정돈된 형태. 스프레드시트의 차가움도, 개그의 가벼움도 아니다(P3). 위기·실패 화면조차 절망이 아니라 "다음 수가 보이는" 시각으로 그린다(톤 §8).

#### 필러 2 — **한 손에 들어오는 명료함 (One-Thumb Clarity)**
세로 화면·짧은 세션·다회사 스캔(최대 10사)에서 **0.5초 안에 상태를 읽을 수 있어야 한다.** 정보는 색 하나가 아니라 색+형태+아이콘+라벨의 다중 채널로 인코딩한다(접근성·색맹 안전, §3.5). 저채도 배경 위 고채도 액션 강조로 시선을 유도한다. 장식은 정보를 이긴 적이 없다.

#### 필러 3 — **존엄한 캐릭터 (Dignified Characters)**
직원은 부품이 아니라 사람이다. 무국적·다양성을 자연스럽게 반영하고(§4.5), 등급 C/B/A/S는 "성장 여력"으로만 시각화하여 **낮은 등급을 초라하게 그리지 않는다**(§4.3). 리아는 따뜻하고 유능한 파트너로, 스테레오타입(수동적 비서상·성별 고정)을 피한다(§4.6).

#### 필러 4 — **순회하는 세 세계 (Three Worlds to Tour)**
무역·게임개발·화장품은 공통 뼈대(스키마·공통 영업부)를 공유하되 **분위기·색·리듬을 뚜렷이 다르게** 그려(narrative §4.3), 회사를 오갈 때 "다른 세계를 순회하는" 인지적 다양성을 준다. 단, 공통 영업부와 UI 골격은 세 세계에서 일관되게 유지해 학습 전이를 돕는다(§3.3, §6).

**설계 결정: 4개 필러 중 필러 2(명료함)가 충돌 시 최우선이다.** 근거: P1 모바일 세로·방치·다회사 운영에서 가독성이 무너지면 유능감(필러 1)도 성립하지 않는다 — 아름다움은 읽힌 다음의 문제다.

### 1.2 레퍼런스 방향 (실존 게임/스타일 언어, 텍스트 서술)

각 레퍼런스는 "무엇을 빌리고 무엇을 버리는가"로 명시한다. 어떤 것도 그대로 모사하지 않는다.

| 레퍼런스 | 빌리는 것 | 버리는 것 |
|---|---|---|
| **Two Point 시리즈** (Hospital/Campus) | 밝고 경쾌한 스타일라이즈드 톤, 캐릭터의 상냥한 유머, 관리 대상의 즉각적 가독성 | 3D·아이소메트릭 구조(우리는 2D 세로 카드 기반) |
| **동물의 숲 / Monument Valley** | 다정함, 플랫·파스텔 면 처리, 절제된 셰이딩, 편안한 색 조화 | 과도한 미니멀·탐험 구조(우리는 정보 밀도가 높음) |
| **픽사(캐릭터 언어)** | 따뜻한 실루엣·표정으로 감정 전달, "미소 짓게 하는" 결(narrative §3.2) | 사실적 렌더·시네마틱 무게 |
| **Kairosoft 경영 시뮬 계보** | 친근한 경영 시뮬 관례, 작은 캐릭터로 조직을 표현하는 문법 | 레트로 픽셀·저해상 마감(우리는 프리미엄 세미플랫 벡터) |
| **Marvel Snap / Slay the Spire(카드·희소도 프레임)** | 카드 프레임과 등급 프레임의 "격" 표현 문법, 만족스러운 획득 연출 | 전투·수집 도박성 강조, 등급의 위계적 위압감(우리는 성장 여력으로 순화) |
| **Duolingo(마스코트·플랫 UI)** | 일관된 동반자 캐릭터(리아)로 시스템에 인간미 부여, 밝은 플랫 UI, 친근한 온보딩 | 강박·FOMO 유발 연출(톤 §8 금지) |

**설계 결정: 종합 좌표는 "Two Point의 상냥함 × 동물의 숲의 플랫 파스텔 × 프리미엄 카드 게임의 프레임 격식"이다.** 근거: P3(밝고 경쾌한 스타일라이즈드)와 카드 기반 세로 UI, 등급·희소도 표현 요구를 한 번에 만족하는 교차점이며, 모두 저사양 모바일에서 검증된 계보다.

## 2. 비주얼 스타일 정의

### 2.1 렌더링 방식 — 세미플랫 벡터

**설계 결정: 전 에셋은 "세미플랫 벡터(semi-flat vector)"로 렌더한다 — 플랫 면 채색 + 단일 방향 소프트 음영 1단 + 최소 라인.** 근거:
- **해상도 독립성**: 모바일 DPI 파편화(§9.5)에서 벡터 기반 형태는 다배율(@1x/@2x/@3x)·다기종에서 깨지지 않는다.
- **성능·용량**: 플랫 면은 그라디언트·페인터리 텍스처 대비 아틀라스 용량과 오버드로우가 작아 저사양·방치(저전력)에 유리(§9.6).
- **가독성**: 세로 소형 표시에서 면+실루엣이 디테일보다 잘 읽힌다(필러 2).
- **일관성·물량**: 조합형 캐릭터(§4.4)와 대량 아이콘을 스타일 편차 없이 찍어내려면 규칙화된 플랫 렌더가 필수다.

배제: 두꺼운 페인터리 렌더, 사진 텍스처, 강한 다중 그라디언트, 픽셀아트, 3D 실사. (강조용 미세 그라디언트·글로우는 VFX·프리미엄 프레임에 한정 허용, §8.)

### 2.2 라인 · 셰이딩 · 질감 원칙

| 요소 | 원칙 |
|---|---|
| **라인** | UI·아이콘은 기본 **무외곽선(면 분리로 형태 구획)**, 캐릭터는 얇고 균일한 소프트 라인 또는 라인리스. 라인 색은 순수 검정 금지 — 대상 색의 어두운 톤(색 있는 라인)으로 부드럽게. |
| **셰이딩** | **단일 광원(좌상단 가정) + 음영 1단 + 하이라이트 0~1단**. 셀 셰이딩식 하드 엣지가 아니라 살짝 부드러운 경계. 앰비언트 오클루전은 접지 그림자(소프트, 저불투명)로만. |
| **질감** | 원칙적으로 매트(무광) 평면. 질감은 "암시" 수준(미세 노이즈·패턴 오버레이 ≤ 아주 옅게)으로만 허용하며, S등급 프레임·프리미엄 상품 등 특별 표면에서만 광택/홀로그래픽을 쓴다(§4.3, §7.2). |
| **형태 언어** | 둥근 모서리(일관된 코너 반경 토큰), 부드러운 실루엣, 안정적 무게중심. 날카로운 각·불안정 형태는 위기/경고 신호에만 절제 사용. |
| **모서리·여백** | 넉넉한 여백과 라운드로 "따뜻한 유능감"(필러 1)을 만든다. 밀집은 정보 위계로만 정당화. |

### 2.3 세로 화면 구도 원칙

**설계 결정: 모든 핵심 표면은 세로(portrait) 단일 지향으로 구성하며 가로 모드는 지원하지 않는다(런치).** 근거: P1 한 손 조작·세로 우선. 가로 대응은 아키텍처만 열어둔다(README P1).

- **엄지 존(thumb zone)**: 하단 1/3을 주 조작 영역으로 상정, 상단은 상태·타이틀(정확한 배치는 §ux-design). 아트는 이 전제에 맞춰 주요 CTA·카드를 하단 무게로 디자인 가능하게 에셋을 준비한다.
- **수직 스택·카드 리듬**: 세로 스크롤 카드 리스트가 기본 문법. 카드는 세로로 쌓이며 한 손 스와이프에 최적화된 종횡비(가로로 넓고 낮은 카드).
- **세이프 에어리어**: 노치·펀치홀·하단 제스처 바를 침범하지 않도록 배경은 상하로 확장 가능한(overscannable) 에셋으로, 핵심 정보는 세이프 영역 안에.
- **가로 초과 금지**: 넓은 콘텐츠(테이블·긴 카드·차트)는 자체 가로 스크롤 컨테이너로 감싸고, 페이지 몸통은 절대 가로로 밀리지 않는다.
- **배경 레이어**: 도시/오피스 배경은 세로 패럴랙스(원경 스카이라인 + 중경 + 근경) 3레이어로, 콘텐츠 뒤에서 저대비로 깔린다(§5.6).

## 3. 컬러 시스템

색은 **의미(semantic) 우선**으로 설계한다. "예뻐서"가 아니라 "무엇을 뜻하는가"로 배정하며, 정확한 HEX는 스타일 가이드에서 토큰(`color/...`)으로 확정한다(본 문서는 역할·관계·대비 요구를 확정).

### 3.1 마스터 팔레트 구조 (4개 레이어)

| 레이어 | 역할 | 방향 |
|---|---|---|
| **뉴트럴(Surface)** | 배경·패널·카드 지면·텍스트 | 라이트 우선의 따뜻한 오프화이트 ~ 소프트 그레이 스케일 + 다크 모드 대응 딥 뉴트럴. 순백/순흑 금지(눈부심·눌림 방지) |
| **브랜드 액센트(Brand)** | 리아·주요 CTA·로고·앱 정체성 | **따뜻한 틸/청록 계열**을 브랜드 상수로 제안 — 신뢰·성장·중립(무국적)의 인상, 세 업종 어디에도 편향되지 않음 |
| **업종 아이덴티티(Industry)** | 회사·부서·카드의 업종 물들임 | 무역/게임개발/화장품 3세트(§3.3). 공통 영업부는 예외로 안정 색 고정 |
| **시맨틱(Semantic)** | 재무 상태·성공/경고·자원·등급 | 상태·자원별 고정 의미색(§3.4, §3.6). 업종 색과 명확히 분리해 혼동 방지 |

**설계 결정: 브랜드 액센트는 업종 색과 별개의 "중립 상수"로 둔다.** 근거: 브랜드 색이 특정 업종 색과 겹치면 그 업종에 편향된 게임처럼 보이고, 리아·CTA가 업종 화면마다 색이 흔들려 학습 전이(필러 4)가 깨진다. 틸/청록은 무역(따뜻)·게임개발(차가운 네온)·화장품(파스텔) 어느 쪽과도 구별되는 중립대에 있다.

### 3.2 라이트/다크 모드

**설계 결정: 라이트 모드를 기본으로 하고 다크 모드를 동등 지원한다.** 근거: 밝고 경쾌한 톤(P3)의 기본값은 라이트이나, 방치·야간·짧은 세션 반복 특성상 다크 모드 수요가 크다. 시맨틱·업종·등급 색은 두 모드에서 **의미 항상성**(같은 뜻=같은 인상)을 유지하도록 각 모드용 톤을 쌍으로 정의한다.

### 3.3 업종별 컬러 아이덴티티

narrative §4.3 무드 표를 색으로 확정한다. 각 업종은 **주조색 + 보조색 + 무드 온도**를 갖는다.

| 업종 | 무드(narrative §4.3) | 주조색 방향 | 보조/글로우 | 온도·채도 | 카드·배경 적용 |
|---|---|---|---|---|---|
| **무역** (입문) | 빠르고 활기찬 상인의 세계 | 앰버·테라코타·크래프트 브라운 | 마켓 틸 포인트 | 따뜻·중~고채도, 활기 | 장터/거래소의 분주한 온기 |
| **게임개발** (상급) | 낭만과 도박의 창작 세계 | 딥 인디고·나이트 네이비 | 네온 마젠타·시안·바이올렛 글로우 | 차갑고 컬러풀·몽환, 대비 큼 | 밤샘 사무실 + 빛나는 출시 화면 |
| **화장품** (중급) | 우아하고 참을성 있는 연구·브랜드 | 소프트 로즈·세이지·크림 | 라벤더·펄 하이라이트 | 파스텔·저채도, 세련·청결 | 미니멀 랩/진열대 |
| **공통 영업부** (전 업종) | 저분산·안정의 밥벌이 | **안정 색 고정(브랜드 인접 차분한 블루/그린)** | — | 중채도·안정 | 업종 무관 **동일 색** 유지 |

**설계 결정: 공통 영업부는 소속 업종의 무드 틴트를 받지 않고 전 업종에서 동일한 "안정 색"을 유지한다.** 근거: narrative §4.3·§12.1 — "어느 회사든 영업부 = 저분산 고정 보상"의 학습 전이를 색으로 강화한다. 영업부만은 순회해도 같은 색이라 안심 신호가 된다.

업종 색은 **틴트(tint) 방식**으로 적용한다: 회사/부서/카드 헤더·프레임·배경 액센트를 물들이되, 본문 텍스트·데이터·시맨틱 색은 물들이지 않아 가독성과 상태 신호를 보존한다.

### 3.4 재무 상태 컬러 시맨틱 (건전/주의/부실/파산)

`game-design.md` §5.6의 재무 상태 머신(건전/부실/파산 + 주의 오버레이)을 색으로 확정한다. 톤 헌장상 **위기조차 공포·처벌로 그리지 않는다**(§0.3) — 경고색은 "긴장"이되 "절망"이 아니다.

| 상태 | 색 방향 | 강도 원칙 |
|---|---|---|
| **건전** | 차분한 그린/틸 (안정·순항) | 과시하지 않는 잔잔한 긍정. 평상 상태이므로 색을 강하게 주지 않음 |
| **주의**(오버레이) | 소프트 앰버 (예측 경고) | 어느 상태 위에도 얹히는 옅은 플래그. "미리 손 쓰면 좋아요" 수준의 온화한 주목 |
| **부실** | 진한 앰버/오렌지 (행동 필요) | 경고를 명확히 하되 붉은 알람은 피함. 복귀 체크리스트를 부르는 "챙겨야 할 색" |
| **파산** | 저채도 뮤트 레드-브라운 (담담한 종료) | 강렬한 순수 적색·해골·폭발 금지. 침착하고 존엄한 "정리"의 색 — 즉시 재기 경로로 시선 이동(§8.5) |

**설계 결정: 위기 스펙트럼을 "그린 → 앰버 → 진한 앰버 → 뮤트 레드브라운"의 단조 온도 상승으로 잡고, 순수 경보 적색(#FF0000류)과 공포 도상을 배제한다.** 근거: narrative §8(죄책감·공포·강박 금지)·§5.6 위기 프레이밍 — 색이 처벌감을 만들면 톤 헌장 위반이다. 앰버 중심 경고는 "행동 유도"이지 "비난"이 아니다.

- **색만으로 상태를 판단하게 하지 않는다**: 각 상태는 전용 아이콘 + 라벨 + (부실/파산은) 텍스처/보더 패턴을 병기(§3.5).

### 3.5 명도·대비·접근성 기준 (§accessibility 연동)

**설계 결정: 본 게임의 색 사용은 WCAG 2.1 AA를 아트 측 최소 기준으로 삼는다. 단 접근성의 최종 정본은 `accessibility-localization.md`이며, 본 절은 그 문서가 상속·확정할 씨앗이다.** 근거: 대비·색맹 안전은 색 시스템을 설계하는 시점에 지켜야 사후 수정 비용이 없다. 값의 확정·검사 프로세스는 접근성 문서 소유.

아트가 산출 시 지키는 요구:
- **텍스트 대비**: 본문 ≥ 4.5:1, 큰 텍스트(굵거나 대형) ≥ 3:1. 업종 틴트 배경 위 텍스트도 이 기준을 넘도록 배경 명도를 제한한다.
- **그래픽/UI 대비**: 아이콘·상태 경계·의미 있는 도형은 인접 색 대비 ≥ 3:1.
- **색 비의존(색맹 안전)**: 재무 상태·등급·자원·자율/직접 태그 등 **의미를 색 하나로만 전달하지 않는다** — 형태·아이콘·라벨·패턴을 반드시 병기. 적/녹 구분(1형·2형 색각), 청/황(3형 색각) 시나리오에서 검증.
- **명도 위계**: 배경 < 카드 지면 < 텍스트/액션의 명도 계단을 일관 유지해 시선 순서를 명도로도 만든다.
- **모션 안전**: 명멸·고대비 플리커 금지(발작 유발 방지), "모션 감소" 설정 시 VFX 강도 하향 대응(§8.7).

### 3.6 자원 컬러 코드 (자원 6종 + 다이아)

자원 아이콘(§7.1)과 연동되는 고정 의미색. **자금과 골드는 반드시 다른 색·형태로 분리한다**(둘 다 "돈"이라 혼동 위험).

| 자원 | 색 방향 | 혼동 방지 포인트 |
|---|---|---|
| 자금(₩) | 민트 그린 (운영 현금) | 골드와 색·형태 완전 분리 |
| 골드 | 딥 골드/황동 (경영자 자산) | 무겁고 메탈릭한 인상 — 현금과 결 다름 |
| 명성 | 골드-퍼플 (격·평판) | 골드 자원과 겹치지 않게 퍼플 편향 |
| 경험치(XP) | 밝은 블루/시안 (성장) | 상승 방향성 |
| 컨디션 | 웜 에너지(옐로-그린 에너지) | 충성도와 분리 — 활력/스태미나 결 |
| 충성도 | 웜 로즈/레드 (유대) | 컨디션과 분리 — 마음/유대 결 |
| **다이아**(결제 재화) | 쿨 시안 크리스탈 | 게임플레이 자원과 뚜렷이 다른 "특별함" |

**설계 결정: 컨디션은 에너지(활력)색, 충성도는 하트(유대)색으로 분리한다.** 근거: 둘 다 직원 상태치라 하트/붉은색으로 겹치기 쉬운데, 컨디션은 소모·회복형 스태미나, 충성도는 마음의 결속으로 의미가 다르다 — 색+형태로 갈라야 스캔 시 오독이 없다.

## 4. 캐릭터 비주얼 시스템

### 4.1 표현 방식 — 상반신 초상 + 조합형 아바타

**설계 결정: 직원의 기본 표현은 "카드 위 상반신 초상(bust portrait)"이며, 조직 화면에서는 축약형 미니 아바타(head chip)를 쓴다.** 근거:
- narrative §4.2가 이미 "초상 + 이름 + 등급 배지 + 스탯 프로필"을 표현 단위로 규정 — 전신은 세로 카드에서 공간 낭비, 순수 아이콘 아바타는 존엄(필러 3)을 해친다.
- 상반신은 표정·의상으로 개성·업종 무드·직무 결을 담기 충분하면서 조합형 물량 통제(§4.4)에 최적.
- 팀/부서 조직도에서는 얼굴 칩(head chip)만으로 밀도 있게 다수를 표시.

표현 계층: **초상(카드 상세) → 반신 칩(리스트) → 얼굴 칩(조직도 다수 표시)** 3단계 LOD.

### 4.2 카드 정보 레이어 (시각 채널 배분)

직원 카드가 실어야 할 정보 채널과 그 시각 인코딩(레이아웃은 §ux-design, 여기서는 시각 언어만):

| 정보 | 시각 채널 |
|---|---|
| 이름 | 로케일 자연 이름(§narrative 5.1), 텍스트 |
| 등급 C/B/A/S | **모서리 등급 배지(문자) + 초상 프레임 마감**(§4.3) |
| 직무 스탯 3종(제작/기획/영업) | 스탯 아이콘 triad + 값, 최고 스탯 강조(§4.7, §7.4) |
| 리더십 | **팀장 보직 시에만** 캡틴 인시그니아 표시(§4.7) |
| 업종 무드 | 카드 헤더·의상 팔레트 틴트(§3.3) |
| 컨디션·충성도 | 소형 상태 미터(에너지/유대 색, §3.6·§7.1) |
| 성격 플레이버 | 한 줄 디스크립터 텍스트(narrative §4.2, 아트는 여백만 확보) |

### 4.3 등급 시각 언어 — C / B / A / S (성장 여력, 인간 가치 아님)

**핵심 원칙(톤 §2.2·§4.2 준수): 등급은 "얼마나 더 빛날 수 있는가(성장 여력)"이지 "현재 가치·인간의 값"이 아니다. 따라서 캐릭터 아트 자체(초상 품질·크기·표정 정성)는 전 등급 동일하며, 차등은 오직 "프레임 마감 + 배지"에만 둔다. C를 회색·초라·슬픈 톤으로 그리는 흔한 가챠 관례를 명시적으로 금지한다.**

**설계 결정: 등급 축은 "채도·가치의 높낮이"가 아니라 "마감의 광채(luster)"로 표현한다 — 담백 → 차분 → 선명 → 광채.** 근거: 성장 여력의 은유는 "아직 무광이지만 닦으면 빛날 수 있음"이다. 광택 축은 C를 폄하하지 않으면서(C도 온전하고 단정한 마감) S의 특별함(§narrative "명성값 하네요")을 준다. 명도·채도를 등급에 연동하면 C가 자동으로 "칙칙한 사람"이 되어 톤 헌장을 위반한다.

| 등급 | 아키타입(narrative) | 프레임 마감 | 배지 | 이펙트 | 금지 |
|---|---|---|---|---|---|
| **C** | 성실한 일꾼("회사의 뼈대") | 깔끔한 무광 프레임(웜 뉴트럴/브론즈 톤) | C 배지 | 없음 | 회색·탈색·슬픈 표정 금지. 단정하고 든든하게 |
| **B** | 숙련 실무자 | 차분한 새틴 프레임(실버-블루) | B 배지 | 없음 | — |
| **A** | 에이스 | 선명한 프레임 + 얇은 광택 테두리(골드-앰버) | A 배지 | 획득 시 소형 반짝 | 과함 금지 |
| **S** | 거물 인재("판을 바꾼다") | 홀로그래픽/프리즘 프레임 + 은은한 상시 시머 | S 배지(특별 형태) | 상시 미세 파티클 + 획득 시 대형 연출(§8.4) | 남발 금지(희소성 보존) |

- **초상·표정 정성은 등급 무관 동일.** C급도 눈빛·미소가 살아 있고 "오늘의 일을 해내는" 든든함이 읽혀야 한다(필러 3).
- 등급 색은 **자원 골드/명성 색과 구별**되도록 프레임 마감 재질감으로 차별화(§3.6 혼동 방지).
- 등급 문자 배지는 색맹 안전을 위해 항상 **문자(C/B/A/S)**를 노출한다 — 프레임 색만으로 등급을 판단하게 하지 않는다(§3.5).

### 4.4 조합형(모듈러) 아바타 — 물량 통제 전략

**설계 결정: 직원 초상은 레이어드 모듈러 조합으로 생성한다(수제 개별 초상 금지).** 근거: 최대 10사 × 수십 명 + 월 갱신 지원자 풀이면 개별 초상은 물량·현지화·용량이 통제 불능이다. 조합형은 유한 파츠로 사실상 무한 다양성을 만들고, 업종 무드 틴트와 다양성 검수를 파츠 단위로 관리하게 한다(narrative §4.2 "조합형 한 줄" 원칙의 시각 대응).

**레이어 슬롯(초상 기준):**

| 슬롯 | 역할 | 대략 파츠 수(런치 목표) |
|---|---|---|
| 두상/얼굴형 | 실루엣 기반 다양성 | 6~8 |
| 피부톤 | 폭넓은 스펙트럼(§4.5) | 8~10 |
| 헤어(스타일 + 색) | 다양성의 핵심 변수 | 스타일 16~20 × 색 8 |
| 눈/표정 세트 | 기본 + 감정 변주(중립/미소/집중/피곤) | 형태 8 × 표정 4 |
| 상의/복장 | **업종 무드로 팔레트 틴트**(§3.3) | 형태 10~12 × 업종 틴트 |
| 액세서리(안경/이어웨어/뱃지 등) | 개성·직무 힌트 | 12~16(없음 포함) |
| 연령 단서(주름·헤어 그레이 등) | 연령 다양성 | 얼굴형·헤어에 내장 |

- 조합 엔진은 파츠 호환성 규칙(레이어 순서·클리핑)을 지키며 결정론적 시드로 생성(같은 직원 = 같은 얼굴 항상성). 시드·생성 로직은 §technical-architecture, 아트는 파츠와 규칙을 공급.
- **업종 무드 반영**: 같은 파츠라도 소속 업종 틴트로 복장 팔레트가 물들어(게임개발=컬러풀, 화장품=파스텔, 무역=웜) "몽상가/장인 연구원/실무 베테랑" 인상을 만든다(narrative §4.2c).
- 표정 세트는 컨디션/이벤트에 가볍게 연동 가능(과로 시 피곤 표정 등 — 연출은 §8, 데이터 연동은 UX/기술).

### 4.5 다양성 · 무국적성

- **피부톤·연령·성별 표현·체형 인상**을 고르게 분포시킨다(narrative §5.1 다양성, §3.3 금지선 준수). 특정 배경으로의 쏠림 금지, 미인 편향 금지.
- **무국적**: 민족 특정 의상·헤어·상징·국가 코드(국기·전통복 등) 배제. 현대 상업 세계의 비즈니스 캐주얼~직무 복장 범위 안에서 표현.
- 성별은 이분법이 아니라 폭넓은 프리젠테이션으로, 직무·등급과 무관하게 분포(이름으로 성능 유추 금지 원칙의 시각 대응 — 외형이 등급·스탯을 암시하지 않게 한다).
- 다양성 검수는 파츠 단위 체크리스트로(§accessibility-localization 연동, 프로세스 정본은 그 문서).

### 4.6 보좌관 리아의 비주얼 컨셉

리아는 게임 유일의 상시 캐릭터 앵커다(narrative §3.1·§4.1).

- **스타일**: 밝고 깔끔한 세미플랫, 단정하지만 친근한 실루엣(narrative §4.1 훅). 비즈니스 캐주얼, 따뜻한 눈매. 스테레오타입(수동적 비서·성적 대상화) 배제 — 유능한 파트너상.
- **화면 존재**: 상시 점유하지 않음(P1 세로 절약). 온보딩·알림·리포트 요약·마일스톤 축하에서 **말풍선 + 반신 버스트/얼굴 칩**으로 등장(배치는 §ux-design). 코너 앵커로 등장하는 소형 버스트가 기본.
- **표정 세트**: 감정 비트를 실어야 하므로 최소 세트 확보 — 밝은 안내(기본), 진심 축하(하이 순간), 담담·따뜻(나쁜 소식), 집중(중요 안내), 장난기(가벼운 위트). narrative §3.2·§6의 톤과 1:1.
- **성장 코스메틱**: 플레이어 성장에 맞춰 미묘한 의상·소품의 격 상승(초반 실무 → 후반 참모)으로 호칭 승격(대표님→회장님)과 정합. 과하지 않게, 알아채면 흐뭇한 수준.
- **시그니처 색**: 브랜드 액센트(틸/청록, §3.1)를 리아의 시그니처로 부여해 어느 업종 화면에서도 "리아=우리 편"으로 즉시 식별.
- **성별·외형·연령·최종 캐스팅은 열린 질문(§narrative 열린질문 1)** — 포용성·현지화 친화를 최우선 기준으로 아트/오디오와 확정. 본 문서는 성별 중립적 또는 로케일 선택 가능 방향을 우선 검토할 것을 권장한다(§11).

### 4.7 직무 스탯 · 리더십의 시각 단서

**설계 결정: 직무 스탯은 "하드 클래스"가 아니라 라이트 디스크립터이므로(narrative §4.2b), 시각 단서도 강한 유니폼이 아니라 약한 힌트로 준다.** 근거: 한 직원은 세 스탯을 모두 갖고 최고 스탯이 인상을 만든다 — 복장을 직무로 고정하면 조합형 다양성과 충돌한다.

| 스탯 | 아키타입 | 약한 시각 힌트(액세서리/소품 수준) | 스탯 아이콘(§7.4) |
|---|---|---|---|
| 제작 | 만드는 사람 | 이어웨어·도구·작업 소품 계열 | 도구/브러시 모티프 |
| 기획 | 설계하는 사람 | 태블릿·안경·보드 계열 | 전구/블루프린트 모티프 |
| 영업 | 연결하는 사람 | 사원증·핸드셋·정장 계열 | 말풍선/악수 모티프 |
| 리더십 | 이끄는 사람 | **팀장 보직일 때만** 캡틴 인시그니아(핀/리본) | 지휘 배지/깃발 모티프 |

- 카드의 **최고 직무 스탯**은 해당 스탯 아이콘을 하이라이트 + 색 강조로 표시해 "한 줄 인상"을 시각화(narrative §4.2b).
- **리더십은 팀장 보직에서만 발현**(§6.7)하므로, 팀장으로 임명된 직원에게만 캡틴 인시그니아가 붙는다(왕관식 위계 도상 금지 — "이끄는 동료"의 결). 표류 팀(팀장 공석)은 인시그니아 자리가 비어 있어 즉시 식별(§5.3).

## 5. 환경 / 오브젝트 비주얼

### 5.1 조직 계층의 시각화 (회사 → 부서 → 팀 → 프로젝트)

`game-design.md` §3.1 계층을 시각 오브젝트로 매핑한다(화면 구성은 §ux-design, 여기서는 오브젝트 비주얼).

| 엔티티 | 시각 표현 |
|---|---|
| **회사** | 오피스/건물 카드 — 업종 틴트 + 등급별 성장 실루엣(§5.2) + 회사명 사이니지 + 재무 상태 배지(§3.4) |
| **부서** | 룸/존 타일 — 부서 아이콘(§7.3) + 업종 틴트, 자율/직접 모드 표식(§5.4), 역량 티어 표시 |
| **팀** | 데스크 포드/파드 — 팀원 얼굴 칩 클러스터 + 팀장 인시그니아 자리 + 담당 프로젝트 물림 |
| **프로젝트** | 의뢰 카드 — 티어 프레임(§5.5) + 난이도 핍 + 보상 아이콘 미리보기 + 진행 게이지 |
| **미배치 풀** | "대기 라운지" 컬렉션 — 배치 대기 직원 칩 모음(휴식/컨디션 회복 뉘앙스) |

### 5.2 회사 등급 5단계의 시각적 성장

**설계 결정: 회사 등급(스타트업→소기업→중기업→대기업→그룹)은 "건물 실루엣의 성장 + 활기 밀도"로 표현한다.** 근거: narrative §1.2·§6의 "원룸 사무실에서 여기까지"의 감정 아크를 한눈에 보이게 — 성장을 숫자가 아니라 자라나는 그림으로 체감시킨다.

| 등급 | 건물/오피스 실루엣 | 활기·디테일 신호 |
|---|---|---|
| 1 스타트업 | 원룸/작은 사무실, 소박한 간판 | 책상 몇 개, 조용함 |
| 2 소기업 | 작은 층 사무실, 정돈된 간판 | 팀이 늘어난 활기 |
| 3 중기업 | 건물 한 층 전체, 로비 등장 | 분주함·부서 다양성 |
| 4 대기업 | 자체 빌딩(중층), 대형 사이니지 | 창문 불빛·왕래 밀도 상승 |
| 5 그룹 | 타워/캠퍼스, 랜드마크급 실루엣 | 최대 활기 + 프리미엄 마감(§narrative 최대 봉우리) |

- 성장은 **점진적**이어야(승급 순간 §8.4 연출과 맞물림) — 등급업 시 건물이 "자라는" 트랜지션.
- 업종 틴트는 유지되므로 "게임개발 그룹"과 "무역 그룹"은 같은 등급이라도 다른 색·무드의 타워로 보인다(필러 4).
- 강등(자진 강등, §7.1)은 실루엣이 한 단계 축소되되 **비극적 붕괴가 아니라 담담한 다운사이징**으로(톤 §8) — 잔해·화염 금지.

### 5.3 팀 · 표류 · 프로젝트 보드의 상태 표현

- **활성 팀 vs 표류 팀**: 활성 팀은 팀장 인시그니아 점등, 표류 팀(팀장 공석)은 인시그니아 자리가 빈 채 팀 파드가 살짝 저채도·"멈춤" 느낌 + 팀장 부재 알림 배지(§8.6). 진척 0의 정지 상태를 색으로 읽히게 하되 위기감이 아니라 "채워야 할 자리"로.
- **의뢰 보드**: 부서별 게시판 메타포. 카드가 핀으로 꽂힌 보드. 게시 기한이 임박한 카드는 옅은 시간 표식(공포 카운트다운 금지, 톤 §8-6).
- **상비 의뢰**: 만료되지 않는 "언제나 있는 안전한 일감"으로 **일관된 특별 표식**(항상 같은 자리·같은 안심 색). narrative §5.3의 "손이 비면 이거라도, 작지만 확실합니다"의 생명줄 감각을 시각으로 — 위기 복귀의 시각적 앵커(§11.6).
- **잠김 미리보기 티어**: 열람만 가능한 상위 티어 카드는 반투명/자물쇠 표식으로 "목표 제시"(§8.4 게임디자인) — 좌절이 아니라 동경으로.

### 5.4 자율 주행 / 직접 하달의 시각 구분

**설계 결정: 자율 주행 부서는 "믿고 맡긴 팀"의 안심 언어로, 로봇/AI/톱니 도상을 절대 쓰지 않는다.** 근거: 톤 헌장 §0.3·narrative §2.2 — 자율 주행은 유능한 사람들의 위임이지 기계가 아니다.

- **자율 모드**: 부서 타일에 "위임됨" 상태 — 부드러운 신뢰 글로우 + 위임 표식(예: 체크/리본 계열, 손을 맞잡는 뉘앙스). "알아서 잘 돌아가는 중"의 평온.
- **직접 하달**: 플레이어의 손길 표식 — 능동·집중의 액센트(브랜드 색 포커스 링). "지금 내가 챙기는 곳".
- **착수 태그(직접/자율)**: 프로젝트 카드에 착수 주체 태그를 작은 배지로(§9.2 태그는 착수 시 고정) — 자율 태그는 위임 색, 직접 태그는 포커스 색. 색만이 아니라 아이콘/라벨 병기(§3.5).
- **예외 기반 보고(§9.6)**: 자율 부서의 "정상"은 시각적으로 조용하다(알림 없음). 개입 필요(실패·팀장 부재·저가동)만 배지로 돌출.

### 5.5 프로젝트 티어 · 난이도의 시각 문법

- **티어 T1~T5**: 카드 프레임의 "격"으로 표현(등급 프레임과 유사한 문법, 단 자원/등급과 혼동되지 않는 별도 티어 색·마크). 상위 티어일수록 프레임 정교화 + 티어 마크(별/체브론 5단).
- **난이도 하/중/상**: 티어 안의 소형 강도 핍(3단) — 색+개수 병기. 무리한 고난이도는 "도전" 뉘앙스(위압 금지).
- 티어와 난이도는 회사 등급 5단계·직원 등급 4단계와 **시각적으로 구별**되도록 마크 형태를 분리(별=티어, 문자=직원 등급, 건물=회사 등급, 핍=난이도).

### 5.6 오피스 / 도시 배경

- **무국적 현대 대도시**: 실존 랜드마크·간판·국가 코드 없는 일반화된 스카이라인. narrative §2.1의 "이름 없는 대도시" — 선택적 월드 앵커 "Midtown"은 텍스트 앵커일 뿐 배경은 무향(§narrative 열린질문 2).
- **세로 패럴랙스 3레이어**(§2.3): 원경 스카이라인(저대비) / 중경 건물군 / 근경 오피스 요소. 콘텐츠 뒤에서 저채도로, 정보 가독성을 방해하지 않게.
- **업종 무드 배경**: 무역=분주한 장터/거래소·컨테이너·시세판, 게임개발=밤샘 사무실·빛나는 출시 화면, 화장품=청결한 랩·진열대(narrative §4.3 대표 이미지). 회사 상세 진입 시 그 업종 무드 배경으로 전환해 "세계 순회"(필러 4).
- **시간대·활기**: 방치 후 복귀 시 조용한 아침, 활발한 낮 등 가벼운 시간 표현 가능(방치를 벌하지 않는 따뜻한 귀환, 톤 §8-1) — 강제 아님, 프로덕션 여력에 따라(§11).

## 6. UI 아트 스타일

**화면 구성·플로우·정보구조는 정의하지 않는다(§ux-design 소유). 본 절은 그 구조에 입힐 비주얼 랭귀지(스킨)만 정의한다.**

### 6.1 표면 언어 — 카드·패널 시스템

- **카드 우선**: 회사·직원·프로젝트·리포트가 모두 카드. 둥근 모서리(코너 반경 토큰), 소프트 엘리베이션 그림자(과하지 않게), 지면은 뉴트럴 서피스 + 헤더에 업종/상태 틴트.
- **엘리베이션 계단**: 배경 → 패널 → 카드 → 팝오버의 명도·그림자 계단으로 깊이 위계(§3.5 명도 위계).
- **9-슬라이스**: 버튼·패널·카드·툴팁·미터는 9-슬라이스로 제작해 가변 크기·다국어 확장(§7 KO+40% 여백, narrative §7.1)을 흡수.

### 6.2 버튼 위계

| 위계 | 스타일 |
|---|---|
| Primary(주 액션) | 브랜드 액센트 솔리드, 고대비, 명확한 프레스 상태 |
| Secondary | 아웃라인/고스트, 뉴트럴 |
| Tertiary/텍스트 | 라벨만, 최소 강조 |
| Destructive(해고·청산 등) | 절제된 경고 색 — 위압적 순수 적색 금지, "신중한 결정"의 차분함(톤 §8, 존엄) |

- 라벨은 **아이콘 병기 전제로 ≤ 6자**(narrative §7.1) — 아이콘이 1차, 텍스트가 2차.

### 6.3 타이포그래피 위계

**설계 결정: 헤딩용 친근한 지오메트릭 산세리프 + 데이터용 고가독 중립 산세리프의 2서체 페어링, 숫자는 고정폭(tabular) 지원.** 근거: 경영 시뮬은 숫자(자금·급여·보상)가 핵심이라 정렬되는 tabular figures가 필수이고, 헤딩은 톤(따뜻·경쾌)을 서체로 전달한다.

- **다국어 필수(P4)**: KO·EN 1차 + JP·CN 확장을 커버하는 글리프 세트. 한글·라틴이 조화되는 페어링, CJK 확장 시 획 두께·베이스라인 정합. 폴백 서체 체계 정의(정본 레이아웃은 §ux/§accessibility).
- **타입 스케일**(역할): Display(축하·마일스톤) / Title(카드 제목) / Body(설명) / Caption(보조) / Numeric(자금·수치, tabular). 실제 pt·행간은 §ux-design.
- 리아의 목소리는 별도 서체가 아니라 말풍선 컨테이너로 구분(톤은 텍스트가, 시각은 말풍선이).

### 6.4 상태·피드백 비주얼

- 로딩·빈 상태·에러도 톤 헌장 준수 — 좌절·비난 없이 따뜻하게(빈 상태는 "여기 채워봐요" 초대).
- 토글/스위치(자율↔직접, 모드 전환)는 상태가 색+위치+아이콘으로 3중 인코딩.
- 미터/게이지(진행·컨디션·충성도·명성 진척): 색+수치+형태. 진행 게이지는 만족스러운 채워짐 애니메이션(§8.2).

## 7. 아이코노그래피

### 7.1 자원 아이콘 (6종 + 다이아)

색은 §3.6, 형태 컨셉은 아래. **모든 자원은 색이 아니라 형태로 먼저 구별**되게(색맹 안전, §3.5).

| 자원 | 형태 컨셉 |
|---|---|
| 자금(₩) | 지폐/코인에 ₩ 마크 — 가볍고 유통되는 "운영 현금" |
| 골드 | 묵직한 주화/잉곳 — 메탈릭·무게감 있는 "경영자 자산"(자금과 형태 분리) |
| 명성 | 별 + 월계/엠블럼 — 격·평판(퍼플 편향으로 골드와 분리) |
| 경험치(XP) | 상승 셰브론/스파크 — 성장의 방향성 |
| 컨디션 | 에너지 스파크/배터리형 미터 — 활력·스태미나(낮으면 형태가 비고 색 빠짐) |
| 충성도 | 하트/유대 리본 — 마음의 결속(에너지와 형태 분리) |
| 다이아(결제) | 크리스탈/보석 컷 — 게임플레이 자원과 뚜렷이 다른 "특별함" |

- 자금 ↔ 골드는 **형태·색·재질 3중 분리**(둘 다 돈이라 최우선 혼동 방지, §3.6). 다이아는 결제 재화이므로 게임 자원 옆에서 확연히 다른 종(種)으로 보이게 — 압박형·번쩍임 남발 금지(P2, 톤 §8-5).

### 7.2 결제 재화 다이아의 시각 취급 (P2 정합)

**설계 결정: 다이아 아이콘은 "특별하지만 조르지 않는" 톤으로 디자인한다.** 근거: 비 페이 투 윈·결제 압박 금지(P2, 톤 §8-5) — 다이아는 매력적이되 화면을 점령하거나 죄책감을 유발하지 않는다. 상품·가격·상점 표현의 정본은 `monetization.md`이며, 본 문서는 아이콘 컨셉만 제공한다.

### 7.3 부서 · 업종 아이콘

| 세트 | 항목 | 형태 컨셉 |
|---|---|---|
| 업종 | 무역 | 컨테이너/저울(교역·시세) |
| 업종 | 게임개발 | 게임패드/픽셀 스파크(창작) |
| 업종 | 화장품 | 코스메틱 병/꽃(연구·브랜드) |
| 부서(공통) | 영업부 | 악수/연결 — **전 업종 동일 형태·색**(학습 전이, §3.3) |
| 부서(무역) | 소싱부 / 물류부 | 저울·박스 / 트럭·컨테이너 |
| 부서(게임개발) | 개발부 / 라이브운영부 | 코드·게임패드 / 순환·라이브 표식(로봇 도상 회피) |
| 부서(화장품) | R&D부 / 생산부 | 플라스크·현미경 / 공장·튜브 |

- 부서명은 규칙 용어이므로 그대로(narrative §5.3), 아이콘도 그 명칭에 충실. 새 부서명·아이콘 신설 금지(업종 추가는 §9.7 계약).

### 7.4 스탯 아이콘 세트 (제작/기획/영업 + 리더십)

§4.7의 모티프를 아이콘화: 제작=도구/브러시, 기획=전구/블루프린트, 영업=말풍선/악수, 리더십=지휘 배지/깃발. 스탯 아이콘은 **직원 카드·프로젝트 요구·부서 주/부 스탯 매핑에서 재사용**되는 공통 자산(부서별 주/부 스탯 표시에 동일 아이콘 사용).

### 7.5 아이콘 세트 원칙 (전 세트 공통)

**설계 결정: 모든 아이콘은 단일 그리드·단일 스트로크·실루엣 우선의 시스템으로 제작한다.** 근거: 세로 소형(16px까지)에서 읽히고, 대량 세트(자원 7 + 부서 7 + 업종 3 + 스탯 4 + UI 시스템 40~60 + 티어/난이도/상태 마크)의 스타일 편차를 없애야 명료함(필러 2)이 성립한다.

- 베이스 그리드(예: 24×24 논리, 48px 렌더 기준), 일관 스트로크 두께, 둥근 종단, 최대 2톤 채색.
- **실루엣 판별성**: 색을 빼도 형태로 구별. 색은 보조 채널.
- 소형(16px) / 표준(24px) / 대형(48px) 3사이즈에서 검증. 미세 디테일은 대형에만.
- 상태 변형(활성/비활성/경고)은 색+명도로, 형태는 유지.

## 8. 모션 · VFX 원칙

### 8.1 강도 4단계 (연출 예산 체계)

**설계 결정: 연출은 순간의 무게에 비례하는 4단계로 배분하되, P1(세로·짧은 세션)·저사양·저전력 제약 아래 "짧고 강렬하게, 입력을 오래 막지 않게" 한다.** 근거: 마일스톤 무보상 원칙(§11.5)상 감정 비트가 곧 보상이므로 큰 순간엔 아낌없이, 그러나 방치·반복 세션에서 지치지 않게 절제가 필요하다.

| 강도 | 대상 순간 | 연출 원칙 | 길이·부하 |
|---|---|---|---|
| **Ambient(상시 미세)** | 카드 hover/press, 코인 카운트업, idle 호흡, 리아 blink | 거의 무의식적 질감. 상시 재생 | 극저부하, 무한 루프 가능하되 저전력 |
| **Small(작은 성취)** | 프로젝트 완료, 레벨업, 훈련 완료, 급여 완납 | 만족스러운 팝 + 자원 플라이(코인/별) + 짧은 반짝 | ≤ ~0.6s, 입력 비차단 |
| **Medium(중간 전환)** | 등급 승급, 부서 개설, 2호 설립, 위임 실습(M8) | 배너 + 버스트 + 리아 코멘트, 건물 성장 트랜지션(§5.2) | ≤ ~1.0s, 스킵 가능 |
| **Tentpole(대형)** | 흥행 롤 히트작, 완주(M15), 전환 마일스톤(M7·M9·M12·M15) | 풀스크린 축하, 최대 파티클, 최대 봉우리(§narrative 감정곡선) | ≤ ~1.5s, 탭-투-스킵 필수 |

### 8.2 핵심 순간별 가이드

- **프로젝트 완료(Small)**: 진행 게이지 채워짐 → 완료 스탬프 + 자원 플라이 → 카드 정리. 담백하지만 손맛.
- **승급(Medium)**: 회사 건물이 다음 등급으로 "자라는" 트랜지션 + 축하 배너 + 리아. 성장의 가시적 보상(§5.2).
- **흥행 롤(Tentpole·게임의 유일한 대형 RNG)**: **설계 결정: 흥행 롤은 서스펜스 → 공개의 "롤 연출"로 만든다(다이얼/슬롯/봉투 개봉류) — 품질 점수가 기대를 세팅하고 롤이 실패작/평작/성공작/히트작을 확정.** 근거: §12.3의 "수익 분산 최대" 정체성의 분산 원천이 이 롤 하나이므로, 이 순간이 게임 최대의 두근거림이어야 한다. 단 **실패작은 담담·존엄하게**(조롱 VFX 금지, narrative §6.3 "배운 게 있으니 다음에") — 히트작은 게임 내 최대 축하 중 하나(꼬리 수익 유입 암시).
- **마일스톤 축하(Medium~Tentpole)**: 무보상이므로 연출이 곧 보상. 전환점(M7 자율 해금·M9 슬롯2·M12 쌍두·M15 완주)은 크게, 정체성 승격(창업가→경영자→총수→거물)을 시각으로.
- **완주(Tentpole)**: 소프트 엔딩 — 회고·성취·따뜻함. 종료가 아니라 여정의 인정(narrative §6.6). 유일하게 연출 분량 여유(컷신/일러스트 여부는 §11 열린 질문).

### 8.3 자원·수치 피드백

- 자금·골드·명성·XP 획득은 **소스에서 카운터로 날아가는 플라이 + 카운트업**으로 인과를 보이게(어디서 벌었는지). 손실(급여·유지비)은 담담한 감소(과장된 하락 연출 금지, 톤 §8).

### 8.4 마일스톤·축하의 무게 (무보상 정합)

마일스톤은 자원을 주지 않으므로(§11.5), 축하 연출·정체성 승격·리아 코멘트가 보상을 대신한다. 연출 품질이 이 순간의 가치를 결정한다 — 값싼 컨페티 남발이 아니라 "이 성장을 함께 기뻐한다"는 진심의 결(필러 1·3).

### 8.5 위기 · 청산 · 파산 연출 (실패=상태)

**설계 결정: 실패·위기·청산·파산 연출은 담담·존엄·회복 지향으로, 폭발·붕괴·조롱·게임오버 도상을 금지한다.** 근거: 톤 헌장 §5·§8, "게임오버 없음" 철학.

- **부실/주의**: 경고는 앰버 신호 + 복귀 체크리스트로의 시선 유도(§3.4). "급한 불부터 끄죠"의 침착함(narrative §6.5).
- **청산(자발)**: 담담한 "정리/아카이브" 애니메이션 — 회사가 조용히 정돈되고 골드가 회수되는 어른스러운 마무리(narrative §2.2 "비극이 아니라 경영 판단"). 따뜻하되 과하지 않게.
- **파산(강제·몰수)**: 침울하되 굴욕적이지 않게, 짧게. 즉시 재기 경로(무료 재설립, §10.4)로 시선 이동 — "다시 시작이 아니라 다시 일어서는 것"(narrative §2.2).

### 8.6 자율 주행 연출 (믿고 맡긴 팀)

- 위임 표현은 신뢰·안심의 부드러운 언어(§5.4) — **톱니·회로·로봇·"AI 처리 중" 스피너 금지**(톤 §0.3·narrative §2.2).
- 자율 부서의 "정상"은 조용하다(예외 기반 보고, §9.6). 개입 필요 순간(자율 실패·팀장 부재·장기 저가동)만 배지·알림으로 침착하게 돌출 — 공포·긴급 과장 없이(톤 §8-2).

### 8.7 성능 · 접근성 제약

- **저사양·저전력**: Tentpole도 스프라이트/파티클 기반의 가벼운 연출, 무거운 셰이더·풀스크린 블러 남용 금지. 방치·백그라운드 시 애니메이션 감축(발열·배터리, §9.6).
- **입력 비차단**: 모든 연출은 스킵 가능(탭-투-스킵), 반복 순간은 짧게(피로 방지).
- **모션 감소 설정**: "모션 감소" 옵션 시 Tentpole→간소 축하로 대체, 명멸·강한 카메라 이동 제거(§3.5 모션 안전, 정본은 §accessibility).

### 9.2 제작 파이프라인 (툴 · 포맷)

**설계 결정: 벡터 저작 → 아틀라스/다배율 래스터 출력 → 리깅 애니메이션(필요 자산 한정)의 파이프라인을 표준으로 한다.** 근거: 세미플랫 벡터(§2.1)의 확장성·용량 이점을 살리고, 캐릭터/리아/건물 등 소수 자산만 리깅해 성능 예산을 지킨다.

- **벡터 저작**: Illustrator / Figma / Affinity 계열(팀 표준 택1). 아이콘·UI·프레임·모듈러 파츠는 벡터 소스 유지.
- **출력 포맷**: 아이콘은 엔진 지원 시 SVG 또는 다배율 PNG(@1x/@2x/@3x), UI는 9-슬라이스 PNG, 캐릭터/오브젝트는 텍스처 아틀라스 PNG.
- **아틀라스**: TexturePacker 또는 엔진 패커로 사용 화면/빈도 단위 그룹핑 → 드로우콜 최소화(§9.6). 자주 함께 뜨는 자산을 같은 아틀라스에.
- **리깅 애니메이션**: Spine / DragonBones 등 본 애니메이션은 리아·캐릭터 idle·건물 성장·핵심 VFX 등 **선별 자산에만**. 대부분은 트윈/스프라이트로.
- **모듈러 조합**: 파츠는 공통 앵커·레이어 순서·클리핑 규칙 준수(조합 엔진 규격은 §technical-architecture와 합의).

### 9.3 네이밍 컨벤션

`카테고리_서브_변형_상태` 소문자 스네이크. 예:
- `icon_res_gold`, `icon_res_funds`, `icon_stat_make`, `icon_dept_sales`
- `char_hair_03_a`, `char_outfit_dev_02`, `char_skin_05`
- `frame_grade_s_light`, `badge_grade_c`
- `ui_btn_primary_pressed`, `panel_card_9slice`
- `bld_company_g4_trade`, `vfx_tentpole_hit`

버전·로케일 접미사 규칙과 아틀라스 그룹 태그는 프로덕션 스타일 가이드에서 확정(§11).

### 9.4 해상도 · 종횡비 대응

**설계 결정: 세로 기준 논리 해상도(예: 1080×1920, 세이프에어리어 인지)로 디자인하고, 배경 확장 + 반응형 레이아웃 + 다배율 에셋으로 기종 파편화를 흡수한다.** 근거: P1 모바일 세로, 노치/펀치홀/제스처 바 다양성.

- 종횡비: 19.5:9(노치)·16:9·태블릿 4:3 등을 배경 오버스캔(상하 확장 가능 배경)으로 대응. 레이아웃 앵커링은 §ux-design.
- 배율: @2x/@3x 래스터 또는 벡터 스케일. 아이콘은 실루엣 무결성 우선.
- 세이프 영역: 핵심 정보·CTA는 세이프 안, 배경만 침범 허용.

### 9.5 업종 추가 시 에셋 확장 원칙 (§12.8 계약의 아트 대응)

**설계 결정: 신규 업종 = 데이터 팩 + "아트 팩"이며, 시스템·아트 골격 변경 없이 추가 자산만으로 성립해야 한다.** 근거: `game-design.md` §12.8 확장 계약을 아트에서 미러링 — 성립하지 않으면 아트 시스템 개정 안건이다.

신규 업종 1종의 아트 팩 체크리스트:
1. **무드 팔레트 1행**(주조/보조/온도, §3.3) + narrative §4.3 무드 표 신규 행과 정합.
2. **부서 아이콘 3종**(공통 영업부는 재사용 — 학습 전이 유지) + 업종 아이콘 1.
3. **모듈러 복장 틴트 세트** + 소수 테마 액세서리/소품(기존 파츠 재사용 우선).
4. **회사 건물 5등급 틴트 세트** + 업종 무드 배경.
5. 기존 UI 골격·프레임·자원/스탯 아이콘·VFX는 **전량 재사용**(신설 금지).
6. 공통 영업부 색·아이콘은 불변(§3.3).

### 9.6 성능 예산 (아트 측 가이드, 하드 수치는 §technical-architecture)

- **드로우콜**: 아틀라스 그룹핑으로 화면당 목표 최소화. 오버드로우(반투명 다중 겹침) 절제.
- **텍스처 메모리**: 아틀라스 용량 상한을 저/중사양 기기 기준으로. 배경은 큰 단색·저주파라 압축 친화적으로.
- **파티클·본 애니메이션**: 동시 파티클 상한, 본 애니메이션은 선별 자산만(§9.2). Tentpole도 경량.
- **프레임/전력**: 중사양 60fps 목표·저사양 30fps 하한. **방치/백그라운드 시 애니메이션 감축**(idle 저전력) — 다회사 방치 특성상 상시 고부하 연출은 발열·배터리를 해친다(P1).
- 하드 예산(MB·드로우콜 상한·타깃 기기 목록)은 `technical-architecture.md`가 확정하며 본 문서는 그에 맞춰 자산을 최적화한다.

## 10. 마케팅 아트 정합 (§marketing 참조 씨앗)

마케팅 아트의 정본 전략은 `marketing.md`이며, 본 절은 인게임 비주얼 언어와의 정합을 위한 방향성 씨앗만 제공한다.

### 10.1 키 비주얼 방향

- **핵심 판타지 시각화**: "빈손의 창업가가 사람을 키워 여러 회사를 거느린 총수가 되는" 자수성가 판타지(narrative §1.1) — 플레이어(총수) + 리아가 성장하는 회사 포트폴리오(작은 오피스들 → 타워)를 내려다보는 따뜻하고 야심 찬 장면. **재벌 세습이 아니라 안목의 힘**(narrative §2.2).
- 밝고 낙관적, 세 업종의 색 다양성(필러 4)이 한 화면에 공존.

### 10.2 앱 아이콘

**설계 결정: 앱 아이콘은 소형에서 즉시 읽히는 단일 강모티프로 한다(A/B 후보 병행 검토).** 근거: 스토어 썸네일 경쟁에서 판별성이 전부다.
- 후보 방향: (a) 성장하는 건물 + 상승 화살표(성장·경영), (b) 리아(친근한 동반자상), (c) 브랜드 심볼. 무국적·실존 브랜드 회피, 클러터 금지.

### 10.3 스토어 스크린샷 · 피처 그래픽

- 세로 스크린샷으로 (1) 다회사 포트폴리오 장악감, (2) 세 세계의 색 다양성, (3) 직원 캐릭터의 따뜻함·존엄, (4) 성장(등급업·완주) 순간을 보여준다. 벤핏 카피는 `marketing.md`·`ux-design.md` 소유.
- 인게임 비주얼 언어와 100% 정합 — 스크린샷의 과장·미표기 연출 금지(정직, 톤 §8).
- ASO·현지화 스크린샷은 무국적 원칙 덕에 로케일 전환 마찰이 낮다(narrative §2.1).

## 열린 질문

프로덕션·스타일 가이드 단계에서 확정할 시각 미결 사항(규칙과 무관).

1. **확정 HEX 팔레트 토큰화** — 본 문서의 색 역할·대비 요구를 만족하는 정확한 컬러 토큰(라이트/다크 쌍, 업종 3세트, 시맨틱, 등급, 자원)의 최종 값. 색맹 시뮬레이션 검증 세트 포함.
2. **리아의 최종 비주얼 캐스팅**(narrative 열린질문 1 연동) — 성별·외형·연령·시그니처 실루엣. 포용성·현지화 친화 최우선. 성별 중립/로케일 선택 방향의 채택 여부.
3. **브랜드 액센트 색 확정** — 틸/청록 상수 제안의 최종 채택 여부와 정확 값(업종 3색과의 구별·리아 시그니처 겸용 검증).
4. **모듈러 파츠 물량·다양성 기준** — 슬롯당 파츠 수의 최종 목표, 중복 체감 방지선, 다양성 검수 프로세스(§accessibility-localization 연동).
5. **등급 프레임 마감의 강도 캘리브레이션** — S의 홀로그래픽/시머가 "특별하되 초라한 C를 만들지 않는" 지점, A의 광택 수위. 플레이테스트로 "C 폄하 없음" 검증.
6. **서체 페어링·CJK 확장 세트** — 헤딩/데이터 2서체의 최종 선정, JP·CN 확장 시 글리프 커버리지·라이선스(§ux/§accessibility 연동).
7. **회사 건물 성장 표현의 제작 방식** — 5등급 × 3업종 정적 스프라이트 세트 vs 파츠 조립형(용량·다양성 트레이드오프).
8. **완주 엔딩 연출 분량**(narrative 열린질문 7 연동) — 텍스트 회고로 충분한지, 컷신/전용 일러스트가 필요한지(프로덕션 규모 P5와 트레이드오프).
9. **오피스 배경의 시간대·활기 표현 채택 여부** — 방치 후 귀환 시 시간 표현(§5.6)을 런치에 포함할지, post-launch로 둘지.
10. **접근성 대비·모션 기준의 상호 확정** — 본 문서 §3.5·§8.7 씨앗을 `accessibility-localization.md`가 상속·확정하는 계약(WCAG AA·색 비의존·모션 감소)의 최종 문안.
11. **업종 추가 아트 팩 계약의 정형화**(§9.5) — narrative 열린질문 8과 짝을 이뤄, 신규 업종 아트 팩 체크리스트를 확장 계약으로 문서 고정할지.
12. **성능 하드 예산 합의** — §9.6의 아트 측 가이드를 `technical-architecture.md`의 타깃 기기·드로우콜·메모리 상한과 정합시키는 수치 확정.
