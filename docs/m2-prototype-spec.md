## 1. M2 목표·비목표·Exit 게이트

### 1.1 목표 (한 문장)

> **1개 업종(무역)으로 코어 루프(채용→배치→하달→완료→급여→강화→확장 [GD §2.6])가 "재미있는지"를 최소 구현으로 검증한다.**

M2의 산출물은 셋이다: (a) 엔진 비의존 **결정론 시뮬 코어(L1)** 실동본, (b) 무역 팩을 로드해 굴러가는 **최소 플레이 가능 빌드**(그레이박스), (c) **재미·가드레일 판정 데이터**. M2는 "재미의 원천이 코어 루프 자체인가"를 검증하는 것이지, 콘텐츠 양·비주얼·수익화를 검증하지 않는다.

### 1.2 비목표 (명시적으로 하지 않는 것)

| 비목표 | 근거 |
|---|---|
| **3업종** — 무역만. 게임개발·화장품 팩 미구현 | roadmap M4 (`4.1`). 단 코어는 팩 교체로 3업종을 표현 가능해야 함 `[GD §12.8]` — M2는 무역 팩 1개만 로드 |
| **아트·오디오 프로덕션** — 전부 그레이박스(플레이스홀더 텍스트·박스) | roadmap M3 (`3.2`). `[TA §0.2]` L2 표현 계층 최소화 |
| **수익화** — 다이아·상점·IAP·광고 없음 | roadmap M4 (`4.2`). `monetization.md` 범위 밖 |
| **멀티 컴퍼니 포트폴리오 UX** — 슬롯 해금·주의 배분·설립/청산 UX | roadmap M3 (`3.1.2·3.1.3`). 단 설립/청산 **경제 함수**(`G_liq`·`F_found`)는 가드레일 실측용 헤드리스로 구현(§2) |
| **진행/성장 마일스톤 M1~M15 전량·온보딩 FTUE** | roadmap M3 (`3.1.5·3.3`). M2는 등급 승급·자율 해금 게이트까지만 |
| **세이브 마이그레이션·클라우드·서버** | roadmap M5 (`5.2`). M2는 인메모리 상태 + 디버그 JSON 덤프로 충분(§10) |
| **밸런스 확정** — 1차안 값 주입만, 실측 교정은 M3/M6 | `[BAL]` 전체가 "플레이테스트 전 1차안", D-201 |

### 1.3 Exit 게이트 (셋 전부 충족 시 M2 종료)

1. **코어 루프 플레이 가능** — 무역 회사 1곳에서 채용→배치→하달/자율→완료→급여→강화→소기업 승급까지 최소 UI로 완주 가능. 실시간 자동 진행 + 오프라인 캐치업 동작(`[TA §4]`).
2. **내부 재미 판정 통과** — §9 관측 가능 기준(의사결정 빈도·이해도·리텐션 프록시)으로 내부 플레이테스트 판정 통과(roadmap `2.4.1`).
3. **경제 가드레일 9종 실측** — 헤드리스 시뮬로 `[BAL §8]` 9개 가드레일이 1차안 값에서 성립함을 계측(roadmap `2.4.2`). 결정론 리플레이·회사 순서 무관성 자동 테스트 그린(roadmap `2.1.5`).

Exit 판정 = roadmap `2.4.3` Go/No-Go. No-Go 시 코어 루프 설계 개정(`game-design.md` 선행) 후 재검증.

## 2. 스코프 경계 (플레이 가능 / 헤드리스 전용 / 범위 밖)

L1 코어는 `[MS §4~§9]` 규칙을 **완전 구현**한다(팩 교체·헤드리스 검증·서버 재실행이 값싸지는 근거 `[TA §0.1]`). 그러나 M2의 **UI 노출·플레이 검증 범위**는 단일 회사로 좁힌다. 세 단계로 구분한다.

| 구분 | 포함 | 근거 |
|---|---|---|
| **A. 플레이 가능(UI 노출)** | 단일 무역 회사: 채용·배치·팀장 임명·부서 개설(≤2)·직접 하달·자율 위임(기본 정책)·완료/실패·월말 급여/유지비·훈련/레벨업·컨디션/충성도·이탈·소기업/중기업 승급·재무 상태(건전/부실/파산)·실시간 자동 진행·오프라인 캐치업 | `[GD §2.6]` 코어 루프, `[MS §4·§5·§6]` |
| **B. 헤드리스 전용(수식 구현, 풀 UX 없음)** | 회사 설립 `F_found`·청산 반환 `G_liq`(`[MS §7.4]`)·슬롯 해금 판정·2호 회사 병렬(가드레일 3·5·9 실측용). UI는 미노출, 코어 함수·명령만 존재해 하네스가 구동 | roadmap `2.4.2` "가드레일 9종", `[BAL §8]` |
| **C. 범위 밖(M2 미구현)** | 게임개발·화장품 팩, 아트/오디오, 수익화, 진행 마일스톤 전량·FTUE, 세이브 마이그레이션·클라우드·서버, 다국어(문자열 키 배선만) | §1.2 |

**핵심:** 자율 주행 선택 알고리즘(`[MS §6]`)은 **B가 아니라 A**다 — 오프라인 캐치업(`2.3.3`)이 "명령 없는 `advance_one_cycle` 반복 = 자율만 프로젝트 굴림"(`[TA §4.1]`)이므로 자율 없이는 캐치업이 아무 일도 하지 않고, 가드레일 2(자율 생존)도 측정 불가. M2는 **기본 정책 1종**(균형/명목 보상/기본 휴식 임계, `[GD §9.3]`)으로 §6을 구현하되, 정책 튜닝 UI·위임 실습·모드 토글 심화는 M3(`3.1.1`)로 미룬다.

## 3. 시뮬 코어(L1) 모듈 분해

`[TA §0.2]` L1은 **엔진·SDK·부동소수·벽시계·비결정 컨테이너를 참조하지 않는 순수 모듈**(`Core.Sim` + `Core.Data`)이다. 아래 12모듈로 분해한다. 각 행: 책임 / 핵심 인터페이스(개념 시그니처) / 의존 / 정본 §.

| # | 모듈 | 책임 | 핵심 인터페이스(개념) | 의존 | 정본 |
|---|---|---|---|---|---|
| 1 | **FixedPoint** | 고정소수 산술·화폐 반올림·정수 분배 | `Mul/Div(a,b)`, `RoundHalfUp(num,den)`, `LargestRemainder(total,weights[])`; `FP=1_000_000`, `PROB_ONE=1_000_000`, 다중 곱 `i128` 중간 누산 | 없음(최하층) | `[MS §2.3]`, `[TA §2.6·§13-②③]` |
| 2 | **Prng** (좌표 키잉 무상태) | 롤 = `(seed,stream,c0..c3)`의 순수 함수, 분포 매핑 | `Hash64(seed,stream,c0,c1,c2,c3)`, `Uniform01Fp(...)`, `UniformRange(a,b,...)`, `Bernoulli(p,...)`; 해시 구현은 인터페이스 뒤 은닉(§10) | FixedPoint | `[MS §3]`, `[TA §13-①]` |
| 3 | **IdCounter + CanonicalOrder** | 단조 u64 ID 할당·불변·재사용 금지; 자식 "ID 정렬 인덱스 뷰" 캐시 | `NextId()`, `SortedView<T>(parent)`; 삽입=append(단조), 삭제=안정 제거 | 없음 | `[MS §1.2·1.3]`, `[TA §2.1·2.2]` |
| 4 | **Entities + Snapshot/StateHash** | 회사·부서·팀·직원·프로젝트·게시물·꼬리·경영자 필드; 정준 직렬화·상태 해시 | 엔티티 구조체; `Serialize()`(정준 순서), `StateHash()` | IdCounter | `[MS §10]`, `[TA §2.3·2.4·§11]` |
| 5 | **CommandQueue** (FIFO 단일) | 제출 순서 직렬화, 1단계 재검증·`reject-on-invalid` | `Enqueue(cmd)`, `DrainInto(step1)`; 명령 종류 닫힌 목록(`[MS §1.4]`) | Entities | `[MS §1.4·§4.2]`, `[TA §5.2]` |
| 6 | **EventBus** | 각 단계 `EVT_*` 정준 순서 발행, 버퍼에 append, 사이클 밖 소비(콜백 없음) | `Emit(evt)`, `DrainBuffer()` | 없음 | `[MS §4·§5]`, `[TA §5.3]` |
| 7 | **TickScheduler** | `advance_one_cycle()` 5단계 오케스트레이션 + 월말 훅(day%30==0) | `AdvanceOneCycle()`, `FastForward(n)` | 5·6·8~12 | `[MS §4.1·§5]`, `[TA §5.1]` |
| 8 | **ResourceLedger + FinanceStateMachine** | 자금(하한0)·명성(단조)·골드·XP·컨디션·충성도 원장; `month_credit_log`·`arrears`·`unpaid_upkeep`; 건전/부실/파산 전이 | `Debit/Credit(company,amt)`, `ReputationAdd`, `TransitionFinance(company)` | FixedPoint, Entities | `[MS §2.1·§5·§8.2·§10.4]` |
| 9 | **CapabilityAggregation** | `k=f(L)`·`m(L)`·`A_team`·`Cap_team`·`Cap_dept`(표류 제외) | `Members(L)→k`, `CapTeam(team)`, `CapDept(dept)`; `Cap_team=max(1,·)`(DD-d) | FixedPoint, Entities | `[MS §7.1·§9.6-35]` |
| 10 | **ProgressEval** (step2·3·4) | 자율 선택 §6·일일 진척 ΔP·완료/실패·품질·보상·XP 분배 | `AutonomyDispatch(dept)`, `Progress(proj)`, `CompleteOrFail(proj)`, `Quality(proj)` | 9, Prng, FixedPoint | `[MS §4.3·§4.4·§4.5·§6·§7.2·§7.3]` |
| 11 | **StateUpdate** (step5) | 레벨업 루프·컨디션 소모/회복·퇴사 판정·보드 만료/보충·주의 오버레이 | `LevelUp(emp)`, `CondUpdate(emp)`, `AttritionRoll(emp)`, `RefillBoard(dept)` | 8·9, Prng | `[MS §4.6·§7.4]` |
| 12 | **MonthEndSettle** | 30일차 직후 회사별 정산 5단계(매출·급여·유지비·등급심사·전이·풀갱신) | `Settle(company)` | 8·11, Prng | `[MS §5]` |

**보조 모듈(L1/L2 공용):** **ContentPackLoader**(무역 팩 파싱·검증·해석 파라미터 주입, §6)·**BalanceProvider**(1차안 값 테이블 주입·버전 핀, §6)·**FoundLiquidate**(설립 `F_found`·청산 `G_liq`·정리 절차 `[MS §9.5]`, 헤드리스). 이들은 코어 상태를 읽고 명령을 낼 뿐 규칙을 재정의하지 않는다.

**의존 방향(단방향, 위→아래 금지):** UI/하네스 → TickScheduler → (CommandQueue/EventBus, Progress/StateUpdate/MonthEnd) → (Capability/Ledger) → (Entities) → (FixedPoint/Prng/IdCounter). 역방향 호출·엔진 심볼 링크는 CI 어셈블리 의존 그래프로 차단(`[TA §11]`).

### 6.2 밸런스 값 주입 (M2-22)

- `BalanceProvider`가 `[BAL §1~7]` 테이블을 `[MS §7]` 함수 형태의 **계수**로 주입한다(형태는 코어 고정, 값만 데이터). 주입 대상 예: 전역 상수(`T_cycle`·`DAY_OFFLINE_CAP`·`λ_due 1.5`·`α_auto 0.72`·`ε_max 0.08`·`M_bankrupt 2`·`θ_util 0.6`·`N_pool 6`·`L_min 20`·`w_leaderXP 1.5`), 등급 5단계(`T_max/E_max/D_max/U/R_up/C_up`), 티어 커브(`Cap_ref(t)`·`R_t`·`W/D_std/M/Rep/X`), 직원 커브(`XP_need`·`Pay`·`P_quit`·`GradeDist`), 청산(`γ_cash 0.5·γ_up 0.6·ρ_G`).

### 6.3 문자열 키 연결

## 8. 테스트 계획 (Phase 2.4)

### 8.2 회사 순서 무관성 프로퍼티 테스트 (M2-16, DD-f)

## 9. 재미 판정 기준 (Exit 게이트 2)

"코어 루프가 재미있는가"는 주관이지만, **관측 가능한 프록시**로 판정한다(roadmap 2.4.1·2.4.3, `[GD §11.1]` 결정 부하 곡선·`[GD §2.7]` 핵심 긴장 기반). 아래 3축을 M2-30이 계측하고 M2-31이 종합한다.

| 축 | 관측 지표(프록시) | 통과 방향(1차 기준, 실측 교정 D-202) |
|---|---|---|
| **의사결정 빈도·유의미성** | 세션당 유의미 명령 수(하달·편성·훈련·자율 토글)·개입 시점 분포·"무의미 다음날 넘김" 비율 | 의사결정이 **일정 밀도 이상** 발생하고 지배 전략(방치만/직접만)이 없음(핵심 긴장 `[GD §2.7]` 4종이 실제 트레이드오프로 작동) |
| **이해도** | 이해도 태스크 정답률(왜 이 팀이 이 프로젝트를 못 하는가·자율 vs 직접 손익·시세 타이밍)·첫 완료까지 이탈률 | 온보딩 없는 그레이박스에서도 코어 인과가 **관찰 가능**(불투명·운빨 체감 아님). 미흡 시 규칙 단순화 아니라 표현(UI) 개선 안건 |
| **리텐션 프록시** | "다음 세션 이어서 하고 싶은가"(자기보고)·자발적 재접속·캐치업 요약 확인 후 개입 발생률 | 방치→복귀 루프가 **개입 동기**를 만든다(캐치업이 "그냥 진행됨"이 아니라 "볼 게 생김"). `α_auto`·`DAY_OFFLINE_CAP` 체감 검증(D-201 연동) |

- **판정 규약:** 세 축 모두 방향 충족 = 재미 판정 통과. 한 축이라도 구조적 결함(예: 지배 전략 존재·인과 불투명)이면 **밸런스 교정이 아니라 규칙/표현 개정 안건**으로 M2-31이 분리 기록(`game-design.md` 개정 선행, README §2.6).
- M2는 **절대 수치 목표(리텐션 %·CPI 등)를 확정하지 않는다** — 그것은 소프트런치 실측(M6, D-202). M2는 "코어 루프가 재미의 원천으로 성립하는가"의 **정성+프록시** 판정만 한다.

## 10. 동결 의존성 (D-102~105)

`decision-log.md` B절의 D-102~105(엔진·PRNG·FP·세이브포맷)가 M2의 어디를 막는지, 미동결에서 착수 가능한 부분과 대기 부분을 구분한다. **핵심 원칙: L1 코어는 엔진·포맷 비의존이라(`[TA §0.2]`) 대부분의 M2는 동결 전 착수 가능하고, 동결은 "골든 고정값·바이너리 세이브·특정 엔진 UI"만 막는다.**

| 결정 | roadmap 동결 기한 | M2에서 막는 것 | 미동결 착수 방안(완화) | 대기(동결 후) |
|---|---|---|---|---|
| **D-102 엔진·코어 언어** (Unity/C# vs Godot) | 알파 전 | 특정 엔진의 L2 표현 계층 최종 구현 | L1 코어는 순수 C#로 착수(엔진 무관, `[TA §1.2·§0.2]`). UI는 **엔진 비의존 뷰모델**(M2-23)로 최소 셸 구동 | 엔진 확정 후 L2 렌더/입력 최종화(M3) |

**요약 판정:**
- **동결 없이 착수 가능(M2 대부분):** M2-01~26의 코어·무역·UI 전부(D-103은 인터페이스 뒤 잠정, D-104는 10⁶ 확정, D-105는 인메모리, D-102는 뷰모델 흡수).
- **동결이 게이트하는 것:** 결정론 리플레이 **골든 고정값**(D-103)·바이너리 세이브 골든(D-105, M2 비목표)·특정 엔진 UI 최종화(D-102, M3).
- **강한 권고:** roadmap이 D-103·D-104를 "프로토타입 착수 시 동결"로 배치한 이유 = M2가 만드는 저장된 롤·밸런스 정밀도가 교체 시 리플레이/세이브 비호환을 유발하기 때문. **M2 착수 스프린트(S1)에서 D-103·D-104를 `[TA §13]` 1순위(SplitMix64/`FP=10⁶`)로 정식 동결**하고 `decision-log.md`에서 A절로 이관할 것을 권고한다. 미동결로 진행 시 M2-15 골든값은 `provisional`로만 유지한다.
