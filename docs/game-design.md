# 회사 경영 시뮬레이션 — 게임 시스템 디자인 문서 (통합본 v1.0)

---

## 1. 개요와 설계 범위

### 1.1 게임 개요

플레이어는 **경영자**가 되어 최대 10개의 회사를 동시에 운영한다. 업종은 MVP 기준 3종(무역 / 게임개발 / 화장품)이며 같은 업종의 회사를 여러 개 세울 수 있고, 업종은 이후 데이터 확장으로 계속 추가된다(§12.8). 기본 구조는 다음과 같다: 직원을 채용해 팀을 꾸리고, 부서가 확보한 프로젝트를 팀이 수행해 수익을 얻고, 월말에 급여를 지급하고, 남는 재원으로 직원과 회사를 강화하며, 다 키운(혹은 가망 없는) 회사는 **청산**해 경영자 재화 **골드**로 회수할 수 있다.

핵심 재미는 세 축이다.

1. **다층 성장** — 직원(스탯·레벨) → 팀(팀장·편성) → 부서(역량 티어) → 회사(등급) → 그룹(전 업종 제패)으로 이어지는 성장 사다리
2. **포트폴리오 운영** — 현금 흐름 성격이 다른 업종들(평탄 / 스파이크 / 계단형)을 조합해 굴리고, 회사를 계속 키울지 청산해 골드로 회수할지를 판단하는 자산 관리
3. **주의 배분** — 직접 하달(고효율·고부하)과 자율 주행(저효율·저부하) 사이에서 "지금 어느 회사·부서를 직접 챙길 것인가"를 매 사이클 결정

### 1.2 문서의 지위

본 문서는 공통 설계 프레임과 8개 서브시스템 초안을 통합·정합화한 **단일 정본**이다. 본 문서와 충돌하는 이전 문서·초안은 무효이며, 규칙 변경은 본 문서 개정으로만 이루어진다.

### 1.3 다루지 않는 것

본 문서는 게임 시스템(규칙, 엔티티, 상태, 자원 흐름, 플레이어 의사결정)만을 다룬다. 다음은 명시적으로 범위 밖이다.

- **기술 구현**: 엔진, DB, 코드 구조, 아키텍처, 네트워크
- **밸런싱 수치**: 구체적 값의 튜닝(본 문서는 변수·관계식·단조성 원칙까지만 확정)
- **UX/화면 구성/그래픽**: UI 레이아웃, 아트, 연출
- **사운드**

### 1.4 표기 규약

- **설계 결정:** — 원 요구사항이 모호하거나 선택지가 갈리는 지점의 확정. 근거를 한 줄 이상 붙인다.
- *변수* — 밸런싱 대상 수치는 기호(예: `C_seed`, `α_auto`)로 표기하고 값 대신 관계식·단조성만 확정한다.
- **구조적 수** — 개수·단계 수(등급 5단계, 업종 3종 등)는 구조로서 확정한다.
- *(post-MVP)* — 설계 금지가 아닌 구현 보류. MVP는 작게 유지한다.

### 1.5 시스템 구성과 소유권

본 게임은 **7개 시스템 + 1개 데이터 팩**으로 구성된다.

**설계 결정: 채용은 독립 시스템이 아니라 직원 시스템에 내장한다.** 근거: 지원자 풀과 직원 엔티티 생성은 분리할 수 없는 하나의 수명주기다.

모든 공유 데이터는 **단일 소유자**를 가지며, 타 시스템은 읽기 전용으로 조회하거나 이벤트로 통지받는다. 소유권 매트릭스:

| # | 시스템 | 단독 소유 데이터/규칙 |
|---|---|---|
| 1 | **경제** (§5) | 자금 원장(회사별), 유출입 닫힌 목록, 미지급/미납 이월 잔액, 재무 상태 머신(건전~파산), 월간 결산 리포트 |
| 2 | **직원** (§6, 채용 내장) | 직원 엔티티, 스탯·레벨·잠재력, 컨디션·충성도와 효율 계수 `e`, 지원자 풀(공고·창립), 급여 테이블, 훈련, 이탈(해고·퇴사) |
| 3 | **회사/조직** (§7) | 회사 등급·승급·자진 강등, 부서·팀·배치 규칙, 조직 불변식, **명성 원장** |
| 4 | **프로젝트** (§8) | 프로젝트 스키마(확장 필드 포함), 의뢰 보드, 역량 게이트, 진척·완료·실패 판정, 보상 산정 |
| 5 | **자율 주행** (§9) | 부서 운영 모드·정책, 결정론적 선택 알고리즘, 페널티 계수 `α_auto` |
| 6 | **멀티 컴퍼니** (§10) | 경영자 레이어, **골드 원장(경영자 재화)**, 회사 슬롯(최대 10, 해금 조건 포함), **회사 생애주기: 신규 회사 초기 상태·설립 절차·소멸 절차(청산 가치 산정 포함)** |
| 7 | **진행/성장** (§11) | 게임 목표(완주), 단계 국면, 자율 주행 해금, 마일스톤, 위기 복귀 루프의 안내 |
| 8 | **업종 콘텐츠** (§12, 데이터) | 3업종의 부서 종류·프로젝트 카탈로그·확장 필드 해석 함수·`C_seed`/`F_found` 값 |

**설계 결정: 소유권 단일화 원칙.** 자금은 경제, 명성은 회사/조직, **골드와 회사 슬롯·생애주기는 멀티 컴퍼니**, 해금·마일스톤은 진행/성장이 각각 유일하게 소유한다. 근거: 동일 데이터의 이중 장부는 정합성 붕괴의 근원이므로, 자금에 적용한 단일 원장 원칙을 모든 공유 상태로 확장한다.

## 2. 코어 루프와 시간 모델

### 2.1 시간 모델

**설계 결정: 시뮬레이션은 이산 사이클(턴) 단위로 처리되며, 사이클은 실시간 벽시계로 자동 진행된다.** 여기서 "실시간 틱이 아니다"는 것은 **프레임 단위 연속 시뮬이 아니라는 뜻**이다 — 모든 진행·판정은 이산 사이클(일) 단위로 결정론적으로 처리되되(프레임 무관), 그 사이클의 진행 자체는 플레이어의 수동 조작이 아니라 실시간 시계가 구동한다. 근거: 여러 회사 동시 운영 + 부서 자율 주행 + 모바일 방치 플레이(P1)에서는 "실시간으로 굴러가는 이산 사이클 + 사이클 사이 개입" 모델이 결정 부하 통제와 방치 수익을 동시에 만족한다. (순수 턴제 — 플레이어가 수동으로 하루를 넘기는 방식 — 는 방치·자율 주행 컨셉과 상충하므로 배제한다.)

- 기본 단위: **일(Day)** = 1사이클. 모든 진행·판정의 최소 단위(이산·결정론).
- **사이클↔실시간 매핑**: `1 게임일 = T_cycle 실시간`(전역 상수). 앱 종료 중 경과한 실시간은 재진입 시 **결정론적 캐치업**으로 사이클을 소급 진행한다(technical-architecture §4). 오프라인 소급 상한 `DAY_OFFLINE_CAP`을 둔다. `T_cycle`·`DAY_OFFLINE_CAP`의 값 정본은 balance.md이며, 구체 값은 밸런싱 대상으로 열어 둔다(§15).
- 정산 단위: **월(Month) = 30일**. 급여·유지비·등급 심사 등 경제 정산은 월말에만 발생.
- 주(Week) 단위는 MVP에서 사용하지 않는다. *(post-MVP: 주간 리포트)*
- 사이클은 플레이어가 보유한 **모든 회사에 동시 적용**된다. 회사별 일시정지·배속은 없다. 전역 시간 단축·가속은 수익화·편의 레이어에서 별도로 정의한다(monetization, 비 P2W 경계 준수).

### 2.2 일 처리 순서 (고정 5단계)

| 단계 | 이름 | 이 단계에 실리는 처리 (전량) |
|---|---|---|
| 1 | **지시 반영** | 플레이어 명령 일괄 적용 + 즉시 지출 집행: 채용 확정(계약금), 배치·이동·팀장 임명/교체, 팀 신설/해체, 훈련(비용), 직접 하달 착수(착수 비용 `C₀`), 취소 예약의 확정, 자율 모드/정책 전환, 승급 예약의 원자 처리(재검증→차감→상한 갱신), 부서 개설(개설비), 회사 설립/청산 처리, 자율 부서의 팀장 자동 승계 |
| 2 | **자율 주행 판단** | 자율 모드 부서의 프로젝트 선택·착수 (자금 무지출, §9.3) |
| 3 | **프로젝트 진행** | 진행 중 프로젝트의 일일 진척 산출·누적, 컨디션 소모량 산출 |
| 4 | **완료 판정 및 수익 지급** | 완료/기한 실패 판정, 보상 스케줄 이행(일시 지급 + 활성 꼬리의 일일 지급) |
| 5 | **상태 갱신** | XP 반영·레벨업, 컨디션·충성도 갱신, 퇴사 판정, 의뢰 보드 유지보수(만료·보충), 재무 '주의' 예측 갱신, 마일스톤·알림 발신 |

### 2.3 월말 정산 순서 (고정 5단계, 30일차 일 처리 이후)

| 단계 | 이름 | 내용 |
|---|---|---|
| 1 | **매출 확정** | 당월 지급된 프로젝트 보상(꼬리 포함)의 집계. 재지급 아님 |
| 2 | **급여 지급** | 직원별 청구액(이월 미지급 잔액 + 당월 급여) 차감. 부족 시 규칙은 §5.5 |
| 3 | **유지비 차감** | `U(등급)` 차감. 부족 시 미납 이월 (§5.5) |
| 4 | **등급 심사** | 승급 조건 판정("승급 가능" 표시), 자진 강등 신청 적용, 회사 슬롯 해금 판정은 이 결과를 읽음 |
| 5 | **월간 결산 리포트** | 리포트 생성. 재무 상태 전이 확정, 지원자 풀 전면 갱신, 자율 부서 운영 요약 포함 |

### 2.4 공통 규칙 (전 시스템 준수)

1. 어떤 시스템도 §2.5의 자원 6종 외의 **자원을 신설할 수 없다**.
2. 어떤 시스템도 §2.2/§2.3의 처리 순서에 **새 단계를 삽입할 수 없다**. 새 처리는 기존 단계의 하위 작업으로만 정의한다.
3. 자금 증감은 경제 시스템의 트랜잭션으로만, 명성 증감은 회사/조직 시스템의 원장 기록으로만, 골드 증감은 멀티 컴퍼니 시스템의 원장 기록(청산 반환·설립비 지불)으로만 발생한다.

### 2.5 자원 (6종 확정)

| 자원 | 귀속 | 획득 | 소비/감소 | 비고 |
|---|---|---|---|---|
| **자금(₩)** | 회사별 | 프로젝트 보상(꼬리 포함), 설립 시드 | §5.4의 닫힌 유출 목록 | 회사 간 이전 금지(MVP) |
| **골드** | 경영자(계정) | 회사 청산 반환(§10.5, 유일 획득 경로) | 회사 설립비 지불(§10.4, 유일 소비처) | 자금과 직접 교환 불가 — 회사 원장에 주입할 수 없다 |
| **명성** | 회사별 | 프로젝트 완료(티어 비례) | 소비되지 않음(문턱형), 감소 없음 | 승급 문턱·지원자 풀 품질에 사용 |
| **경험치(XP)** | 직원별 | 프로젝트 참여 | 레벨업(자동 변환) | 레벨 → 스탯 성장 |
| **컨디션** | 직원별 | **프로젝트 비수행 일**에 회복 | 프로젝트 수행 중 매일 감소 | 낮으면 효율 계수 `e` 하락 |
| **충성도** | 직원별 | 정시 급여, 승진 | 급여 미지급, 과로, 강등 | 임계 미만 시 퇴사 위험 |

**설계 결정: 컨디션 회복 조건은 "미배치"가 아니라 "해당 사이클에 진행 중 프로젝트를 수행하지 않음"이다.** 미배치 풀 소속, 프로젝트 없는 팀 소속(유휴·표류 팀), 자율 주행의 휴식 판정을 받은 팀이 모두 동일하게 회복한다. 근거: 회복을 미배치에 한정하면 팀 소속 대기 인원의 컨디션 처리가 공백이 되고, 자율 주행의 컨디션 보호선(P3)이 기능하지 않는다. 미배치와 팀 대기의 회복률 차등 여부는 밸런싱 변수로 남긴다.

**설계 결정: 명성은 소비형이 아닌 문턱형 자원이며 단조 증가한다(감소 없음).** 근거: 소비형이면 승급과 해금이 이중 화폐 관리가 되고, 감소를 허용하면 위기 복귀 루프(강등해도 명성 보존 → 빠른 재승급)가 무너진다.

**설계 결정: 경영자 재화는 골드 단일이다. 다이아 등 제2 경영자 재화(프리미엄 재화)는 post-MVP.** 근거: 게임 시스템 관점에서 재화는 고유한 획득-소비 루프가 있을 때만 정당하다. MVP의 경영자 경제는 [청산 → 골드 → 설립] 루프 하나로 충분하며, 프리미엄 재화는 수익화 설계(본 문서 범위 밖)와 함께 결정할 사안이다.

### 2.6 코어 루프

**메인 루프 (월 스케일, 회사 단위):**
1. **채용** — 지원자 풀에서 채용(계약금)
2. **배치** — 팀 편성·팀장 지정·부서 편성
3. **프로젝트** — 부서별 직접 하달 또는 자율 위임 → 팀이 수행
4. **수익** — 완료 보상으로 자금·XP·명성 획득
5. **급여** — 월말 급여·유지비 지급
6. **강화** — 훈련(자금→스탯), 레벨업, 재배치
7. **확장** — 등급 승급(자금+명성 문턱) → 상한 증가 → 1로 회귀. 여유가 생기면 신규 회사 설립(스폰서 자금 또는 골드), 다 키웠거나 가망 없는 회사는 청산해 골드 회수

**보조 루프 (일 스케일):** 진행 리포트 확인 → 문제 부서 개입(프로젝트 교체, 자율 토글, 재배치).

**횡단 루프 (월 스케일, 멀티 컴퍼니):** 포커스 결정 → 주력 회사 밀도 운영 → 위성 회사 예외 점검 → 월말 횡단 결산 → 확장/손절 판단 (§10.7).

### 2.7 핵심 긴장

1. **현금 흐름** — 급여·유지비(고정 지출) vs 프로젝트 수익(변동 수입)
2. **개입 트레이드오프** — 직접 하달(보상 100%) vs 자율 주행(보상 ×`α_auto`)
3. **무리 대 안정** — 팀 역량 대비 어려운 프로젝트의 고보상 vs 기한 실패·과로 위험
4. **확장·회수 타이밍** — 승급·신규 설립의 선투자 vs 스폰서 회사의 체력, 계속 운영의 미래 수익 vs 청산 골드의 즉시 회수(파산까지 가면 반환 0)

## 3. 엔티티 정의와 계층

### 3.1 계층 구조

```
플레이어(경영자) 1 — 골드 원장 + 비자원 상태 보유 (§10.2)
 └─ 회사 0..10 (업종 중복 허용 — 슬롯은 해금으로 확장, §10.3)
     ├─ 미배치 인력 풀 (회사 단위)
     └─ 부서 1..D_max(등급) (업종별 고정 종류, 업종당 3종)
         └─ 팀 0..T_max(등급)
             ├─ 팀장 0..1 (직원)
             ├─ 팀원 0..k (직원, k = f(팀장 리더십), 단조 증가)
             └─ 담당 프로젝트 0..1
```

**설계 결정: 부서 ≠ 팀. 부서는 여러 팀을 갖는 관리 계층이고, 프로젝트 수행 단위는 팀이다.** 근거: "회사 등급에 따른 최대 팀 수 증가"와 "팀장 역량에 따른 팀원 수"는 팀이 독립 실체임을 전제한다.

**설계 결정: 동시 운영 회사는 최대 10개(슬롯 10), 동일 업종 중복 허용.** 근거: 후반 콘텐츠의 실체는 "회사 컬렉션 포트폴리오" 운영이며, 늘어나는 개입 부하는 자율 주행과 슬롯 해금 페이싱(§10.3, §11.1)이 흡수한다. 회사는 독립 경제체이므로 업종 중복을 금지할 시스템적 이유가 없다.

### 3.2 엔티티 요약

| 엔티티 | 정의 | 상세 |
|---|---|---|
| **플레이어(경영자)** | 회사 위의 최상위 엔티티. 골드 원장과 슬롯·해금·마일스톤 상태를 가짐. 경영자 명성 없음 | §10.2 |
| **회사** | 자금·명성·직원·부서를 갖는 독립 경제체. 등급 5단계 | 생애주기 §10, 등급 §7.1 |
| **부서** | 프로젝트 카탈로그(의뢰 보드)의 소유자, 자율 주행 on/off의 단위. 종류는 업종이 결정 | §7.2 |
| **팀** | 프로젝트 수행 단위. 동시에 1개 프로젝트만 담당. 팀장 없는 팀은 착수 불가 | §7.3 |
| **직원** | 유일한 생산 수단. 직무 스탯 3종 + 리더십 + 잠재력, 레벨/XP, 급여, 컨디션, 충성도 | §6 |
| **프로젝트** | (업종, 부서 종류, 티어, 난이도, 기간, 보상)으로 정의되는 템플릿의 인스턴스. 상태: 대기→진행→완료/실패 | §8 |

신규 회사의 초기 상태(시드 자금, 창립 멤버, 초기 부서)는 멀티 컴퍼니 시스템이 단일 정의한다 (§10.4).

## 5. 경제 시스템

### 5.1 개요와 책임

경제 시스템은 **자금(₩)의 유일한 관리 주체**다.

**설계 결정: 단일 원장(Single Ledger) 원칙.** 모든 자금 증감은 경제 시스템이 집행하는 트랜잭션으로만 발생하며, 다른 시스템은 청구(비용)와 지급 요청(보상)만 제출한다. 근거: 자금 경로가 흩어지면 파산 판정·결산의 정합성을 보장할 수 없다.

- 가격표·산식의 소유자는 각 시스템이다(급여 테이블=직원, 유지비·승급비·개설비=회사/조직, 계약금·훈련비=직원, 보상액·착수 비용 해석=프로젝트/업종 콘텐츠, 설립비·시드=멀티 컴퍼니/업종 콘텐츠). 경제는 값을 받아 **집행**하고 결과를 돌려준다.
- **MVP 기본 원칙: 인플레이션·이자·세금·환불 없는 정적 가격 모델.** (무역 시세는 가격 변동이 아니라 특정 프로젝트의 보상 계수다. §12.2)

### 5.2 자금 원장 모델

- 자금은 **회사별 독립 원장**. 플레이어 공용 지갑은 없다. 화면용 "총자산"은 읽기 전용 집계값으로 어떤 규칙에도 쓰이지 않는다.
- **잔액 하한 = 0. 음수 잔액(부채)은 존재하지 않는다.**
- **설계 결정: 지급 불능은 부채가 아니라 "미지급 잔액"으로 표현한다.** 월말에 지급하지 못한 급여·유지비는 소멸하지 않고 **이월 청구액**으로 기록되어 다음 월말 정산에 합산된다. 이는 이자가 붙는 부채가 아니라 지급 대기 청구다. 근거: (1) 미지급분이 소멸하면 "급여를 격월로만 주는" 체불 사이클링이 인건비 절감 전략이 된다 — 이월 구조는 체불을 절약이 아닌 지연으로 만들어 이 퇴화 전략을 구조적으로 차단한다. (2) 위기 해제 판정("미지급 잔액 0")의 기준값이 실재하게 된다.
- 퇴사·해고한 직원의 개인 미지급 잔액은 소멸한다(청구 주체 소멸). 이를 노린 해고는 계약금 가드레일(§5.8-8)로 항상 손해가 되도록 유지한다.

### 5.3 자금 유입원 (닫힌 목록 — 2종)

| # | 유입원 | 발생 시점 | 산정 |
|---|---|---|---|
| **I-1** | **프로젝트 보상** — 완료 시 확정되는 **보상 스케줄**의 이행. 일시 지급과 꼬리(기간 내 일일 지급) 모두 포함 | 일시분: 완료 사이클의 일 처리 4단계. 꼬리분: 이후 매 사이클 4단계 | 프로젝트 시스템이 산정한 최종액(품질·계수 소스·`α_auto` 적용 후, §8.7) |
| **I-2** | **회사 설립 초기 자본** | 설립 확정 시 1회, 시스템 지급 | `C_seed(업종)` — 업종별 고정값 |

- **설계 결정: I-1은 "완료 즉시 1회 지급"이 아니라 "완료 시 확정된 스케줄의 이행"으로 정의한다.** 근거: 게임개발 꼬리 수익을 원장이 지원해야 하며, 꼬리도 일 처리 4단계(수익 지급) 내에서 이행되므로 새 단계가 필요 없다. 월말 매출 확정은 "당월 지급분의 집계"이므로 꼬리가 자연히 포함된다.
- **설계 결정: 프로젝트 실패 시 금전 유출입 없음 — 보상 0, 위약금 없음.** 근거: 투입 기간·컨디션·기회비용이 이미 실패 비용이고, 금전 위약금을 겹치면 저자금 구간에서 회복 불능 나선이 생긴다(잔액 한도 차감식 위약금은 저자금일수록 억지력이 0에 수렴하는 역진 구조이기도 하다). 착수 비용 `C₀`가 있는 프로젝트는 `C₀` 비환불이 자연스러운 금전 하방 역할을 한다. *(위약금은 post-MVP 재검토)*
- **설계 결정: I-2 시드는 기존 회사 자금과 무관한 시스템 지급이다.** 설립비 `F_found`(O-6, 자금 지불형)는 스폰서 회사에서 소멸하고 시드는 시스템이 지급하므로, 설립은 회사 간 자금 "이전"이 아니다(이전 금지 원칙과 무충돌). 시드가 업종별인 근거: 업종마다 선투입 규모(무역 소 ~ 게임개발 대)가 다르다.
- 회사 소멸 시 해당 회사의 **활성 꼬리 스케줄은 잔여분 포함 소멸**한다 (§10.5).

### 5.4 자금 유출처 (닫힌 목록 — 8종)

다른 시스템은 이 목록 밖의 자금 트랜잭션을 만들 수 없다. 신설이 필요하면 본 절 개정이 선행한다.

#### 5.4.1 즉시 지출 — 일 처리 1단계 집행, 선불 원칙

잔액이 청구액 이상일 때만 집행되며, 부족하면 **해당 지시/착수 자체가 거부**된다(예약·외상 없음).

| # | 유출처 | 청구 주체 | 산정 원칙 |
|---|---|---|---|
| O-1 | **채용 계약금** | 직원 | `f(직원 등급, 초기 스탯 총합)`. 창립 선발은 면제 (§6.4) |
| O-2 | **훈련 비용** | 직원 | 대상 스탯 현재치에 단조 증가 (체증) |
| O-3 | **등급 승급 비용 `C_up(등급)`** | 회사/조직 | 등급에 단조 증가. 승인 예약 → 다음 사이클 1단계에서 재검증·차감·상한 갱신을 **원자적으로 동시 처리**, 실패 시 승급 기각 (§7.1) |
| O-4 | **부서 개설비 `D_open`** | 회사/조직 | 첫 부서(설립 시 선택 부서)는 면제 |
| O-5 | **프로젝트 착수 비용 `C₀`** | 프로젝트(값은 업종 데이터) | 기본 0. 무역 트레이딩 딜·화장품 R&D/자사 라인만 >0. 시세 품목은 `C₀ × μ(g, 착수일)`. **실패·중도 포기 시 비환불** |
| O-6 | **회사 설립비 `F_found(업종)`** | 멀티 컴퍼니 | 자금 지불형 설립 시 스폰서 회사에서 차감되는 **소멸형(싱크) 지출**. 골드 지불형 설립(`F_found_G`, 경영자 골드 원장 차감 — 경제 원장 밖 §10.4)을 택하면 발생하지 않음. 첫 회사·회사 0 상태 재설립은 면제 (§10.4) |

- **설계 결정: 착수 비용 `C₀`를 유출 목록에 정식 등재한다.** 근거: 무역의 시세 마진과 화장품의 원가 구조는 선투입 없이는 표현할 수 없다. "착수 과금이 저자금 교착을 만든다"는 우려는 **착수 비용 0인 상비 의뢰가 모든 부서에 상시 존재**하는 것(§8.4)으로 해소된다 — 수입 수단이 막히는 상태는 구조적으로 없다.
- **설계 결정: 자율 주행 부서는 `C₀ > 0` 프로젝트를 착수하지 않으므로**(§9.5), 즉시 지출 6종은 전부 플레이어 지시에 의해서만 발생한다. 자율 주행 = 자금 무지출 원칙이 유지된다.

#### 5.4.2 정기 지출 — 월말 정산 집행

| # | 유출처 | 청구 주체 | 시점 | 부족 시 처리 |
|---|---|---|---|---|
| O-7 | **급여** | 직원(테이블) + 경제(이월 잔액) | 월말 2단계 | 직원 단위 전액 지급, 미지급분 이월 (§5.5) |
| O-8 | **운영 유지비 `U(등급)`** | 회사/조직 | 월말 3단계 | 잔액 전액 차감 + 부족분 미납 이월 (§5.5) |

- **설계 결정: 해고·퇴사에 따른 금전 지출(퇴직 위로금 등)은 MVP에 없다.** 근거: 인건비 구조조정이 즉각적인 현금 흐름 개선 수단이어야 위기 대응 플레이가 성립한다 — 위로금+자금 검증 방식은 정확히 자금이 없는 순간에 해고를 봉쇄한다. 채용→해고 남용은 계약금 가드레일(§5.8-8)로 차단한다. *(퇴직금·대량 해고 페널티는 post-MVP)*
- 프로젝트 수행 자체의 별도 과금(착수 비용 외)은 없다. 스카우트 수수료는 스카우트와 함께 post-MVP.

### 5.5 월말 정산의 집행 명세

1. **매출 확정** — 당월 I-1 지급분(일시+꼬리) 집계. 리포트용 확정치.
2. **급여 지급** — 직원별 청구액 = **이월 미지급 잔액 + 당월 급여**.
   - **설계 결정:** 잔액 < 청구 총액이면, **직원 단위 전액 지급 원칙**(부분 지급 없음) 하에 **청구액이 낮은 직원부터** 지급한다(동률 시 근속 오래된 순). 근거: 동일 자금으로 미지급 피해 인원을 최소화하는 결정론적 규칙.
   - 지급하지 못한 직원의 청구 잔액은 **미지급 잔액으로 이월**된다. 미지급 직원 목록은 미지급 이벤트로 직원 시스템에 전달된다(충성도 반영은 직원 소관, 미지급 월 누적 시 하락 폭 체증).
3. **유지비 차감** — 이월 미납분 + 당월 `U(등급)` 청구. 부족 시 잔액 전액 차감 후 부족분 미납 이월.
4. **등급 심사** — 경제는 자금 잔액·재무 상태를 심사 참조값으로 제공(심사 규칙은 회사/조직 소관). 자진 강등 신청도 이 단계에서 적용된다.
5. **월간 결산 리포트** — §5.7 생성. **재무 상태 전이 판정(§5.6)도 이 단계 내부에서 확정**된다. 지원자 풀 갱신(직원 시스템)도 이 단계에 병합된다.

### 5.6 재무 상태 머신과 파산

회사 단위 상태 머신은 **건전/부실/파산 3상태**이며, 상태 간 전이는 월말 정산 5단계 내부에서 확정된다. **'주의'는 상태 머신의 정식 상태가 아니라 매일 갱신되는 경고 오버레이(플래그)다** — 일 처리 5단계에서 예측이 갱신되며(§2.2), 어느 상태 위에도 중첩 표시될 수 있고 규칙적 제약이 없다. 신규 회사는 **건전 상태로 시작**한다(§10.4).

| 상태 | 진입 조건 | 게임 효과 |
|---|---|---|
| **건전** | 초기 상태(§10.4), 또는 미지급·미납 잔액 0이며 직전 월말 전액 지급 | 없음 |
| **주의** *(오버레이)* | (매일 갱신 예측) 현재 잔액 < 다음 월말 고정 지출 예상액(이월 잔액 + 급여 총액 + `U`) | 경고 표시만. 규칙적 제약 없음 |
| **부실** | 직전 월말 정산에서 미지급/미납 발생, 또는 미지급 잔액 > 0 지속 | 충성도 하락(직원 소관), 등급 심사 참조값 "부실" 출력, **자진 강등 허용**(§7.1), 복귀 체크리스트 표시(§11.6) |
| **파산** | 부실이 **연속 `M_bankrupt`개월**(`M_bankrupt ≥ 2`) 지속 | 파산 판정 이벤트 발행 → 멀티 컴퍼니의 **몰수형 소멸 절차**(청산 반환 0) 실행 (§10.5) |

- 부실 해제(→건전): **이월 잔액을 포함한 전액 지급에 성공한 월말**. 이때 부실 연속 카운터도 0으로 리셋된다.
- **설계 결정: 파산은 회사 단위이며, 판정은 경제가, 소멸 절차는 멀티 컴퍼니가 소유한다.** 근거: 다회사 구조에서 한 회사의 실패가 세션을 끝내면 포트폴리오 운영의 의의가 사라진다. 절차의 단일 소유로 청산 규칙의 중복 정의를 막는다.
- **설계 결정: 플레이어 단위 게임오버는 없다.** 모든 회사가 파산해도(보유 회사 0 상태) 무료 재설립으로 재기할 수 있다 (§10.4). 근거: 경영 시뮬레이션의 리텐션은 재기 루프다. *(하드 게임오버는 post-MVP 난이도 옵션)*

**위기 대응 수단(전용 구제 메커니즘 없음, 기존 규칙의 조합):** 훈련·채용·승급·개설·`C₀` 지출 중단, 고급여 직원 해고(무비용 — 즉시 인건비 축소), 고보상 프로젝트 직접 하달(`α_auto` 회피), 저티어 단기·상비 의뢰로 현금 회전, 자진 강등(부실 한정, §7.1), 최후에는 청산·재설립(§10.5, §11.6 — 파산 몰수 전에 청산하면 반환 골드라도 남는다).

### 5.7 월간 결산 리포트

회사별 생성. 포함 항목: 수입 내역(프로젝트별, `α_auto` 적용 전/후 구분, 꼬리 구분) / 지출 내역(급여 지급·미지급·이월, 유지비, 즉시 지출 합계) / 순이익·월말 잔액 / 재무 상태·부실 카운터·미지급 잔액 / 다음 달 고정 지출 예상액 / 자율 부서 운영 요약(§9.6).

### 5.8 밸런싱 가드레일 (관계식 원칙)

1. **양의 마진**: 각 등급에서 등급에 걸맞은 편성이 완전 가동되면 `월 기대 수입 > 급여 총액 + U`. 마진율은 등급이 올라도 음수가 되지 않는다.
2. **자율 생존 가능**: `α_auto` 적용 + `C₀ > 0` 콘텐츠 제외 상태의 자율 수입만으로도 유지(급여+유지비)가 가능해야 한다. 자율 주행은 "성장이 느린 선택"이지 "서서히 파산하는 선택"이 아니다.
3. **승급 회수**: `C_up`은 확장된 편성의 마진 증가분으로 유한 개월 내 회수 가능해야 한다.
4. **초기 자본**: `C_seed(업종)`은 창립 편성(계약금 면제) 기준으로 첫 프로젝트 완료 전까지의 고정 지출을 감당하는 수준 이상.
5. **설립 순소비**: `F_found(업종) > C_seed(업종)`(골드 지불형 `F_found_G`도 등가 원칙 동일). 설립-청산 반복이 가치 증식 채널이 되지 않아야 한다(가드레일 9와 결합해 구조적으로 닫힘).
6. **체불 비이득**: 미지급 이월 구조에 의해 체불은 절약이 아닌 지연이며, 충성도 하락(체증)·퇴사 위험이 더해져 고의 체불은 항상 순손해여야 한다.
7. **`C₀` 기대 마진 양수**: 시세 중립 기대값에서 `R_base > C₀`(무역), 감쇠 하한 `δ_min`에서도 자사 라인 마진 ≥ 0(화장품). 선투입 콘텐츠는 보너스 상방이지 생존 조건이 아니다.
8. **고용 사이클링 차단**: 계약금은 해당 직원 기본급 수개월분 이상으로 유지하여, "급여일 직전 해고 후 재채용"이 정상 고용 대비 항상 손해가 되게 한다.
9. **청산 왕복 손실**: 청산 반환 가치는 그 회사에 투입된 가치보다 항상 작다 — 산정식(§10.5)이 시드 `C_seed`와 미지급 채무를 공제하고 모든 환수율 `γ < 1`이며 명성·꼬리·직원 투자는 환산하지 않으므로, [설립 → 운영 → 청산] 사이클은 어떤 경로로도 순손실이다.

### 5.9 다회사 자금 규칙

- **MVP: 회사 간 자금 이전 전면 금지**(대여·증여·배당·공동 지출 불가). 각 회사가 독립적으로 자립해야 한다는 것이 다회사 운영의 핵심 긴장이다.
- 설립비 `F_found`는 싱크(소멸), 시드 `C_seed`는 시스템 지급이므로 이전이 아니다.
- **골드는 자금이 아니다.** 골드의 소비처는 설립비 지불(§10.4)뿐이며, 골드를 회사 자금으로 주입하는 경로는 없다. 근거: 골드→자금 주입을 허용하면 청산이 회사 간 자금 이전의 우회 통로(A 청산 → 골드 → B 주입)가 되어 이전 금지 원칙이 무너진다.
- *(post-MVP: 이전 허용 시 월말 이후 한정 + 수수료율 `t ∈ (0,1)` 부과 — 무비용 이전은 단일 지갑화로 회사별 파산 긴장을 무효화)*

### 5.10 인터페이스

| 상대 | 입력(경제가 받음) | 출력(경제가 내보냄) |
|---|---|---|
| **프로젝트** | 완료 시 확정 보상 스케줄(최종액, 자금분), 착수 비용 `C₀` 청구, 꼬리 갱신 지시(대상 스케줄 잔여 기간 리셋) | 지급 트랜잭션 결과, `C₀` 차감 결과(승인/착수 거부), 활성 꼬리 상태(출시작별 잔여 기간, 읽기 전용) |
| **직원** | 급여 테이블(직원별 청구액), 계약금·훈련비 청구 | 차감 결과(승인/거부), 직원별 지급/미지급 이벤트(이월 잔액 포함) |
| **회사/조직** | 유지비 `U(등급)`, 승급비 `C_up`·개설비 `D_open` 청구 | 차감 결과, 자금 잔액·재무 상태(등급 심사 참조값) |
| **멀티 컴퍼니** | 설립비 `F_found` 청구(자금 지불형 한정), 설립 확정(시드 지급 요청), 소멸 절차의 잔액 소멸 지시 | 파산 판정 이벤트, `C_seed` 지급, 스폰서 자격 검증용 잔액, **청산 산정용 스냅샷(잔액·미지급/미납 잔액·승급비 지출 누계)** |
| **진행/성장** | — | 재무 상태 전이 이벤트(부실/건전), 월간 결산 데이터 |
| **업종 콘텐츠** | `C_seed(업종)`·`F_found(업종)` 데이터 | — |

### 5.11 MVP / post-MVP

**MVP:** 회사별 원장, 잔액 하한 0, 유입 2종·유출 8종 닫힌 목록, 미지급/미납 이월, 재무 상태 머신(3상태+주의 오버레이), 회사 단위 파산(절차는 멀티 위임), 게임오버 없음, 이전 금지(골드→자금 주입 불가 포함), 실패 무과금·해고 무비용·환불 없음, 청산 산정용 스냅샷 제공(골드 원장은 멀티 컴퍼니 소관).
**post-MVP:** 대출(월말 상환 단계 필요 — 시간 모델 개정 사항), 투자 유치(지분), 회사 간 이전/배당, 시장 변동 이벤트, 퇴직금, 위약금, 세금, 신용 등급, 하드 게임오버 옵션.

## 6. 직원 시스템

### 6.1 개요

직원은 유일한 생산 수단이다. 본 시스템은 직원 엔티티, 채용(지원자 풀), 성장(XP/훈련), 팀장 자격, 급여 결정, 이탈을 담당한다. 팀 편성·역량 집계는 회사/조직, 지급 집행은 경제 소관이다.

설계 목표: 플레이어의 의사결정을 "누구를 뽑을까 → 어디에 쓸까 → 얼마를 더 투자할까 → 언제 내보낼까"의 4개 질문으로 압축한다.

### 6.2 능력치 모델

| 구분 | 스탯 | 역할 |
|---|---|---|
| 직무 스탯 | **제작 / 기획 / 영업** (3종) | 부서마다 주 스탯 1종(+선택적 부 스탯 1종)이 지정되어 팀 역량에 반영 |
| 보직 스탯 | **리더십** | 팀장 보직일 때만 발현. 팀원 상한 `k`와 팀장 보정 `m`의 근거 |
| 정적 속성 | **잠재력** | 성장 한계. 생성 시 확정, 불변 |

- **설계 결정: 직무 스탯은 업종 불문 공통 3종.** 근거: 9개 부서에 개별 스탯을 두면 스탯 인플레이션이 발생한다. 부서→주/부 스탯 매핑은 업종 콘텐츠 데이터다.
- **설계 결정: 컨디션·충성도는 스탯이 아니라 상태치(자원)다.** 근거: 성장 대상이 아닌 소모/회복형 값이므로 분리해야 규칙이 단순하다.

**레벨과 XP:** XP는 프로젝트 참여로만 획득. 레벨업은 일 처리 5단계에서 자동 판정·적용(필요 XP는 레벨에 단조 증가). 레벨업 스탯 포인트는 **사용 기반 자동 분배**된다(직전 레벨 구간의 소속 부서 주/부 스탯 비중, 팀장 재직 시 리더십 포함).
- **설계 결정: 수동 분배 없음.** 근거: 수동 분배는 훈련과 역할이 겹치고 다회사 운영에서 클릭 부하가 과도하다. "배치가 곧 육성 방향"이 된다.

**성장 한계:** 레벨 상한은 잠재력에 단조 증가. 개별 스탯 상한은 레벨에 단조 증가하되 잠재력이 정하는 절대 상한을 넘지 못한다. 즉 **레벨업이 상한을 밀어 올리고 훈련이 상한까지 채우는** 이중 구조.

### 6.3 직원 등급 (4단계: C / B / A / S)

**설계 결정: 등급 = 잠재력 대역의 공개 라벨.** 근거: 잠재력을 숨기면 채용이 복권이 된다. 등급은 별도 파라미터가 아니라 잠재력의 구간 표시이므로 이중 관리가 없다.
등급이 결정하는 것: 잠재력 롤 대역, 초기 스탯 기대값·고리더십 출현 확률, 계약금·기본급 배율. 상위 등급 출현 확률은 회사 **명성**에 단조 증가.

### 6.4 채용

**공고 채용(기본):**
- 지원자 풀은 **회사별 독립** 생성, 크기 `N_pool`. 지원자 카드는 등급·초기 스탯·리더십·계약금·기본급 **전부 공개**.
- 풀은 매월 **월말 정산 5단계에서 전면 갱신**(미채용자 소멸). 공고 자체는 무료, 비용은 채용 확정 시 계약금(O-1)만.
- 등급 분포는 회사 명성에 단조 증가.

**창립 선발:**
- **설계 결정: 회사 설립 시(첫 회사·추가 회사 공통) 본 시스템이 "창립 지원자 풀"을 1회 생성한다.** 명성 0 기준 분포이되 **리더십 ≥ `L_min` 보유자 최소 1인을 보장**하며, 플레이어는 최대 `N_found`명을 **계약금 없이** 선발한다(이후 월 급여는 정상 발생, 선발 후 풀 소멸). 근거: 1일차부터 활성 팀을 구성해 코어 루프에 즉시 진입해야 하고, 신규 회사가 공고 풀의 월 갱신 주기와 어긋나 수주 동안 무수입 대기하는 상황을 막는다.

**채용 확정:** 일 처리 1단계 적용. 조건: 자금 ≥ 계약금 ∧ 회사 총원 < `E_max(등급)`. 신규 직원은 미배치 풀로 편입된다.

*(post-MVP: 스카우트 — 등급·직무 지정 유료 확정 소싱. MVP는 공고 풀+창립 풀로 채용 검증이 충분하므로 이연)*

### 6.5 성장 — 두 축

- **축 1: XP 성장(시간·배치 투자).** §6.2 참조. 자금이 아니라 배치와 시간을 소비한다.
- **축 2: 훈련(자금 투자).** 직원과 대상 스탯 1종을 지정해 즉시 상승(일 처리 1단계, O-2). 비용은 현재치에 단조 증가(체증). 스탯 상한 도달 시 훈련 불가 → "레벨업으로 상한을 올리고 훈련으로 채우는" 리듬. 리더십도 훈련 가능(팀장 후보를 돈으로 만드는 경로).
  - **설계 결정: 훈련은 기간·슬롯 없는 즉시형.** 근거: 훈련 기간은 처리 순서에 새 단계를 요구해 공통 규칙에 저촉된다. *(post-MVP: 기간제 훈련·시설)*

### 6.6 컨디션

- 프로젝트 수행 중 매일 감소(감소량은 프로젝트 시스템이 산출·통지). **해당 사이클에 프로젝트를 수행하지 않은 직원은 일당 회복**(§2.5의 설계 결정 — 미배치 풀·유휴 팀·표류 팀·자율 휴식 모두 해당). 반영은 일 처리 5단계.
- 본 시스템은 **효율 계수 `e(컨디션)`**(단조 증가, 상한 1)을 정의해 제공한다. 개인 값·`e`는 본 시스템 소유이고, 팀 평균 집계는 회사/조직이 수행해 프로젝트·자율 주행에 전달한다(§6.10).
- **과로:** 컨디션이 임계 `C_min` 미만인 채 프로젝트 수행이 유지된 일수마다 충성도 감소.

### 6.7 팀장 자격

- 팀장 지정은 배치 행위(일 처리 1단계). 자격 조건은 **리더십 ≥ `L_min` 단 하나**.
  - **설계 결정: 레벨·근속 조건 없음.** 근거: 지원자 카드만으로 "즉시 팀장 가능" 여부가 판단돼야 채용 가치 평가가 명료하다.
- 승격 시 충성도 상승 + 팀장 수당 발생. 강등(팀장→팀원) 시 충성도 소폭 하락.
  - **설계 결정: 강등 페널티 유지.** 근거: 무비용 교체는 "매 프로젝트 최적 팀장 스왑" 미시 조작을 유발한다.
- 팀원 상한 `k = f(리더십)`: 단조 증가 계단 함수, `f(L_min) = k_base ≥ 1`. 값 산출·편성 검증은 회사/조직 소관(§7.3).
- 자율 부서의 팀장 자동 승계 시에도 본 시스템의 `L_min` 자격 판정이 적용된다(§7.3).

### 6.8 급여

- **기본급 = Pay(등급, 레벨)** — 둘 다에 단조 증가. **팀장 수당 = 기본급 × 수당률**(상수 변수).
- **설계 결정: 급여는 스탯이 아니라 등급×레벨에만 연동.** 근거: 훈련으로 올린 스탯이 급여까지 올리면 훈련이 이중 과금되어 항상 손해인 선택이 된다.
- 인상 요인(MVP): 레벨업 자동 인상, 팀장 수당. *(post-MVP: 연봉 협상, 카운터오퍼)*
- 지급 집행은 경제(월말 2단계). 본 시스템은 급여 테이블을 내보내고 지급/미지급 결과를 받아 충성도에 반영한다: 정시 지급 → 회복, 미지급 → 하락(미지급 월 누적 시 체증).

### 6.9 이탈

- **해고(플레이어 주도):** 언제든 지시 가능, 일 처리 1단계 적용, 즉시 팀 제외·엔티티 소멸.
  - **설계 결정: 해고는 무비용·즉시다(위로금 없음, 자금 검증 없음).** 근거: 인건비 구조조정이 위기 대응의 핵심 수단이므로 자금이 없는 순간에도 가능해야 한다(§5.4.2). 남용은 계약금 가드레일(§5.8-8)이 차단한다. *(위로금·대량 해고 페널티는 post-MVP)*
- **자발적 퇴사:** 일 처리 5단계에서, **충성도 < `Loy_min`** 인 직원에 한해 매일 확률 판정(부족분에 단조 증가). 임계 이상이면 확률 0(예측 가능성). 임계 미만 직원은 리포트에 "이탈 위험" 표시. 퇴사 시 즉시 이탈, 개인 미지급 잔액 소멸, 팀 공석 등 후속은 이벤트로 통지.
  - **설계 결정: 퇴사는 MVP 포함.** 근거: 충성도에 소비처가 없으면 급여 미지급 리스크가 무의미하다. 퇴사는 처벌인 동시에 인건비 자동 축소라는 복귀 경로다(§11.6).

### 6.10 인터페이스

| 상대 | 입력(받음) | 출력(줌) |
|---|---|---|
| **프로젝트** | 직원별 XP 획득량, 컨디션 소모량 | 직원별 컨디션 값·효율 계수 `e` (팀 평균 집계는 회사/조직 경유) |
| **회사/조직** | 배치·보직 상태(성장 분배·과로·휴식 판정 근거), 팀장 자동 승계 요청(자격 판정) | 직원 스탯 4종, `e`, 리더십·`k = f(리더십)` 계단 구간표, `L_min` 자격 판정, 이탈 이벤트(해고/퇴사) |
| **경제** | 지급/미지급 결과(이월 잔액 포함), 계약금·훈련비 차감 결과 | 급여 테이블(기본급+수당), 계약금·훈련비 청구 |
| **멀티 컴퍼니** | 회사 설립 이벤트(창립 풀 생성 요청), 회사 소멸 이벤트(직원 전원 소멸) | — |
| **회사/조직(명성)·채용 판단** | 회사 명성 현재치(지원자 등급 분포), 총원 상한 `E_max`·잔여 슬롯 | 현재 총원 |
| **업종 콘텐츠** | 부서별 주/부 직무 스탯 매핑 | 직무 스탯 3종 정의 |
| **자율 주행** | — (직접 접점 없음. 팀 평균 컨디션은 회사/조직 경유로만 노출) | — |

### 6.11 MVP / post-MVP

**MVP:** 직무 3종+리더십+잠재력(등급 4단계 공개), 공고 풀(월 갱신)+창립 풀, XP 자동 성장+즉시형 훈련, `L_min` 단일 게이트·계단형 `k`·강등 페널티, 등급×레벨 급여+팀장 수당, 무비용 해고, 충성도 임계 퇴사.
**post-MVP:** 스카우트, 특성/스킬 트리, 숨겨진 잠재력·면접, 기간제 훈련·멘토링, 연봉 협상·카운터오퍼, 회사 간 이적.

## 7. 회사/조직 시스템

담당: 회사 등급, 부서, 팀, 배치, 명성 원장. 회사의 생성·소멸(생애주기)은 멀티 컴퍼니 시스템 소유(§10)이며, 본 시스템은 생성된 회사의 조직 규칙을 소유한다.

### 7.1 회사 등급

**5단계 확정: 스타트업 → 소기업 → 중기업 → 대기업 → 그룹.**

**등급이 결정하는 것 (모두 등급에 단조 증가/유리):**

| 항목 | 기호 | 원칙 |
|---|---|---|
| 부서당 최대 팀 수 | `T_max(g)` | 단조 증가 |
| 회사 총원 상한 | `E_max(g)` | 단조 증가. 미배치 포함 전원 |
| 개설 가능 부서 수 | `D_max(g)` | **스타트업 1 / 소기업 2 / 중기업 이상 3** (구조 확정) |
| 월 유지비 | `U(g)` | 단조 증가. 경제에 요율 제공 |

- **설계 결정:** `D_max`는 중기업에서 3종 전부 도달, 이후 등급은 팀 수·총원으로 차별화. 근거: 부서 3종뿐인 MVP에서 부서 해금을 5단계에 늘어뜨리면 후반 등급 보상이 공허해진다.

**승급 조건 (g → g+1):**
1. **명성 문턱**: 명성 ≥ `R_up(g+1)` (문턱형, 비소비)
2. **비용**: 자금 `C_up(g+1)` 차감 가능
3. **가동률**: 활성 팀 수 ≥ `θ_util × (개설 부서 수 × T_max(g))`, `0 < θ_util ≤ 1`
   - **설계 결정: 가동률 조건 포함.** 근거: 현 상한을 쓰지 않은 승급은 유지비만 키우는 함정 — "쓰고 나서 넓힌다"를 시스템이 보증.

**승급 절차:**
1. 월말 정산 4단계에서 조건 1·3 판정 → 충족 시 "승급 가능" 표시(조건 유지되는 한 만료 없음 — 유지비 상승 타이밍을 플레이어가 고른다)
2. 플레이어 승인 = **예약 명령**
3. **설계 결정: 다음 사이클 일 처리 1단계에서 조건 전체(자금 포함)를 재검증하고, 통과 시 `C_up` 차감과 상한 갱신을 원자적으로 동시 적용한다. 실패 시 명령 기각.** 근거: 승인과 차감 사이의 잔액 경합(이중 지출)을 없애고 선불 원칙과 정합.
4. 유지비는 승급이 적용된 달의 월말부터 신등급 요율.

**강등:**
- **설계 결정: 자동·강제 강등은 없다. 단, 재무 상태 "부실"인 회사에 한해 자진 강등(1단계)을 허용한다.** 근거: 강제 강등은 실패 나선의 이중 부과지만, 자발적·위기 한정 강등은 "지출의 바닥"을 제공하는 복귀 수단이다. 평시 강등을 금지하는 이유: 유지비 회피용 등급 스위칭(정산 직전 강등→직후 승급) 악용 차단.
- 자진 강등은 월말 정산 4단계에서 적용. 효과: 유지비·상한이 하위 등급으로 축소, 승급비 환불 없음, **명성은 보존**(문턱형 — 재승급 시 자금·가동률 요건만 다시 충족하면 됨).
- 상한 초과 인원·팀·**부서**는 **해체하지 않되**, 초과가 해소될 때까지 신규 채용·팀 신설·팀원 증원·**부서 개설**이 금지된다(인원·팀은 자연 감소 대기). 이 상태는 조직 불변식의 명시적 예외다(§7.5).
- **설계 결정: 초과 부서는 강등 후에도 정상 운영(보드·착수·자율 주행)을 유지한다.** 부서 폐쇄가 post-MVP이므로 초과 부서의 해소 수단은 MVP에서 재승급뿐이며, 이는 허용된 지속 상태다(신규 부서 개설 금지만으로 `D_max`의 확장 억제 기능은 보존된다). 근거: 강등 시 부서 강제 폐쇄·기능 정지는 위기 복귀 수단(§11.6 수단 2)에 실패 나선을 이중 부과한다.

### 7.2 부서

- 부서 종류 목록은 업종 콘텐츠 데이터(업종당 3종). 회사는 자기 업종의 종류만, **종류당 1개만** 개설 가능.
- 개설: 개설 수 < `D_max(g)` ∧ 자금 ≥ `D_open`(첫 부서 면제). 일 처리 1단계 적용, 개설 직후 빈 팀 1개 자동 생성. **부서 폐쇄는 post-MVP.**
- **부서 역량 = Σ(소속 활성 팀의 팀 역량).** 활성 팀 = 팀장이 있는 팀. 표류 팀은 합산 제외 → 팀장 퇴사가 선택 가능 티어 하락으로 파급될 수 있다(의도된 리스크).
- **설계 결정: 부서/팀 역량은 컨디션을 반영하지 않는 정적 역량이다.** 근거: 티어 판정값이 매일 요동치면 선택 가능 목록이 불안정해져 자율 주행과 계획 양쪽을 해친다. 역량(무엇을 열 수 있나)과 효율(얼마나 빨리 하나)의 분리. 컨디션 보정은 프로젝트 진척 산출에서 적용(§8.6).
- 자율 주행 on/off 플래그는 부서 속성으로 본 시스템이 보관·토글 처리(1단계 적용). 선택 논리·페널티는 자율 주행 소관.

### 7.3 팀

**생성·해체:** 팀 수 < `T_max(g)`이면 무비용 생성. 팀장 임명 시 활성화(활성 팀만 착수 가능). **진행 중 프로젝트가 있는 팀은 해체 불가**, 해체 시 구성원은 미배치 풀로.

**구성:** 팀장 0..1 + 팀원 0..k. 직원은 동시에 1팀·1역할만(겸직 불가). `k = f(팀장 리더십)` 계단 함수. 팀장 공석 팀은 팀원 신규 배치 불가(기존 팀원 잔류).
- **k 축소 시(팀장 교체·강등, 표류 팀의 새 팀장 임명 — 자동 승계 포함):** 초과 인원은 지시 반영 시 자동으로 미배치 풀로 이동(플레이어 미지정 시 직무 스탯 합 낮은 순). 예외 상태를 남기지 않고 불변식을 항상 성립시킨다.

**팀 역량 = 집계(팀장+팀원의 부서 주/부 직무 스탯) × m(팀장 리더십).** 집계는 합산 기반 단조 증가, `m ≥ 1` 단조 증가.
- **설계 결정: 팀장의 직무 스탯도 집계에 포함.** 근거: 팀장 단독 팀도 역량 > 0이어야 초반 소규모 플레이가 성립. 리더십은 곱 보정으로만 작용해 역할이 겹치지 않는다.

**배치·이동:** 모든 조직 변경 명령은 일 처리 1단계에서 명령 순서대로 일괄 적용, 각 적용 직후 불변식 위반 명령은 기각. 진행 중 프로젝트가 있어도 **팀원 이동은 항상 허용**(역량 변화는 다음 진척부터 반영, 이탈자 보상 처리는 프로젝트 소관).
- **팀장 교체 페널티:** 진행 중 프로젝트를 가진 팀의 팀장을 교체하면 `P_swap`일간 리더십 보정 미적용(`m = 1`). 근거: 일 단위 팀장 돌려막기의 기대이익 제거. 자동 승계에도 적용된다.

**팀장 공석(표류):**
- 팀장이 퇴사·이동으로 공석이 되면 팀은 표류 상태: 부서 역량 합산 제외, 팀원 잔류(프로젝트 비수행이므로 컨디션 회복).
- **설계 결정: 표류 팀의 진행 중 프로젝트는 일일 진척 0이 되고 마감 기한은 계속 소모된다(별도 유예 규칙 없음).** 기한 초과 시 기한 실패로 귀결된다. 근거: 마감 기한이 자연 유예 역할을 하므로 별도 유예·정지 규칙은 중복이다. 공석 방치의 비용이 기한으로 표현된다.
- **설계 결정: 자율 주행 부서에 한해 자동 승계.** 표류 발생 다음 사이클의 1단계에서, **해당 팀 팀원 중 리더십 ≥ `L_min`인 자 중 최고 리더십자**를 시스템 지시로 팀장에 임명한다(`P_swap` 적용). 자격자가 없으면 표류 유지 + 팀장 부재 알림. 직접 관리 부서는 플레이어가 임명한다(공석 즉시 알림). 근거: 자율 주행의 약속("개입 없이 굴러간다")을 지키되, 승계 범위를 팀 내부로 한정해 다른 팀·미배치 풀을 건드리는 조직 개편으로 번지지 않게 한다. 이 자동 승계는 자율 주행 권한 경계의 유일한 조직 변경 예외로 §9.4에 등재된다.

### 7.4 미배치 인력 풀

**설계 결정: 팀 미배속 직원은 부서가 아닌 회사 단위 풀에 귀속.** 근거: 부서 간 이동 자유도 확보, 소속 계층 한 겹 축소. 미배치 직원은 프로젝트 미참여(컨디션 회복), 급여 정상 지급, 총원 상한에 포함. 신규 채용자는 미배치 풀로 들어온다.

### 7.5 조직 불변식 (모든 사이클 종료 시 성립)

1. 보유 회사 ≤ 해금된 슬롯 수 (≤ 10). 업종 중복 제한 없음
2. 직원은 정확히 1개 회사 소속, 0..1개 팀 소속, 팀 소속 시 역할은 팀장/팀원 중 하나
3. 회사 총원(미배치 포함) ≤ `E_max(g)`
4. 부서 수 ≤ `D_max(g)`, 종류 중복 없음, 종류는 업종 카탈로그에 존재
5. 부서의 팀 수 ≤ `T_max(g)`
6. 팀장 ≤ 1인, 팀원 수 ≤ `f(팀장 리더십)`
7. 팀의 담당 프로젝트 ≤ 1, 착수는 활성 팀만
- **예외(명문화):** ① 자진 강등 직후의 초과 상태에서는 3·4·5의 초과를 허용하되 신규 유입(채용·팀 신설·증원·부서 개설)을 금지한다. 초과 해소 시 예외 종료. 불변식 4의 초과는 부서 폐쇄가 post-MVP이므로 재승급으로만 해소되며, 그때까지 예외가 지속되는 것을 허용한다(§7.1). ② 팀장 공석(표류) 팀에서는 기준값 `f(팀장 리더십)`이 정의되지 않으므로 불변식 6의 팀원 수 상한 판정을 유예하고, 신규 팀원 배치 금지(§7.3)가 이를 대체한다. 새 팀장 임명(자동 승계 포함) 시 `k = f(신임 팀장 리더십)` 기준의 k 축소 자동 이동(§7.3)이 적용되어 불변식이 즉시 회복된다.

### 7.6 명성 원장

**설계 결정: 명성 원장(누적치 보관·문턱 충족 판정)은 본 시스템이 단독 소유한다.** 근거: 명성의 규칙적 소비처(승급 문턱)와 회사 엔티티의 소유자가 본 시스템이며, 자금=경제와 대칭인 단일 원장 구조를 만든다.
- **획득:** 프로젝트 완료 시 티어 비례 획득(산출·`α_auto` 적용은 프로젝트, 누적은 본 시스템). 유일한 유입 경로.
- **효과 (MVP에서 정확히 2가지):** ① 등급 승급 명성 문턱 `R_up` ② 지원자 풀 품질 입력(직원 시스템에 현재치 제공).
- **설계 결정: 명성은 프로젝트 해금에 사용하지 않는다.** 근거: 프로젝트 선택 가능성은 부서 역량으로 확정되어 있다. 겹치면 해금 조건 이원화.
- 단조 증가·감소 없음(§2.5). 회사 소멸 시 소멸. 진행/성장·직원 시스템은 읽기 전용 구독자다.

### 7.8 MVP / post-MVP

**MVP:** 등급 5단계, 승급 3조건+예약 원자 처리, 부실 한정 자진 강등(+불변식 예외), 부서 개설·역량 합산·자율 플래그, 팀 규칙 전반(계단형 `k`, 정적 역량, `P_swap`, 표류·자동 승계), 미배치 풀, 명성 원장.
**post-MVP:** 부서 폐쇄·통폐합, 부팀장(승계 예약), 부서장 보직·부서 버프, 팀 전문화, 구조조정 이벤트, 지주회사 시너지.

## 8. 프로젝트 시스템

### 8.1 설계 목표

프로젝트는 **유일한 수입원**이자 XP·명성의 공급원이다. 세 가지 긴장을 만든다: ① 티어 상승 압력(부서 역량을 키워야 상위 티어가 열림) ② 무리 대 안정(어려운 프로젝트 = 고보상 + 기한 실패·과로 위험) ③ 직접 하달 대 자율 주행(개입 가치).

### 8.2 정의 — 템플릿과 인스턴스

- **템플릿**: 업종 콘텐츠가 공급하는 정적 데이터(스키마는 본 시스템이 정의).
- **인스턴스**: 템플릿이 의뢰 보드에 게시된 것. 상태 `대기 → 진행 → 완료/실패`.
- **설계 결정: 보상 확정 시점 — 게시 시점에 기본 변동률(게시물 간 우열)을 확정하고, 보상 계수 소스(시세/성과 등급/라인 감쇠)가 있는 프로젝트의 최종 계수는 완료 시점에 평가한다.** 근거: 시세 마진·흥행 성과는 본질적으로 완료 시점 정보다.

### 8.3 속성 스키마

**기본 필드:**

| 분류 | 속성 | 정의 |
|---|---|---|
| 식별 | 업종 / 부서 종류 | 게시될 보드 결정 |
| 게이트 | **요구 티어 t (T1~T5)** | 부서 역량 게이트. **설계 결정:** 티어는 회사 등급과 같은 5단계 — 등급 성장 리듬과 티어 상승 리듬을 1:1 정렬 |
| 강도 | **난이도 d (하/중/상)** | 같은 티어 내 세부 강도. 작업량·컨디션 소모·보상 가중 |
| 분량 | 총 작업량 `W(t,d)` | 단조 증가. 누적 진척 ≥ W = 완료 |
| 기간 | 표준 기간 `D_std` | 티어 기준 역량 팀의 완료 소요일(표시용 환산치) |
| 기한 | **마감 기한 `L = D_std × λ_due`** (`λ_due > 1` 전역 상수) | 착수일로부터 L일 초과 시 미완료면 실패 |
| 보상 | 기본 보수 `M(t,d)`, 명성 `Rep(t)`, XP 풀 `X(t,d)` | 티어에 단조 증가. 게시 시 보수에 ±변동률 롤 |
| 상태 | 상태, 진척도, 경과일, 수행 팀, 착수 모드 태그(직접/자율) | 인스턴스에만 존재 |

**설계 결정: 티어(게이트)와 난이도(강도)의 분리.** 근거: 티어만 있으면 보드가 단순 최고 티어 클릭이 된다.

**확장 필드 6종 (MVP 정식 범위 — 업종 메커닉의 유일한 표현 수단):**

| 필드 | 값 | 기본값 |
|---|---|---|
| **착수 비용 `C₀`** | 착수 시 선불 차감(경제 O-5), 실패·포기 시 비환불 | 0 |
| **보상 계수 소스** | 고정 / 시세(품목군 g) / 성과 등급 / 라인 감쇠 | 고정(×1) |
| **보상 스케줄** | 일시 / 일시+꼬리(기간, 일 지급 단조 감소) | 일시 |
| **해금 조건** | 없음 / 완료 이력 술어(특정 프로젝트 완료 — **성과 등급 문턱 부가 가능**) / **동적 상태 술어(활성 꼬리 보유 자사 출시작 존재)** — 닫힌 목록, 신설은 본 절 개정 선행 | 없음 |
| **완료 부가 효과** | 없음 / 해금(대상 프로젝트) / 꼬리 갱신(대상 출시작 — 선택 규칙은 아래 설계 결정) | 없음 |
| **반복 가능** | 1회성 / 반복(누적 완료 카운터 `n`) | 1회성 |

**설계 결정: 확장 필드 지원을 본 시스템의 MVP 범위에 정식 등재한다.** 근거: 업종 콘텐츠가 이 필드에 의존하므로 숨은 스코프가 되어서는 안 된다. 필드 해석 함수(시세 `μ`, 꼬리 스케줄, 감쇠 `δ`, 해금 그래프)는 업종 콘텐츠 데이터다.

**설계 결정: 해금 조건은 완료 이력 술어(성과 등급 문턱 부가 가능)와 동적 상태 술어(활성 꼬리 보유 자사 출시작 존재) 2계열의 닫힌 목록이다.** 완료 이력 술어는 비가역(한번 열리면 유지), 동적 상태 술어는 근거 상태가 소멸하면(전 꼬리 소진) **재잠김**되며, 판정은 선택 가능 판정식(§8.5)의 "해금 조건 충족" 항에서 착수 시점마다 평가된다. 근거: 게임개발 꼬리 갱신 메커닉(§12.3)이 스키마 밖 예외가 되지 않게 하되, 열거를 닫아 "확장 필드 6종 = 업종 메커닉의 유일한 표현 수단" 원칙을 지킨다. 동적 술어의 평가 입력(활성 꼬리 상태)은 경제의 보상 스케줄 조회로 충당하므로 새 자원·새 단계가 필요 없다.

**설계 결정: "꼬리 갱신(대상 출시작)"의 대상 선택 규칙.** 활성 꼬리 보유 출시작이 복수일 때 — 직접 하달은 **착수 시 플레이어가 1개를 지정**한다(지정은 착수 명령의 일부, 활성 대상이 없으면 착수 거부 — 동적 해금 술어와 자연 일치). 자율 착수는 **잔여 꼬리 기간이 가장 짧은 출시작**을 결정론적으로 지정한다(동률 시 완료가 오래된 순 — 소멸 임박분 우선 구제가 유일하게 정당화 가능한 무정보 기본값). 대상은 착수 시 고정되며, 수행 중 대상 꼬리가 소진되어도 완료 시 갱신(잔여 기간 리셋)은 유효하다(갱신 횟수 상한은 정상 소모). 근거: 기간 리스크로 갱신형 프로젝트가 무의미해지는 역전 방지.

### 8.4 공급 — 의뢰 보드

- 프로젝트는 **부서별 의뢰 보드**로만 공급된다. 슬롯 수는 부서당 상수 `S_board`(등급·명성 무관 — 성장은 공급량이 아니라 티어 구성으로 표현).
- 게시물은 게시 기한 후 만료·소멸. 만료 처리와 빈 슬롯 보충은 **일 처리 5단계의 하위 작업**.
- 게시물 티어 분포는 부서 도달 티어 이하 위주 + **잠김 미리보기 1티어**(열람만 가능, 목표 제시용).
- **상비 의뢰:** 모든 부서 보드에 만료되지 않는 T1·난이도 하·`C₀`=0·보상 최저의 범용 의뢰가 항상 1건 존재하며, **역량 게이트 판정을 면제받는다 — 부서 역량과 무관하게 활성 팀만 있으면 상시 착수 가능**.
  - **설계 결정: 상비 의뢰의 게이트 면제 명시.** 근거: ① 신생·붕괴 부서의 "할 일 없음" 상태를 구조적으로 차단 ② 직원 1명(팀장 단독)만 남아도 현금 흐름을 만들 수 있다는 위기 복귀 보장(§11.6)의 이행 ③ 자율 주행 후보 목록이 공집합이 되지 않는 구조적 보증.

*(post-MVP: 명성 연동 특별 의뢰, 발주처 관계, 경쟁 입찰, 연쇄 의뢰)*

### 8.5 선택 가능 판정과 착수

**선택 가능 판정식 (단일 정의):**

> 선택 가능 = (업종 일치) ∧ (부서 종류 일치) ∧ (부서 역량 ≥ 티어 문턱 `R_t` **또는** 상비 의뢰) ∧ (해금 조건 충족) ∧ (1회성인 경우 미완료)

- 게이트 판정은 착수 시점 1회. 진행 중 역량이 문턱 아래로 떨어져도 회수되지 않는다.
- **설계 결정: 팀 역량은 착수 자격에 관여하지 않는다**(진척 속도·품질·컨디션 소모에만 반영). 근거: 게이트 주체는 부서라는 원 요구사항 준수. "강한 부서가 약한 팀에 고티어를 맡기는" 무리수는 금지가 아니라 기한 실패 리스크로 처벌하는 편이 선택지를 넓힌다. (자율 주행은 자체적으로 팀 단위 안전 필터를 적용한다 — §9.3)

**착수:**
- **직접 하달**: 플레이어가 게시물·수행 팀 지정 → 다음 사이클 1단계 적용(직접 태그). `C₀ > 0`이면 이 시점에 선불 차감(부족 시 착수 거부). 부서의 운영 모드와 무관하게 허용된다 — 자율 모드 부서에도 가능하며 이 경우에도 직접 태그다(태그의 단일 정의는 §9.2: 착수 주체 기준).
- **자율**: 사이클 2단계에서 자율 주행이 선택·착수(자율 태그). `C₀ > 0` 게시물은 자율 후보에서 제외된다(§9.5).
- **동시성**: 팀당 동시 1개(확정) / 프로젝트당 수행 팀 정확히 1개(복수 팀 협업은 post-MVP) / 부서 단위 인위적 상한 없음(팀 수·팀장 요건이 자연 상한).
- **팀장 공석**: 해당 프로젝트의 일일 진척 0, 마감 기한은 계속 소모 (§7.3의 단일 규칙).

### 8.6 진행 판정 (일 처리 3단계)

```
일일 진척 ΔP = base(팀 역량, 난이도) × e_team × (1 + ε)
```

- `base`: 팀 역량에 단조 증가, 난이도에 단조 감소 — "역량 대 난이도" 비율이 속도를 결정.
- `e_team`: 팀 구성원 효율 계수 `e(컨디션)`의 평균(직원 시스템 정의, 회사/조직 집계 — 효율 변환 함수는 게임 전체에서 `e` 하나뿐이다).
- `ε`: 좁은 범위의 일일 변동(질감용, 성패를 뒤집지 않는 수준).
- 동시에 **일일 컨디션 소모량** = `c_base(난이도) × 과부하 계수`를 직원 시스템에 전달. 과부하 계수는 팀 역량이 티어 기준에 미달할수록 커진다(≥1) — 무리한 수주는 느릴 뿐 아니라 팀을 갈아 넣는다.
- `α_auto`는 진척에 적용하지 않는다(보상 전용 — 속도 페널티는 컨디션 소모 총량까지 왜곡).

같은 사이클 4단계에서 `누적 진척 ≥ W` → 완료, `경과일 > L` ∧ 미완료 → 기한 실패.

### 8.7 완료 — 품질 판정과 보상

**품질 판정:**
- 완료 시 **연속 품질 점수 `q_raw ∈ [0,1]`** = q(기한 여유율, 역량 초과율, 수행 기간 평균 컨디션) — 세 인자 모두에 단조 증가.
- `q_raw`를 구간 분할한 **품질 등급 3종(우수/표준/미흡)**을 함께 산출한다. 티어 기준 역량과 같은 팀이 무난히 끝내면 "표준"이 중앙값.
- **설계 결정: 이산 등급과 연속 점수를 모두 인터페이스로 노출한다.** 근거: 게임개발 성과 등급(4단계) 매핑은 연속값의 구간 분할이어야 결정 가능하다(3값 입력으로 4등급을 만들 수 없다).

**보상 분배 (완료 사이클 4단계에서 스케줄 확정·이행 개시):**

| 보상 | 수령처 | 산식 원칙 |
|---|---|---|
| 자금 | 회사 | `M(t,d) × 게시 변동률 × m_Q(품질) × 계수 소스 평가값 × α_auto(자율 태그 시)` — 계수 소스 평가값: 고정=1 / 시세=`μ(g, 완료일)` / 성과 등급=`q(Q)` / 감쇠=`δ(n)`. 꼬리 스케줄이 있으면 일시분+꼬리분으로 분할 이행되며 **꼬리에도 착수 태그 기준 `α_auto`가 동일 적용**된다 |
| 명성 | 회사(조직 원장) | `Rep(t) × r_Q(품질) × α_auto(자율 태그 시)` |
| XP | 참여 직원 | XP 풀 `X(t,d)`를 **참여일수 비례 지분**으로 분배, 팀장 가중(>1). 중도 합류·이탈자는 참여일수만큼. **`α_auto` 미적용** |

- **설계 결정: `α_auto`는 자금·명성에 적용하고 XP에는 적용하지 않는다.** 근거·상세는 §9.2(단일 정의).
- **설계 결정: 착수금 없이 완료 후 지급(스케줄 개시).** 근거: 급여 대 수익의 현금 흐름 긴장 유지, 실패 정산 단순화. *(post-MVP: 마일스톤 분할 지급)*

### 8.8 실패

| 분류 | 발생 조건 | 결과 |
|---|---|---|
| **기한 실패** | 경과일 > L, 진척 < 100% | 자금·명성 보상 0. XP는 `X(t,d) × p(최종 진척도)`로 축소 지급(`p < 1`, 진척도에 단조 증가). `C₀` 비환불 |
| **중도 포기** | 플레이어 취소(취소 예약 → 다음 사이클 1단계 확정) | 기한 실패와 동일(보상 0, 축소 XP, `C₀` 비환불) |

- **금전 위약금은 없다**(§5.3의 설계 결정). 실패 비용 = 투입 기간·컨디션·기회비용 + (`C₀` 콘텐츠는) 선투입 손실.
- **명성은 감소하지 않는다**(획득 0으로 한정) — 문턱형·단조 자원 원칙.
- 축소 XP를 주는 이유: 실패한 도전이 완전 손실이면 플레이어가 상비 의뢰만 도는 극단적 안전 플레이로 수렴한다.
- 회사 소멸 경로의 강제 실패는 보상·XP 정산을 생략한다(§10.5).
- 실패 이벤트(참여 직원 포함)는 직원·자율 주행·진행/성장에 통지.

### 8.9 취소·이관 규칙

- 취소는 언제든 예약 가능(자율 부서 건 포함 — 직접 개입은 항상 자율 결정에 우선), 다음 사이클 1단계 확정. 취소 인스턴스는 소멸(같은 템플릿의 새 게시물은 이후 정상 등장).
- **진행 중 타 팀 이관 불가.** 근거: 이관을 허용하면 "강팀 막판 구원 등판"이 지배 전략이 되어 편성 결정의 무게가 사라진다. 조정은 팀원 교체로만.
- 자율 주행은 자기 착수 건을 스스로 취소하지 않는다(손절은 플레이어 전권, 자율 손절은 post-MVP).

### 8.10 인터페이스

| 상대 | 입력(받음) | 출력(줌) |
|---|---|---|
| **회사/조직** | 부서 역량(게이트), 팀 역량·팀 평균 컨디션(진척), 팀장 유무, 팀원 이탈 이벤트 | 팀별 점유 상태, 완료 명성(`α_auto` 적용 후 — 원장 누적용) |
| **직원** | (컨디션·`e`는 조직 경유 수신) | 직원별 XP(완료/실패), 일일 컨디션 소모량, 과부하·실패 이벤트 |
| **자율 주행** | 착수 결정(팀×게시물)+자율 태그, `α_auto` 값 | 부서별 게이트 통과 게시물 목록(티어·난이도·보상 3종 명목치·`C₀`·마감 기한·팀 역량 대입식 예상 소요일 평가 포함), 완료/실패 이벤트 |
| **경제** | `C₀` 차감 결과(부족 시 착수 거부), **활성 꼬리 상태(출시작별 잔여 기간 — 동적 해금 술어·꼬리 갱신 대상 판정용)** | 보상 스케줄(자금 최종액), `C₀` 청구, **꼬리 갱신 지시(대상 스케줄 잔여 기간 리셋)**, 월 매출 집계용 완료 기록 |
| **진행/성장** | — | 완료 이벤트(티어·수행 모드), 실패 이벤트 |
| **업종 콘텐츠** | 템플릿 카탈로그(기본+확장 필드), 필드 해석 함수, 성과 등급 매핑 테이블 | 스키마 정의, 완료 품질 점수 `q_raw`·품질 등급, 완료 이력(해금·감쇠 카운터 판정용) |

### 8.11 MVP / post-MVP

**MVP:** 스키마(티어 5×난이도 3+확장 필드 6종), 보드(고정 슬롯·게시 기한·일일 보충·게이트 면제 상비 의뢰), 게이트+잠김 미리보기, 결정적 진척+소변동, 연속 품질 점수+3등급, 보상 스케줄(일시+꼬리)·완료 지급, 기한 실패/중도 포기(무위약금·축소 XP·`C₀` 비환불), 동시성 규칙, 취소.
**post-MVP:** 마일스톤 지급·착수금, 복수 팀 협업, 연쇄 의뢰·입찰, 돌발 이벤트, 자율 손절, 위약금 재검토.

## 9. 자율 주행 / 위임 시스템

### 9.1 목적과 3원칙

멀티 컴퍼니 운영의 결정 부하를 통제하는 핵심 장치. 플레이어의 개입 횟수는 회사 수 × 부서 수에 비례해 폭증하므로, "집중할 곳"과 "맡길 곳"을 부서 단위로 나눈다.

1. **위임은 운영에 한정한다.** 자율 부서는 "일감을 골라 팀에 시키는 것"까지만 한다. 돈을 쓰는 결정과 조직을 바꾸는 결정은 플레이어 고유 권한이다(예외 1건: §9.4).
2. **위임에는 대가가 있다.** 자율 착수 프로젝트는 보상 페널티 `α_auto`를 가진다.
3. **판단은 결정론이다.** 동일 상태 + 동일 정책 = 동일 선택. 자율 주행은 AI 기술이 아니라 플레이어가 예측·역이용할 수 있는 게임 규칙이다.

### 9.2 운영 모드와 페널티

| 모드 | 선택 주체 | 보상 효율 | 부하 |
|---|---|---|---|
| **수동(직접 하달)** | 플레이어 | 100% | 높음 |
| **자율 주행** | 부서(정책 기반) | 자금·명성 ×`α_auto` (0<α<1) | 낮음 |

- **설계 결정: `α_auto`는 완료 보상 중 자금·명성에 적용하고 XP는 면제한다.** (게임 전체 단일 정의 — §8.7의 산식이 유일한 적용점) 근거: ① XP 면제 → 자율은 "돈·평판은 덜 벌지만 육성은 온전히 돌아가는 방치 모드"로서 존재 이유가 남는다. ② 명성 적용 → 직접 하달 회사가 승급도 빠르므로 "키우려는 회사에 개입을 집중"하는 포커스 전략(§11.3)이 성립한다. ③ 자율만으로도 생존은 가능해야 하며(§5.8-2) 이는 자금 페널티의 크기 문제이지 적용 범위 문제가 아니다.
- **설계 결정: 해금 게이트.** 자율 주행은 진행/성장의 해금 플래그(계정 전역, 소기업 승급 시 해금 — §11.4)를 입력으로 받으며, **해금 전에는 자율 전환 명령이 거부된다.** 근거: 초반 강제 수동 운영으로 코어 루프를 학습시킨다.
- **설계 결정: 신규 부서 기본 모드는 수동.** 근거: 위임은 페널티를 인지한 명시적 선택이어야 한다.
- **설계 결정: 착수 모드 태그는 부서의 운영 모드가 아니라 "착수 주체" 기준으로 확정된다 — 플레이어 지정 착수(직접 하달, 1단계) = 직접 태그, 선택 알고리즘 착수(2단계) = 자율 태그.** (게임 전체 단일 정의 — §8.5의 착수 규칙이 이를 따른다) 태그는 착수 시 인스턴스에 고정되어 이후 모드 전환에 영향받지 않으며, 꼬리 지급분에도 착수 태그가 따라간다(§8.7). 근거: ① "자율 착수 후 완료 직전 수동 전환" 회피 악용은 착수 시 태그 고정으로 차단된다. ② 주체 기준이어야 자율 모드 부서에 대한 직접 하달(아래)이 페널티 없이 성립해, 위기 수단 "직접 하달로 `α_auto` 회피"(§5.6)와 모순이 없다.
- **설계 결정: 자율 모드 부서에 대한 직접 하달은 허용되며, 그 건은 직접 태그(페널티 없음)로 착수된다.** 근거: 직접 개입은 항상 자율 결정에 우선(§8.9)하며, 모드 전환 없이도 개별 건 개입이 가능해야 주의 배분의 트레이드오프가 유연해진다. 직접 하달로 점유된 팀은 유휴 팀이 아니므로 그 사이클의 자율 선택 대상에서 자연히 제외된다(§9.3).
- 전환은 언제든 가능(1단계 적용), 비용·쿨다운 없음(태그 고정이므로 잦은 전환의 이득이 없다). 진행 중 프로젝트는 전환과 무관하게 기존 태그로 계속된다.
- **회사 일괄 토글** 제공(소속 전 부서 일괄 변경 매크로 — 상태는 부서 단위에만 존재).

### 9.3 정책 (파라미터 3종)과 선택 알고리즘

부서 단위 저장. 회사마다 **기본 정책 1세트**를 두고 신규 부서가 상속한다(부서별 개별 수정 가능). 정책 변경은 1단계 적용, 진행 중 건에는 무영향.

| # | 파라미터 | 선택지 | 역할 |
|---|---|---|---|
| P1 | **위험 성향** | 안정 / 균형 / 도전 | **마감 안전 계수 `s(성향)`** 결정. 후보 조건: `해당 팀 기준 예상 소요일 × s ≤ 마감 기한 L`. 안정일수록 `s`가 커서 여유 있는 건만, 도전은 `s ≈ 1`로 빠듯한 고티어까지 허용 |
| P2 | **우선 목표** | 수익 / 성장 / 명성 | 점수화 정렬 키: 자금/일 · XP/일 · 명성/일 |
| P3 | **컨디션 보호선** | 혹사 / 표준 / 보호 | 팀 평균 컨디션 < `C_guard`(단계에 단조 증가)면 착수 대신 **휴식**(그 사이클 미착수 — 컨디션 회복은 §2.5 규칙으로 자동 성립) |

- **설계 결정: P1 위험 성향은 티어 대역이 아니라 팀 단위 마감 안전 계수로 정의한다.** 근거: 실패 위험의 실체는 "팀 역량 대 티어 기준"의 비율(기한·과부하)이지 부서 역량이 아니다 — 부서 합산이 높아도 개별 팀이 약하면 고티어는 위험하다. 안전 계수 조건은 프로젝트 시스템의 실패 조건과 위험 정의를 직접 정렬시킨다.
- **설계 결정: 예산 한도 파라미터는 두지 않는다.** 근거: 자율 주행은 자금을 지출하지 않으므로(§9.5) 무의미하다. *(post-MVP에서 `C₀` 위임·훈련 위임 도입 시 부활 후보)*

**선택 알고리즘 (일 처리 2단계, 자율 부서마다 — 무난수·결정론):**

입력 스냅샷: 유휴 팀 목록(팀장 보유 ∧ 담당 프로젝트 없음), 팀별 역량·평균 컨디션, 게이트 통과 게시물 목록(상비 의뢰 포함).

1. 유휴 팀 정렬 — 팀 역량 내림차순, 동률 시 팀 ID 오름차순(강한 팀이 좋은 일감 선점).
2. 각 팀에 대해:
   a. **휴식 판정** — 평균 컨디션 < `C_guard` → 이번 사이클 휴식, 다음 팀으로.
   b. **후보 필터** — 게시물 중 [`C₀ = 0`] ∧ [예상 소요일 × `s` ≤ `L`]만 남긴다. **상비 의뢰는 마감 안전 계수 조건을 면제받고 항상 후보에 포함된다**(역량 게이트 면제(§8.4)와 같은 취지의 최후 폴백 보증 — 극저역량 팀 + 안정 성향에서도 후보가 비지 않게 한다).
   c. **점수화** — 점수 = P2 지정 자원의 명목 보상 ÷ 예상 소요일 (`α_auto`는 전 후보 동일 곱이므로 순위 무관).
   d. **배정** — 점수 내림차순 → 동점 시 티어 낮은 순 → 기간 짧은 순 → 카탈로그 ID 순. 최상위 후보를 자율 태그로 착수, 후보 목록에서 제거.
   e. 필터 결과가 상비 의뢰뿐이면 상비 의뢰를 착수한다. **상비 의뢰(게이트 면제·필터 면제·`C₀`=0·최저 난이도)가 항상 후보에 포함되므로 후보 공집합은 구조적으로 발생하지 않는다.**
3. 부서 간 경합 없음 — 보드는 부서 소유이므로 부서 처리 순서는 결과에 영향 없음.

**자율이 하지 않는 판단(명시적 비행동):** 진행 중 중단·교체 없음(완주 원칙 — 도전 성향에 맡긴 책임은 플레이어의 것), 채용·해고·훈련·팀 편성·부서 개설·승급·자기 정책/모드 변경 없음.

### 9.4 권한 경계

**원칙: 자율 = 운영(Operation), 플레이어 = 투자·조직(Investment & Organization).** 경계 판정 기준은 "자금 지출 여부 + 조직 변경 여부" 두 가지다(열거식이 아니라 기계적 판정 — 향후 행위가 추가돼도 분쟁이 없다).

| 행위 | 자율 가능? | 비고 |
|---|---|---|
| 유휴 팀에 `C₀`=0 프로젝트 선택·착수 | 가능 | 정책 범위 내, 보상에 `α_auto` |
| 컨디션에 따른 팀 휴식 | 가능 | P3 |
| **표류 팀 팀장 자동 승계** | **가능(유일한 조직 변경 예외)** | 팀 내부 `L_min` 자격자 한정, 실행은 회사/조직(§7.3). 위임 계약("개입 없이 굴러간다")에 포함된 예외로 명시 |
| `C₀ > 0` 프로젝트 착수 | 불가 | §9.5 |
| 진행 중 중단·교체, 채용·해고, 훈련, 팀 신설/해체·팀원 이동, 부서 신설, 승급 신청, 자기 정책·모드 변경, 그 외 자금 지출 일체 | 불가 | 플레이어 고유 |

**역방향 경계 — 자율 모드는 플레이어 권한을 제한하지 않는다.** 자율 모드 부서에 대해서도 직접 하달(직접 태그·페널티 없음, §9.2)·취소 예약(§8.9)을 포함한 모든 직접 개입이 항상 가능하며, 직접 개입은 자율 결정에 우선한다.

게임플레이 의미: 자율 부서는 방치하면 서서히 정체한다(훈련·승급·`C₀` 콘텐츠를 못 한다). 플레이어는 주기적으로 순회하며 투자·조직 결정을 내려야 하고, 이것이 멀티 컴퍼니의 리듬이다.

### 9.5 착수 비용 프로젝트의 취급

**설계 결정: `C₀ > 0` 프로젝트는 자율 선택 대상에서 제외한다.** 근거: ① 자율 무지출 원칙이 온전히 유지된다(자율 부서가 잔액을 소진해 급여 미지급을 유발하는 시나리오 원천 차단) ② 시세 타이밍·R&D 재투자 같은 **판단 프리미엄 콘텐츠를 직접 하달 전용으로 포지셔닝**하는 업종 콘텐츠 원칙(§12.5)과 정합적이다. 결과적으로 자율 위임된 무역 소싱부·화장품 생산부(자사 라인)·R&D부(라인 개발)는 고정 계수 카테고리(상비 의뢰·OEM·용역)만 수행한다 — 이는 결함이 아니라 "선투입 판단은 경영자의 일"이라는 의도된 배치다. *(post-MVP: 예산 한도 파라미터와 함께 `C₀` 자율 지출 개방)*

### 9.6 보고 규칙 — 예외 기반(management by exception)

자율 부서는 "정상 진행 중"을 매일 알리지 않는다(최대 10사 × 3부서 × 매일 알림은 부하 절감이라는 존재 이유를 파괴).

**즉시 알림 (개입 요청 신호, 3종):**

| 이벤트 | 조건 | 기대 개입 |
|---|---|---|
| 자율 프로젝트 실패 | 자율 착수 건의 실패 전이 | 위험 성향 하향, 팀 보강 |
| 팀장 부재 | 직접 관리 부서의 공석 발생, 또는 자율 부서의 **자동 승계 실패**(`L_min` 자격자 부재) | 팀장 지정·리더십 훈련 |
| 장기 저가동 | 팀의 휴식·대기·상비 의뢰 반복이 연속 `N_idle`일 초과 | 육성으로 역량 확보, 직접 하달, 재배치 |

즉시 알림은 전부 "자율이 스스로 해결할 수 없는 상태"와 일대일 대응한다. 타 시스템 소관 알림(급여 미지급, 이탈 위험)은 중복 발신하지 않는다. 알림에는 회사 태그가 포함되어 주의 전환의 트리거가 된다.

**월간 요약 (월말 5단계, 결산 리포트 내 부서 섹션):** 착수/완료/실패 건수, 획득 자금·XP·명성, **페널티 소실분**(자금·명성의 `α_auto` 미적용 가정치와의 차액 — "이 부서를 직접 챙길 가치"의 판단 근거), 팀별 가동률, 월말 평균 컨디션.

**상시 조회:** 자율 부서의 진행 상황·정책·알림 이력은 언제든 정확히 조회 가능. MVP에 정보 왜곡·은폐는 없다. *(post-MVP: 팀장 성향에 따른 보고 품질 차)*

### 9.7 상태 모델

- 부서: 운영 모드(수동|자율), 정책(P1~P3), 팀별 연속 저가동 카운터
- 회사: 기본 정책 1세트(상속용)
- 플레이어: 자율 주행 해금 플래그(진행/성장 소유의 읽기)
- 프로젝트 인스턴스: 착수 모드 태그(§8.3)

### 9.8 인터페이스

| 방향 | 상대 | 내용 |
|---|---|---|
| 입력 | 회사/조직 | 부서 역량·자율 플래그, 유휴 팀 목록(팀 역량·평균 컨디션), 표류·승계 이벤트 |
| 입력 | 프로젝트 | 게이트 통과 게시물 목록(보상 3종 명목치·`C₀`·기한·팀별 예상 소요일 평가), 완료/실패 이벤트 |
| 입력 | 진행/성장 | **자율 주행 해금 플래그(계정 전역)** — false면 전환 명령 거부 |
| 입력 | 플레이어 | 모드 전환·정책 설정·일괄 토글(1단계 반영) |
| 출력 | 프로젝트 | 착수 결정(팀×게시물)+자율 태그, `α_auto` 값(보상 산정용) |
| 출력 | 회사/조직 | 팀 휴식 결정(그 사이클 미착수 유지) |
| 출력 | 경제 | 월간 요약 데이터(결산 리포트 탑재용) |
| 출력 | 플레이어 | 즉시 알림 3종 |

### 9.9 MVP / post-MVP

**MVP:** 모드 2종+해금 게이트, 착수 시점 태그, `α_auto`(자금·명성), 정책 3종(마감 안전 계수형 P1)+기본 정책 상속, 결정론 알고리즘+상비 의뢰 폴백, 권한 경계(승계 예외 1건), `C₀` 자율 제외, 알림 3종+월간 요약+상시 조회, 일괄 토글.
**post-MVP:** 훈련 위임+예산 한도, `C₀` 자율 지출 개방, 채용 요청 워크플로, 팀장 성향 반영, 조건부 정책, 위임 숙련(α→1 점근).

## 10. 멀티 컴퍼니 시스템

### 10.1 목표와 원칙

여러 회사를 동시에 굴리는 것 자체를 게임플레이로 만든다. 핵심 명제:

> 플레이어의 주의(attention)는 명시적 자원이 아니지만 게임에서 가장 희소한 자원이다. 모든 규칙은 "지금 어느 회사를 직접 챙길 것인가"가 핵심 의사결정이 되도록 설계한다.

1. **동시 시간 진행** — 사이클은 전 회사 동시. 일시정지·배속 없음.
2. **방치의 비용은 `α_auto`로 표현** — "덜 챙기는 회사 = 덜 벌고 덜 유명해지는 회사"가 자동 성립한다. **설계 결정: 별도의 '주의 포인트' 자원·포커스 보너스는 도입하지 않는다.** 근거: 자원 6종 확정 원칙 + 페널티가 이미 개입 가치를 경제적으로 표현하므로 이중 장치다. "포커스"는 자율 토글 분포로 창발하는 개념이다.
3. **회사 간 결합 최소화** — MVP에서 회사들은 사실상 독립 경제체다(§10.6 표).
4. **회사는 회수 가능한 자산** — 키운 회사는 청산해 골드로 회수할 수 있다(단, 항상 순손실 — §5.8-9). 파산은 반환 0이므로 "언제 손절하느냐"가 포트폴리오 판단의 한 축이 된다.

### 10.2 경영자 레이어

경영자는 회사 위의 최상위 엔티티이며 **골드 원장 1개와 비자원 상태**를 가진다: 골드 잔액, 보유 회사 목록(0..10), 슬롯 상태(10개), 슬롯 해금 플래그(비가역), 청산·파산 이력(통계용).

**설계 결정: 경영자 재화는 골드 단일이며, 골드 원장은 본 시스템이 소유한다.** 획득 = 청산 반환(§10.5), 소비 = 설립비 지불(§10.4) — 증감 경로는 이 둘뿐이고, **골드→회사 자금 주입 경로는 없다**(§5.9). 근거: 골드가 회사 자금으로 흘러들면 청산이 회사 간 이전의 우회 통로가 된다. 골드는 "회사를 자산으로 회수해 다른 회사 설립에 재배치하는" 메타 화폐로만 기능한다. (다이아 등 프리미엄 재화는 post-MVP — §2.5의 설계 결정)

**설계 결정: 경영자 명성은 존재하지 않는다.** 근거: 명성은 회사 귀속으로 확정되어 있다(§7.6). 제3자 가격 협상형 **회사 매각·M&A는 post-MVP**(청산은 시스템 환수 고정 산식이므로 매각과 다르다).

### 10.3 회사 슬롯

- **슬롯 10개(확정), 업종 제한 없음** — 동일 업종 회사를 여러 개 동시 보유할 수 있다(각 회사는 독립 경제체이므로 시스템적 충돌이 없다. 전역 시세 `μ`는 모든 무역 회사가 공유 — §12.2). 슬롯은 업종에 고정되지 않는다.
- 슬롯 상태 머신: `잠김 → (해금 조건 충족, 월말 등급 심사 결과를 읽어 자동 판정) → 빈 슬롯 → (설립) → 점유 → (소멸) → 빈 슬롯`.

**해금 조건 (본 시스템 단독 소유, 일반식):**

| 슬롯 | 해금 조건 |
|---|---|
| 슬롯 1 | 게임 시작 시 |
| 슬롯 n (n = 2..10) | 보유 회사 중 **중기업(3등급) 이상이 n−1곳** |

- **설계 결정: 해금은 개수 문턱의 일반식이다(슬롯 2 = 1곳, 슬롯 3 = 2곳, … 슬롯 10 = 9곳).** 근거: 해금의 설계 의도는 "기존 회사들을 자율 주행에 맡겨도 될 만큼 키웠다는 검증"이며, 슬롯이 늘수록 포트폴리오 전체의 성숙을 요구하는 단조 확장이 이에 부합한다. 한 회사 몰빵으로 다슬롯이 열리는 우회를 막고, 마일스톤 M12(쌍두 체제)와도 정합된다. 후반 슬롯의 페이싱(상위 슬롯에 등급 문턱 상향이 필요한지)은 밸런싱 질문으로 남긴다(§15).
- **설계 결정: 해금 조건은 회사 등급 단일 문턱**(자금·명성 문턱 없음 — 등급 심사가 이미 자금·명성을 검증하므로 중복. 골드 구매 해금도 없음 — 해금은 역량의 검증이지 재화의 소비처가 아니다). **해금은 비가역·플레이어 귀속**: 조건을 만족시킨 회사가 이후 강등·청산·소멸돼도 회수되지 않는다. 근거: 재잠금은 청산 결정에 불필요한 공포를 얹고 복귀 루프를 파괴한다.

### 10.4 설립 — 신규 회사 초기 상태 (단일 정의)

**모든 회사 공통 초기 상태 (설계 결정 — 본 표가 유일한 정본):**

| 항목 | 초기값 |
|---|---|
| 회사 등급 | 스타트업(1단계) |
| 자금 | `C_seed(업종)` — 업종별 고정값, **시스템 지급**(I-2) |
| 명성 | 0 |
| 부서 | 업종별 3종 중 **플레이어가 1개 선택 개설**(개설비 면제) — 첫 의사결정부터 플레이 방향을 정하게 한다 |
| 팀 | 선택 부서에 빈 팀 1개 자동 생성 |
| 직원 | **창립 선발**: 창립 지원자 풀(직원 시스템 §6.4)에서 최대 `N_found`명 계약금 없이 선발 |
| 재무 상태 | **건전**(미지급·미납 잔액 0으로 시작 — '직전 월말 전액 지급' 이력이 없는 신설 회사의 명시적 초기값, §5.6) |

**설립 규칙:**
- **첫 회사(게임 시작)**: 슬롯 1에 업종 선택 설립. **설립비 없음.**
- **추가 회사(슬롯 2 이후)**: 조건 = ① 빈 슬롯 존재 ② 설립비 지불 가능 — **지불 수단 택일**: (a) 자금 지불형: **스폰서 회사**(보유 회사 중 플레이어 지정 1곳)의 자금 ≥ `F_found(업종)`(O-6) / (b) 골드 지불형: 경영자 골드 ≥ `F_found_G(업종)`(골드 원장 차감, 경제 원장 밖). 절차 = 설립비 지출 → 신규 회사가 위 초기 상태로 생성. 업종은 보유 여부와 무관하게 자유 선택(중복 허용).
- **설계 결정: 설립비는 지불 수단과 무관하게 전액 소멸(싱크)하고, 시드는 시스템 지급이다 — 설립은 자금 "이전"이 아니다.** 근거: 회사 간 이전 금지 원칙과 충돌 없이 확장에 기회비용을 부여하는 구조. 자금 지불형은 "스폰서의 급여·유지비 여력을 훼손하면서까지 확장할 것인가", 골드 지불형은 "과거 청산으로 회수한 가치를 어디에 재투자할 것인가"의 트레이드오프다. 두 수단의 가치 등가 원칙(`F_found_G` ↔ `F_found`)은 밸런싱 변수.
- **설계 결정: `F_found(업종) > C_seed(업종)`** (§5.8-5). 설립은 총량 기준 순소비 — 설립·청산 반복이 가치 증식 채널이 되지 않는다(§5.8-9와 결합).
- **설계 결정: 보유 회사 0 상태에서의 재설립은 첫 회사 규칙을 적용한다(설립비 면제, 시드 지급, 창립 선발 제공).** 근거: 전 회사 파산 시 스폰서가 존재하지 않으므로, 이 예외가 없으면 영구 진행 불능이 된다. 이 예외로 "게임오버 없음 + 데드락 없음"(§11.6)이 실제로 성립한다.
- 설립 지시는 일 처리 1단계 적용, 신규 회사는 그 사이클부터 공통 시간축에 합류.

### 10.5 소멸 — 청산과 파산 (단일 정리 절차 + 반환 산정)

자발적 소멸(**청산**)과 강제 소멸(**파산**)은 **동일한 정리 절차**를 공유하며, 차이는 반환 골드의 유무뿐이다(본 시스템이 절차와 산정을 소유, 경제는 파산 판정 이벤트와 산정용 스냅샷만 제공).

**트리거:**
- **청산(자발)**: 플레이어 지시. 재무 상태 무관하게 가능하며, **마지막 1사도 청산 가능**. **설계 결정:** 근거 — 회사 0 상태에서 §10.4의 무료 재설립로 즉시 재기할 수 있어 데드락이 없고, "골드를 들고 다른 업종으로 갈아탄다"는 정당한 용도가 있으며, 시드·채무 공제 규칙(아래)으로 반복 악용은 무이득이다.
- **파산(강제)**: 경제의 파산 판정(§5.6). **몰수형 — 반환 골드 0.** 보유 회사 0 상태는 파산 경유로도 도달 가능하며, 허용된 상태다.

**청산 반환 산정 (청산 한정, 절차 개시 시 확정):**

> 반환 골드 `G_liq = γ_cash × max(0, 잔액 − 미지급·미납 잔액 − C_seed(업종)) + γ_up × Σ(승급비 C_up 지출 누계)`

- 환수율 `γ_cash, γ_up ∈ (0, 1)` — 모든 항이 부분 환수이므로 청산은 항상 순손실이다(가드레일 §5.8-9).
- **시드 `C_seed` 공제**: 무료 설립(첫 회사·회사 0 재설립)으로 받은 시드를 곧바로 골드로 환전하는 [무료 설립 → 즉시 청산] 펌프를 수익 0으로 만든다.
- **미지급·미납 잔액 공제**: 체불을 쌓아 두고 청산으로 채무를 털어내는 경로를 차단한다(채무는 반환에서 먼저 상계).
- **설계 결정: 명성·활성 꼬리·직원 투자(계약금·훈련)는 환산하지 않는다.** 근거: 명성 환산은 "성숙 회사를 주기적으로 수확"하는 퇴화 루프를 만들고, 이들의 소멸 손실이야말로 "계속 굴릴까, 회수할까" 판단의 실체다. *(post-MVP: 명성 일부 환산 재검토)*

**정리 절차 (지시/판정 → 다음 사이클 1단계에서 일괄 처리):**
1. 진행 중 프로젝트 전부 강제 실패 처리 — **보상·XP 정산 생략**(회사 소멸 경로)
2. 소속 직원 **전원 소멸**(계약 해지, 개인 미지급 잔액 소멸)
   - **설계 결정: 지원자 풀 반환 없음.** 근거: 직원 이적 금지 원칙과 정합 — 반환 모델은 "성숙 직원을 청산·재설립으로 재획득"하는 우회로가 된다
3. 청산이면 `G_liq`를 골드 원장에 지급. 이후 잔여 자금·명성·**활성 꼬리 스케줄** 전액 소멸(반환 산정에 포함되지 않은 가치의 소멸이 청산·파산의 기회비용이자 손절 판단의 실체)
4. 슬롯 반환(점유 → 빈 슬롯). 플레이어 귀속 해금·마일스톤·**골드**는 보존
- 악용 분석: [설립–청산] 반복은 시드 공제 + 환수율 < 1 + 명성 리셋으로 항상 순손실(§5.8-9). 별도 쿨다운 불요. **파산 직전의 청산은 허용되며 의도된 플레이다** — 파산 몰수 대비 "제때 손절"의 보상이 청산 반환의 존재 이유다.

### 10.6 회사 간 상호작용 — MVP 차단 표

| 상호작용 | MVP | 규칙/근거 |
|---|---|---|
| 자금 이동 | 금지 | §5.9. 설립비는 싱크+시스템 지급이라 이전 아님 |
| 직원 이적 | 금지 | **설계 결정:** 고레벨 직원 이식은 신규 회사의 성장 곡선과 채용 시스템의 의의를 붕괴시킨다. 신규 회사는 창립 선발 후 반드시 자체 채용으로 성장한다 |
| 시너지(수익/역량 보너스) | 없음 | post-MVP |
| 지원자 풀 공유 | 없음 | 풀 품질은 각 회사 명성으로 독립 결정 |
| 타 회사 상태 읽기 참조 | 허용 | 슬롯 해금·스폰서 자격 판정에 한정(읽기 전용) |
| 설립비 지출 | 허용 | 1회성·소멸형(자금 지불형 한정 — 골드 지불형은 회사 간 결합이 아예 없음) |
| 청산 반환 골드의 회사 주입 | 금지 | 골드의 소비처는 설립비뿐(§5.9, §10.2) — 청산이 자금 이전의 우회로가 되는 것을 차단 |

### 10.7 횡단 루프 — 주의 배분

1. **포커스 결정** — 이번 달 직접 하달로 운영할 주력 회사를 정하고 나머지는 자율 위임
2. **주력 운영** — 채용·배치·하달·훈련을 밀도 있게 (고효율·고부하)
3. **위성 점검** — 즉시 알림과 이상 신호(자금 하강, 이탈 위험, 저가동)만 확인
4. **월말 횡단 결산** — 회사별 결산 리포트 비교(페널티 소실분 포함), 다음 달 포커스 재배분
5. **확장/회수 판단** — 슬롯·설립비(스폰서 자금 또는 골드) 충족 시 신규 설립, 다 키웠거나 회생 불가한 회사의 청산

긴장의 원천: 회사 추가의 한계 수익은 `α_auto`로 체감한다(무조건 슬롯을 다 채우는 것이 정답이 되지 않게 하는 억제 장치) / 신규 회사는 시드 소진 전에 궤도에 올라야 하므로 설립 직후 강제 포커스가 생긴다 — "기존 회사가 방치를 버틸 만큼 성숙했는가"가 설립 타이밍 판단의 실체 / 설립비는 스폰서 현금흐름 또는 과거 청산으로 모은 골드에서 나온다 / 청산은 이르면 미래 수익을 버리고 늦으면(파산) 반환이 0이다.

### 10.8 인터페이스

| 방향 | 상대 | 내용 |
|---|---|---|
| 입력 | 회사/조직 | 각 회사의 현재 등급(월말 심사 결과 — 슬롯 해금 판정) |
| 입력 | 경제 | 자금 잔액(스폰서 자격 검증), 파산 판정 이벤트(몰수형 소멸 트리거), **청산 산정용 스냅샷(잔액·미지급/미납·승급비 누계)**, 월간 결산(횡단 비교) |

### 10.9 MVP / post-MVP

**MVP:** 경영자 레이어(골드 원장+비자원 상태), 슬롯 10(업종 중복 허용·개수 문턱 일반식 해금·비가역), 단일 초기 상태(시드+창립 선발), 설립비 이중 지불 수단(스폰서 자금/골드, 첫 회사·회사 0 재설립 면제), 청산(반환 산정: 시드·채무 공제+환수율)·파산(몰수) 통합 정리 절차(직원·꼬리 소멸, 마지막 1사 청산 허용, 회사 0 허용), 상호작용 차단, 횡단 루프.
**post-MVP:** 다이아(프리미엄 재화), 제3자 매각·M&A, 청산 시 명성 일부 환산, 자금 이전(손실 계수), 직원 이적(이적비+충성도 페널티), 업종 조합 시너지, 슬롯 11+, 지주회사.

## 11. 진행/성장 시스템

### 11.1 설계 원칙 — 결정 부하 곡선

> **원칙: (운영 중 회사 수) × (회사당 요구 개입 밀도) ≈ 상수.** 부하를 늘리는 콘텐츠(신규 회사)는 반드시 부하를 낮추는 도구(자율 주행)가 먼저 해금된 뒤에 열린다.

### 11.2 게임 목표

**설계 결정: 완주 조건이 있는 무한 성장형(soft-ending).** 근거: MVP 콘텐츠(3업종 × 5등급)는 유한하므로 종착점이 필요하지만, 세션 강제 종료는 경영 시뮬레이션의 관성과 충돌한다.
- **완주(그룹 완성)**: 전 업종(MVP 3종) 각각에서 그룹(5등급) 도달 **이력**을 확보. 완주 리포트(누적 통계) 생성 후 플레이는 계속된다.
  - **설계 결정: 완주는 동시 보유가 아니라 업종별 달성 이력(비가역) 기준이다.** 근거: 청산이 정당한 플레이인 이상, 그룹 회사를 청산했다고 완주가 되돌아가면 안 된다. **추가 업종은 완주 조건에 소급 포함하지 않는다**(완주는 달성 시점의 업종 집합 기준, 신규 업종의 그룹 달성은 별도 기록 — §12.8).
- **게임오버 없음** — 실패는 상태이지 종료가 아니다(§5.6·§11.6). 실패 비용은 시간이며, 완주 소요 일수가 사실상의 스코어다.
*(post-MVP: 프레스티지 재시작, 완주 일수 리더보드)*

### 11.3 단계 국면 (시스템 상태가 아니라 해금 스파인이 만드는 자연 국면)

| | 1단계: 창업기 | 2단계: 위임기 | 3단계: 확장기 | 종반: 완주 이후 |
|---|---|---|---|---|
| 구간 | ~첫 소기업 승급 | ~첫 중기업 승급 | ~전 업종 그룹(완주) | 완주 후 |
| 회사 수 | 1 | 1 | 2~10 | 자유 |
| 가용 도구 | 직접 하달만 | +자율 주행 | +회사 슬롯 | 전부 |
| 개입 밀도 | 매 사이클 | 수 사이클 단위 | 회사별 차등 | 월 단위 |
| 학습 목표 | 코어 루프 | 위임 트레이드오프, 팀장 육성 | 포트폴리오 관리, 명성 0 재등반 | 최적화·기록 |
| 핵심 긴장 | 첫 월급일 전 현금 확보 | `α_auto` vs 개입 부하 | 신생 회사 J커브 | 시간 효율 |

단계 전환 게이트는 전부 **회사 등급**으로 통일(설계 결정 — 등급은 자금+명성을 내포한 종합 지표이므로 별도 조건 신설은 이중 장부). 3단계의 재미: 성숙 회사는 자율로 돌리고 신생 회사에 개입을 몰아주는 **비대칭 운영** — §11.1 원칙의 실현.

### 11.4 해금 스파인

**설계 결정: 해금 대상은 "자율 주행"과 "회사 슬롯" 2종으로 최소화.** 채용·배치·훈련·하달·부서 개설 등 기본 도구는 시작부터 전부 개방. 근거: 해금은 부하 조절 장치로만 쓴다 — 기본 도구를 잠그면 코어 루프 학습이 방해받는다.

| # | 해금 대상 | 게이트 | 소유 |
|---|---|---|---|
| 0 | 첫 회사 + 전 기본 기능 | 게임 시작 | — |
| 1 | **자율 주행**(부서 토글 사용권, 계정 전역) | 보유 회사 1곳 **소기업(2등급)** 승급 | **본 시스템**(플래그를 자율 주행에 출력) |
| 2 | **슬롯 2** | 1곳 중기업(3등급) | 멀티 컴퍼니(§10.3 — 본 표는 조망용 참조) |
| 3 | **슬롯 3..10** | 중기업 이상 n−1곳(일반식) | 멀티 컴퍼니(참조) |
| 4 | 완주 | 전 업종 그룹 달성 이력 | 본 시스템 |

- 해금은 **플레이어 귀속·영구적**(조건 달성 회사가 이후 강등·소멸해도 회수 없음). 근거: 해금 회수는 복귀 루프를 파괴한다 — 회사를 잃어도 플레이어의 진행은 보존되어야 재기가 재시작과 달라진다.
- 소기업 < 중기업이므로 **자율 주행은 구조적으로 항상 2호 회사보다 먼저 열린다**(§11.1 원칙의 보증).
- 자율 주행 해금 시점의 의도: 소기업부터 팀 수가 늘어 수동 부하가 실제로 체감될 때 위임 도구를 준다.

### 11.5 마일스톤 (선형 체인, 계정 전역, 튜토리얼 겸용)

**설계 결정: 마일스톤은 자원 보상을 지급하지 않는다(보상은 해금과 기록뿐).** 근거: 자원 획득 경로(자금·명성=프로젝트)를 보존 — 마일스톤이 돈을 주면 경제 밸런싱 변수가 오염된다.
**설계 결정: 별도 튜토리얼 모드 없음.** M1~M6이 튜토리얼이다. 조건을 이미 충족한 마일스톤은 순서와 무관하게 자동 달성(앞질러도 막히지 않음).

| # | 마일스톤 | 조건 | 효과 |
|---|---|---|---|
| M1 | 첫 채용 | 직원 ≥ 1 (창립 선발 포함) | 안내 |
| M2 | 첫 팀 편성 | 팀장 지정 팀 ≥ 1 | 안내 |
| M3 | 첫 하달 | 직접 하달 착수 ≥ 1 | 안내 |
| M4 | 첫 완료 | 완료 ≥ 1 | 안내 |
| M5 | 첫 정산 통과 | 급여 완납 월말 1회 | 안내 |
| M6 | 첫 육성 | 훈련 ≥ 1 | 안내 |
| M7 | 소기업 승급 | 임의 회사 등급 ≥ 2 | **자율 주행 해금** |
| M8 | 위임 실습 | 자율 완료 `N_auto`회 | 학습 완료 표식 |

**회사 단위 목표: 승급 요건의 미러링(가시화)만.** 본 시스템은 독자 회사 목표를 신설하지 않는다(목표 장부 이원화 방지). 각 회사에 "다음 승급까지: 명성/자금/가동률" 체크리스트를 표시(데이터는 회사/조직 입력). 위기 회사에는 대신 **복귀 체크리스트**(미지급 잔액 해소 → 전액 지급 월말)를 표시.

### 11.6 위기와 복귀 루프

**설계 결정: 본 시스템은 독자적 위기 플래그를 두지 않고 경제 재무 상태 머신의 "부실" 상태를 구독한다.** 진입 = 부실 전이, 해제 = 전액 지급(이월 포함) 월말의 건전 복귀. 근거: 같은 현상(미지급)에 대한 병렬 상태 체계는 진입·해제 시점의 미세 불일치를 낳는다. 본 시스템 소관은 부실 중 UI(복귀 체크리스트·리포트 강조)뿐이며, 자진 강등 허용 판정도 부실 상태 자체가 기준이다(§7.1).

**복귀 4수단 (전용 구제 메커니즘 없음):**
1. **수입의 바닥 — 상비 의뢰.** 게이트 면제·`C₀`=0·상시 존재(§8.4)이므로 직원이 1명이라도 있으면 현금 흐름 ≥ 0을 만들 수 있다.
2. **지출의 바닥 — 자진 강등**(부실 한정, §7.1). 유지비·상한 축소, 명성 보존 덕에 재승급이 빠르다.
3. **인건비 자연 감소.** 미지급 → 충성도 하락 → 퇴사는 처벌인 동시에 인건비 자동 축소 경로다(무비용 해고로 능동 가속도 가능).
4. **최후 수단 — 청산 후 재설립**(§10.5). 파산(몰수) 전에 청산하면 반환 골드라도 남고, 플레이어 귀속 해금·마일스톤·골드가 보존되므로 재시작이 아니라 복귀다.

**데드락 부재 (설계 요건):** 직원 ≥ 1이면 수단 1로 탈출 가능(상비 의뢰 게이트 면제가 보장). 최악 상태(전 회사 파산, 보유 회사 0)에서도 §10.4의 무료 재설립(시드+창립 선발)으로 항상 탈출 가능. 따라서 게임오버 없이도 진행 불능 상태는 발생하지 않는다.

### 11.7 인터페이스

| 방향 | 상대 | 내용 |
|---|---|---|
| 입력 | 프로젝트 | 완료 이벤트(티어·수행 모드 — M4·M8 판정) |
| 입력 | 회사/조직 | 등급·승급 결과(해금·M7~M14), 다음 승급 요건(체크리스트 미러링), 명성 현재치(읽기 전용) |

| 입력 | 직원 / 멀티 | 채용·훈련 이벤트(M1·M6), 팀 편성(M2), 슬롯·설립/소멸 이벤트(M10·M13) |

### 11.8 MVP / post-MVP

**MVP:** soft-ending 완주, 3단계 국면, 해금 스파인 2종, 마일스톤 M1~M15(무보상·자동 달성), 승급 미러링 목표, 부실 구독형 위기 UI, 복귀 4수단.
**post-MVP:** 프레스티지·리더보드, 반복 도전 과제, 위기 전조 경보(현금 흐름 예측 고도화), 주간 리포트 연동 목표.

## 12. 업종별 콘텐츠 (무역 / 게임개발 / 화장품)

### 12.1 담당 범위와 원칙

본 챕터는 3개 업종의 부서 구성, 프로젝트 카탈로그, 고유 메커닉을 **데이터로** 정의한다. 판정·산출 알고리즘은 각 시스템 소관이다.

1. **업종 콘텐츠 = 데이터.** 세 업종 모두 공통 스키마(§8.3)의 인스턴스 데이터로 표현되며, 진행·정산 로직에 업종별 분기 코드를 요구하지 않는다.
2. **고유 메커닉은 업종당 정확히 1개**, 전부 확장 필드 6종의 조합으로 표현한다.
3. **프레임 불가침.** 새 자원 없음, 새 처리 단계 없음: 시세 계수는 일자의 결정적 함수(조회만), 꼬리는 4단계 지급의 일부, 해금은 §8.3 해금 조건 술어(완료 이력 / 동적 상태)의 조회, 감쇠 카운터는 해석 파라미터다.
4. **모든 부서는 개전 즉시 유효.** 해금 없는 기초 카테고리를 최소 1개 보유하며, 상비 의뢰가 모든 보드에 존재한다.

**설계 결정: 3개 업종 공통 부서로 영업부를 둔다.** 근거: 업종 간 학습 전이("어느 회사든 영업부 = 저분산 고정 보상")로 멀티 운영의 인지 부하를 낮춘다.

| 업종 | 공통 부서 | 고유 부서 1 | 고유 부서 2 |
|---|---|---|---|
| 무역 | 영업부 | 소싱부 | 물류부 |
| 게임개발 | 영업부 | 개발부 | 라이브운영부 |
| 화장품 | 영업부 | R&D부 | 생산부 |

카탈로그 표기: 체인의 T1 < T2 < … 는 체인 내 상대 순서이며 절대 티어 매핑은 프로젝트 시스템 정의를 따른다. 기간·보상은 원칙(짧음/중간/김, 단조성)으로만 서술한다.

### 12.2 업종 1: 무역 — 시세 마진 (입문)

기간이 가장 짧고 회전이 빠르다. 카탈로그 절반 이상이 저분산 고정 보상이며, 시세 메커닉은 "몰라도 평균 흑자, 활용하면 상방".

**시세 계수 `μ(g, day)`:** 품목군 3종(생활소비재/원자재/전자기기 — 구조 확정)별 **일자의 결정적 함수**. 구간 내 완만한 진동, 저티어 품목군일수록 변동폭이 좁다. 트레이딩 딜의 실효값: 매입가 = `C₀ × μ(g, 착수일)`(O-5 선불), 판매가 = `R_base × μ(g, 완료일)`. **마진 = 판매가 − 매입가** — 쌀 때 착수해 비쌀 때 완료되면 이득. 현재 시세는 플레이어에게 공개(미래 예고는 post-MVP). 시세 중립 기대값에서도 기대 마진 양수(§5.8-7).

**카탈로그:**
- **영업부 — 중개 무역** (고정·`C₀`=0·일시·반복): T1 지역 도매 알선 / T2 국내 기업 간 중개 / T3 해외 바이어 매칭(명성 가중 시작) / T4 대형 상사 중개 계약 / T5 국제 입찰 중개
- **소싱부 — 트레이딩 딜** (시세·`C₀`>0·일시·반복): T1 생활소비재 소량 매입판매(메커닉 튜토리얼) / T2 컨테이너 소비재 딜 / T3 원자재 스팟 딜 / T4 전자기기 대량 딜(변동폭·`C₀` 큼) / T5 원자재 장기 계약 딜(기간 김 → 시세 괴리 위험 최대 = 고위험 고수익)
- **물류부 — 물류 용역** (고정·`C₀`=0·일시·반복): T1 근거리 운송 대행 / T2 창고 보관 계약 / T3 통관 대행 패키지 / T4 국제 복합 운송 / T5 물류 아웃소싱 총괄 계약

**의사결정:** 포트폴리오 배분(안정 중개·물류 vs 시세 노출 트레이딩)과 착수 타이밍. **소싱부는 전 카탈로그가 `C₀ > 0`이므로 사실상 직접 하달 전용 부서다**(자율 위임 시 상비 의뢰만 수행 — §9.5). 무역 회사를 위성으로 돌릴 때는 영업부·물류부가 수입원이 된다.

### 12.3 업종 2: 게임개발 — 출시 꼬리 수익 (상급)

기간이 가장 길고 분산이 가장 크다. 개발 기간 내내 수입 없이 급여가 나가는 현금 흐름 압박이 정체성이며, 성공 시 꼬리로 기대 수익 상한이 3업종 중 최고. 게임개발 카탈로그에 `C₀ > 0`은 없다(전 부서 자율 위임 가능).

**성과 등급과 꼬리:**
- 출시형(개발부 자체 개발)은 완료 시 프로젝트의 **연속 품질 점수 `q_raw`**를 받아 **성과 등급 Q 4단계(실패작/평작/성공작/히트작)**로 매핑한다.
- **설계 결정: 매핑에는 흥행 롤이 개입한다** — 품질 점수가 분포의 기대값을 결정하고(품질↑ → 상위 등급 확률 단조↑), 실제 등급은 롤로 확정된다. 근거: "수익 분산 최대"라는 업종 정체성의 분산 원천을 이 롤 하나로 한정한다(게임 내 유일한 대형 결과 RNG — 다른 업종·카테고리는 무롤).
- 보상 스케줄: 일시 `R_base × q(Q)` + 꼬리 — `D_tail(Q)`일간 매일 지급(경과일에 단조 감소, `D_tail`·지급량은 Q에 단조 증가). 꼬리는 회사 귀속, 팀은 완료 즉시 해방. 자율 태그 시 꼬리에도 `α_auto`(§8.7). 회사 소멸 시 잔여 꼬리 소멸.
- **꼬리 갱신:** 라이브운영부 "자사작 라이브 운영" 완료 시 대상 출시작 꼬리의 잔여 기간 리셋. 대상 선택은 §8.3의 단일 규칙(직접 하달 = 착수 시 플레이어 지정, 자율 = 잔여 기간 최단 출시작 자동 지정). **출시작당 갱신 횟수 유한 상한**(영구 기계 수익 차단 — 신작 유인 유지).

**카탈로그:**
- **영업부 — 퍼블리싱·제휴 계약** (고정·일시·반복): T1 인디 마켓 입점 / T2 광고 제휴(개발 중 현금 보전용) / T3 국내 퍼블리싱 / T4 글로벌 퍼블리싱(명성 가중)
- **개발부 A — 자체 개발** (성과 등급·일시+꼬리·동종 재개발 가능): T1 하이퍼캐주얼 미니게임(꼬리 미미, 튜토리얼) / T2 캐주얼 모바일 / T3 미드코어 모바일 / T4 PC 인디 / T5 멀티플랫폼 대형 타이틀(기간 최장·분산 최대·꼬리 최대)
- **개발부 B — 외주 개발 수탁** (고정·일시·반복, 저위험 현금 흐름용): T1 미니게임 외주 / T2 기능 모듈 외주 / T3 풀 외주 수주
- **라이브운영부 A — 운영 용역** (해금 없음·고정·반복): T1 외부 게임 CS 대행 / T2 QA 테스트 용역 / T3 라이브 운영 대행
- **라이브운영부 B — 자사작 라이브 운영** (해금: **동적 상태 술어** — 활성 꼬리 보유 자사 출시작 존재, 전 꼬리 소진 시 재잠김(§8.3) / 완료 효과: 꼬리 갱신(대상 선택 §8.3) / 일시 보상 소액): T1 밸런스 패치 / T2 시즌 이벤트 / T3 대규모 확장 업데이트(추가 해금: **성과 등급 문턱 부가 완료 이력 술어** — 성과 등급 ≥ 성공작인 자사 출시작 완료 이력, 비가역)

**의사결정:** "긴 개발 동안 무엇으로 급여를 감당할 것인가"(외주·용역·영업 병행), "꼬리를 운영으로 연장할 것인가, 팀을 신작에 돌릴 것인가".

### 12.4 업종 3: 화장품 — 라인 해금·반복 생산 (중급)

R&D 투자(당장은 손해) → 라인 해금 → 반복 생산 회수의 중기 계획 구조. 반복 수익은 안정적이지만 감쇠가 있어 주기적 재투자가 필요하다.

**라인 해금·감쇠:**
- R&D부 "제품 라인 개발"(1회성, `C₀`=연구비, 자금 보상 미미, XP·명성 가중) 완료 → **완료 부가 효과: 해금**으로 생산부의 대응 "라인 생산·판매"가 열린다.
- 라인 생산·판매: 반복, `C₀`=생산 원가, 보상 계수 = **라인 감쇠 `δ(n)`**(누적 완료 횟수에 단조 감소).
- **설계 결정: `δ(n)`은 0이 아닌 하한 `δ_min > 0`으로 수렴한다.** 근거: 구작 라인이 완전히 죽으면 해금 자산이 휘발성이 되어 R&D 투자 심리를 해친다. 신제품 유인은 신규 라인과의 상대 격차로 만든다.
- MVP 라인 **4종**(구조 확정), R&D 체인으로 순차 해금.

**카탈로그:**
- **영업부 — 판로·납품 계약** (고정·일시·반복): T1 로드숍 입점 / T2 온라인몰 기획전 / T3 드럭스토어 납품 / T4 홈쇼핑 론칭 / T5 해외 수출 계약
- **R&D부 A — 제품 라인 개발** (1회성·`C₀`>0·완료 효과 해금·선행 조건 체인): T1 기초 스킨케어 → T2 색조 → T3 기능성 → T4 프리미엄 안티에이징 (각각 생산부 대응 라인 해금, 직전 단계 완료가 선행 조건)
- **R&D부 B — 수탁 연구 용역** (고정·`C₀`=0·반복, R&D부 자체 수입원): T1 성분 분석 / T2 처방 개량 / T3 ODM 처방 개발
- **생산부 A — OEM 수탁 생산** (해금 없음·고정·무감쇠·반복·저마진): T1 소량 샘플 / T2 단일 품목 OEM / T3 대량 OEM / T4 멀티 품목 OEM 총괄
- **생산부 B — 자사 라인 생산·판매** (해금: 대응 R&D 완료·반복·감쇠·`C₀`=원가·고마진): T1 기초 / T2 색조 / T3 기능성 / T4 프리미엄

**의사결정:** "OEM 안정 저마진 vs 자사 라인 고마진(감쇠)" 편성 배분, 감쇠 진행도에 따른 차기 R&D 재투자 타이밍. **R&D 라인 개발과 자사 라인 생산은 `C₀ > 0`이므로 직접 하달 전용**(자율 생산부는 OEM, 자율 R&D부는 수탁 용역 수행 — §9.5).

### 12.5 업종 간 특성 차이 (원칙)

| 축 | 무역 (입문) | 화장품 (중급) | 게임개발 (상급) |
|---|---|---|---|
| 기간 | 최단 | 중간 (R&D만 김) | 최장 |
| 피드백 루프 | 즉각 | 중기 (해금 체인) | 장기 (출시까지 무수입) |
| 수익 분산 | 낮음~중간 (시세) | 낮음 (감쇠 예측 가능) | 최대 (흥행 롤) |
| 선투입 | 소~중 (매입비) | 중 (연구비+원가) | 대 (기간 × 급여) |
| 핵심 판단 | 착수 타이밍 | 재투자 주기 | 현금 흐름 생존 설계 |

- **기대 수익 상한**: 게임개발 > 화장품 > 무역, 분산도 같은 순서 — 위험과 조작 난도를 감수한 만큼만 보상.
- **첫 회사 권장**: 무역(전 카테고리 해금 없음, 실패 비용 소) — 튜토리얼 기본값.
- **자율 주행 적합성**: 고정 계수 카테고리(중개·물류·용역·외주·OEM)는 자율 친화, 판단 프리미엄 콘텐츠(시세 딜, 대형 타이틀 타이밍, R&D 재투자)는 직접 하달 전용/우위 — 개입 가치 보존을 콘텐츠 차원에서 지원.
- **동시 운영 포트폴리오**: 현금 흐름 곡선이 다르다(무역 평탄 / 화장품 계단 / 게임개발 스파이크). 자금 이전이 없는 MVP에서는 심리적 분산 효과에 그친다.

### 12.6 인터페이스

| 방향 | 상대 | 내용 |
|---|---|---|
| 입력 | 프로젝트 | 공통 스키마·티어 체계, **연속 품질 점수 `q_raw`**(성과 등급 매핑용), 완료 이력(해금·감쇠 카운터) |
| 입력 | 경제 | 착수 비용 차감·보상 지급의 집행(본 챕터는 금액·스케줄만 정의) |

### 12.7 MVP / post-MVP

**MVP:** 3업종 × 부서 3종, 카탈로그 전량(§12.2~12.4), 확장 필드 6종 기반 고유 메커닉 최소형(시세: 품목군 3·일자 함수 / 꼬리: 성과 등급 4·흥행 롤·유한 갱신 / 라인: 4종·감쇠 하한), 업종 확장 계약(§12.8 — 규칙 자체는 MVP 확정, 추가 업종 콘텐츠는 post-MVP).
**post-MVP:** 무역 재고 자원(실보유 트레이딩), 게임 IP 자원(속편·리마스터), 화장품 브랜드력(감쇠 상쇄 마케팅), 미래 시세 예고·시장 이벤트, 추가 업종·부서, 업종 간 시너지.

### 12.8 업종 추가 규칙 (확장 계약)

**설계 결정: 업종 추가 = 데이터 팩 추가.** 신규 업종은 시스템(§5~§11)의 규칙 변경 없이 본 챕터 형식의 데이터만으로 성립해야 하며, 성립하지 않으면 그것은 업종이 아니라 시스템 개정 안건이다.

신규 업종 1종이 제공해야 하는 것 (계약 체크리스트):

| # | 항목 | 제약 |
|---|---|---|
| 1 | 부서 종류 3종 | 공통 영업부 포함 권장(학습 전이 원칙 §12.1). 부서별 주/부 직무 스탯 매핑 필수 |
| 2 | 프로젝트 카탈로그 | 공통 스키마(§8.3) + 확장 필드 6종 내에서만 표현. 부서마다 해금 없는 기초 카테고리 ≥ 1(§12.1-4) |
| 3 | 고유 메커닉 정확히 1개 | 확장 필드 6종의 조합으로 표현 가능해야 함. 불가능하면 §8.3 개정이 선행 |
| 4 | 경제 데이터 | `C_seed` / `F_found` / `F_found_G`. 가드레일 §5.8 전 항 충족(특히 1·2·7) |
| 5 | 해석 함수 | 보상 계수 소스·꼬리 스케줄·해금 그래프 등 (§12.6 출력 형식) |
| 6 | 포지셔닝 | §12.5 특성 표에 행 추가(기간/분산/선투입/핵심 판단), 자율 친화 카테고리와 판단 프리미엄(직접 하달 전용) 카테고리의 구분 명시 |

- **완주 비소급**(§11.2): 신규 업종은 기존 완주 판정에 소급 포함되지 않는다. 신규 업종의 그룹 달성은 별도 기록으로 남긴다.
- 슬롯·설립·청산 규칙(§10)은 업종 수와 무관하게 그대로 적용된다(업종 중복이 허용되므로 슬롯 수와 업종 수는 서로를 제약하지 않는다).

## 15. 남은 열린 질문

규칙 구조는 본 문서로 확정이며, 아래는 밸런싱·플레이테스트 단계에서 답해야 할 설계 수준의 질문이다.

1. **`α_auto`의 값 대역** — "자율만으로 생존 가능"(§5.8-2)과 "직접 하달 프리미엄 체감" 사이의 폭. 명성에도 적용되므로 위성 회사의 승급 지연 체감이 과도하지 않은지 플레이테스트 필요.
2. **`C₀` 콘텐츠의 자율 제외에 따른 위성 운영 가치** — 자율 위임된 무역 소싱부·화장품 생산부의 존재감이 지나치게 얇다면 post-MVP 예산 한도(§9.9)의 도입 시점을 앞당길지.
3. **게임개발 흥행 롤의 분산 폭** — "수익 분산 최대" 정체성과 대형 타이틀 실패의 좌절감 사이 경계. 하방(실패작)의 최저 보상 수준 결정 필요.
4. **체불 억제의 수치 검증** — 미지급 이월 + 충성도 체증 하락만으로 "현금 흐름 타이밍 조작형" 전략적 체불이 충분히 손해가 되는지(§5.8-6의 성립 조건).
5. **창립 선발 규모 `N_found`** — 추가 회사에도 동일 제공 시 신설 J커브가 너무 얕아지지 않는지. 첫 회사보다 축소하는 차등안 검토.
6. **컨디션 회복률 차등** — 미배치 풀과 팀 소속 대기의 회복률을 동일하게 둘지, 미배치를 더 빠르게 해 "완전 휴식" 결정을 만들지.
7. **티어 5단계와 등급 5단계의 정렬 검증** — 등급 승급 리듬과 부서 티어 상승 리듬이 실제 플레이 속도에서 1:1로 맞물리는지.
8. **자진 강등의 악용 여지** — 고의로 부실에 진입해 강등 혜택(유지비 절감)을 취하는 경로가 성립하지 않는지(부실 진입의 충성도 비용 > 유지비 절감이어야 함).
9. **상비 의뢰 연명(좀비 회사)의 지루함** — 상비 의뢰만으로 무한 연명하는 고착 상태가 손절(청산) 판단으로 자연 유도되는지. 청산 반환(파산 몰수 대비 양수 회수)이 유도 장치로 충분한지, 별도 신호가 필요한지.
10. **청산 환수율 `γ_cash`·`γ_up`의 대역** — "제때 손절이 아깝지 않을 만큼 크되, 성숙 회사를 주기적으로 수확하는 사이클이 성립하지 않을 만큼 작게"의 폭. 승급비 환수와 잔액 환수의 비중 설계.
11. **골드 싱크의 충분성** — 소비처가 설립비뿐일 때 후반(슬롯 소진·완주 이후)에 골드가 무의미하게 쌓이지 않는지. post-MVP 싱크(다이아·프리미엄 기능) 도입 전 MVP에서의 처리.
12. **슬롯 4~10 해금 페이싱** — 개수 문턱 일반식(중기업 n−1곳)이 후반에 단조롭지 않은지, 상위 슬롯에 등급 문턱 상향(대기업·그룹 요구)이 필요한지.
13. **동일 업종 복수 회사의 전략 검증** — 전역 시세 `μ` 공유로 무역 회사 복제가 시세 차익의 병렬 수확이 되는지(회사별 독립 원장·급여 구조가 충분한 억제인지), 게임개발 다중 보유의 꼬리 스택이 과도하지 않은지.
14. **사이클↔실시간 매핑 `T_cycle`과 오프라인 상한 `DAY_OFFLINE_CAP`** (§2.1) — 1 게임일이 실시간 얼마에 대응하는지, 방치 후 재진입 시 소급 진행 상한을 어디에 둘지. 세션 리듬·완결감(ux), 시간 단축 상품 가치(monetization), 리텐션 페이싱(liveops)이 모두 이 값에 의존하므로 프로토타입 단계에서 조기 확정이 필요하다.
