## 0. 문서의 지위와 범위

### 0.1 지위

본 문서는 게임 "회사 경영 시뮬레이션"의 **화면·정보구조·플로우 단일 정본**이다(README §2.3). 다른 문서는 화면을 **참조만** 하며, 화면·내비게이션·플로우를 정의하거나 변경하는 결정은 본 문서 개정으로만 이루어진다.

본 문서는 **게임 규칙을 만들지 않는다.** 규칙·엔티티·자원·처리 순서의 정본은 `game-design.md`이며, 본 문서의 모든 화면은 그 규칙을 **표현·항해**하기 위한 표면이다. 어떤 화면·플로우도 새 자원·새 처리 단계·새 의사결정을 신설하지 않는다.

### 0.2 의존 전제 (README §1)

- **P1 모바일 우선 · 세로(portrait) · 한 손 조작 · 짧은 세션(1~5분) + 자율 주행 방치 플레이** → IA·레이아웃·세션 구조의 최상위 제약(§1, §2, §6).
- **P3 미드코어 · 밝고 경쾌** → 관리 깊이(드릴다운)와 접근성(요약·예외 표면화)의 균형(§1.2).
- **`game-design.md` 정합** → 화면은 규칙을 반영하되 규칙을 바꾸지 않는다. 특히 코어 루프(§2.6), 일/월 5단계(§2.2·§2.3), 예약 명령(§2.2-1), 예외 기반 보고(§9.6), 주의 배분(§10.7)을 UI로 옮긴다.
- **`narrative-tone.md` 톤 준수** → 모든 UI 텍스트의 화자는 경영 보좌관 **리아**(§9), 카피 길이 예산·금지선(§9.4)을 지킨다.

### 0.3 범위 경계 (다른 문서 소관 — 침범 금지)

| 영역 | 소관 문서 | 본 문서가 다루는 범위 |
|---|---|---|
| 색·그래픽·아이콘 스타일·연출 비주얼 | `art-direction.md` | 레이아웃·구조·상태 위계·플로우까지. 색값·에셋 스타일은 **정의하지 않음** |
| 상품 구성·가격·상점 SKU·라이브 오퍼 | `monetization.md` | 상점 **화면의 존재·진입 경로·비침해 원칙**까지. 상품·가격은 **정의하지 않음** |
| 접근성 상세 기준·현지화 규격 | `accessibility-localization.md` | 터치 타깃·제스처·폰트 스케일의 **대응 지점(훅)**까지. 수치·프로세스는 **정의하지 않음** |
| 수식·상태 전이·엣지 판정값 | `mechanics-spec.md` | 화면이 표시할 **상태의 종류**까지. 판정 산식은 **정의하지 않음** |

### 0.4 표기 규약

- **설계 결정:** — `game-design.md`가 정하지 않은 UX 사항을 본 문서가 확정한 지점. 근거를 한 줄 이상 붙인다. 게임 규칙이 아니라 표현·항해 결정이다.
- 예시 카피는 `KO:`로 표기하며 최종 문자열이 아닌 **톤·배치 견본**이다(확정 카피는 현지화 소관).
- 화면 코드: `S0`~ 로 표기해 플로우에서 참조한다.

## 1. UX 필러와 핵심 난제

### 1.1 핵심 난제 (Central UX Problem)

> **최대 10개 회사 × 부서 3종 × 팀 다수 × 직원 수십 명**의 상태를, 한 손·세로 화면·1~5분 세션에서 **압축해 보여주고, 놓치지 않게 부르고, 세 손가락 안에 항해**시키는 것.

정보량은 회사 수 × 부서 수에 비례해 폭증한다(`game-design.md` §9.1·§11.1). 순진하게 모든 회사·부서·팀을 나열하면 세로 화면에서 스크롤 지옥이 되고, 짧은 세션이 무너진다. **해법의 축은 게임이 이미 정한 두 장치를 UI 척추로 삼는 것이다:**

1. **예외 기반 보고(§9.6)** — 자율 부서의 "정상"은 알리지 않는다. UI도 "정상"을 화면에 채우지 않고, **개입이 필요한 예외만 표면화**한다. 즉 기본 상태는 "조용함"이며, 화면은 예외를 향해 사용자를 끌어당긴다.
2. **주의 배분(§10.7)** — "지금 어느 회사를 직접 챙길 것인가"가 핵심 의사결정이다. UI의 최상위 표면은 **이 결정을 돕는 요약·우선순위**여야 한다.

**설계 결정: UX의 정보 전략은 "밀어내기(push all)"가 아니라 "끌어당기기(pull to exceptions)"다.** 홈은 대시보드의 나열이 아니라 **우선순위 큐**이고, 상세는 요구가 있을 때만 드릴다운으로 연다. 근거: §9.6이 알림을 예외로 한정했으므로, UI가 정상 상태를 전부 렌더링하면 시스템이 없앤 인지 부하를 UI가 되살린다. 화면은 시스템의 예외 원칙을 배신하지 않아야 한다.

### 1.2 UX 필러 (4개)

| # | 필러 | 한 줄 | 시스템 근거 |
|---|---|---|---|
| **UX-1** | **예외가 나를 부른다** (Exception-first) | 정상은 조용하고, 개입이 필요한 것만 표면으로 떠오른다. 첫 화면은 "오늘 할 일" 큐 | §9.6 예외 기반 보고, §5.6 주의 오버레이 |
| **UX-2** | **한 손, 한 결정** (One thumb, one decision, done) | 1~5분 세션이 항상 "완결"된다. 큐 하나를 비우면 세션이 끝나도 손해가 없다 | P1 짧은 세션·방치, §2.6 보조 루프 |
| **UX-3** | **요약은 위, 깊이는 아래** (Summary up, depth down) | 모든 계층은 위에서 요약을 보고, 필요할 때만 드릴다운한다. 회사↔회사 전환은 두 탭 이내 | §3.1 계층 구조, §10.7 위성 점검 |
| **UX-4** | **리아가 옆에 있다** (Guided, never lectured) | 단일 화자 리아가 안내·경고·축하를 전한다. 별도 튜토리얼 없이 마일스톤이 손을 잡는다 | narrative §3.1·§6.1, §11.5 |

- **UX-1 ⟷ UX-2 균형:** 예외가 나를 부르되(UX-1), 부름에 응답하는 각 처리는 세션 안에서 완결된다(UX-2). "부르기만 하고 끝낼 수 없는" 상태(예: 다음 사이클을 강제로 기다려야만 확인되는 결과)는 UI가 "예약됨/내일 반영"으로 명시해 세션을 닫아준다(§7.2).
- **UX-3의 회사 전환 비용:** 멀티 컴퍼니의 인지 다양성(narrative §4.3)은 자산이지만, 전환이 무거우면 순회(§10.7)가 벌이 된다. 회사 스위처를 **상단 상시 노출**해 전환을 1탭으로 유지한다(§2.3).
- **UX-4의 절제:** 리아는 상시 화면을 점유하지 않는다(narrative §4.1). 코멘트는 온보딩·알림·리포트·마일스톤에만 실린다.

### 1.3 필러 → 게임 시스템 정합 매핑

| 게임 원칙 (`game-design.md`) | UX 구현 |
|---|---|
| 예외 기반 보고 3종 알림(§9.6) | 우선순위 큐·회사 태그 딥링크(§5.1) |
| 자율 부서 정상 무보고(§9.6) | 정상 부서는 접힌 요약 1줄, 예외만 펼침(§3 부서 뷰) |
| 주의 배분 횡단 루프(§10.7) | 스위처 "주의 필요도" 정렬 + 그룹 월말 횡단 결산(§5.2) |
| 예약 명령·다음 사이클 반영(§2.2-1) | "예약됨" 상태 + 커밋 전 취소·되돌리기(§7.2) |
| 상비 의뢰 상시 존재(§8.4) | 보드는 절대 완전 공집합이 되지 않음 → 빈 상태 카피 대신 "상비 의뢰" 상시 노출(§7.3) |
| 게임오버 없음·복귀 루프(§5.6·§11.6) | 위기 화면은 처벌이 아니라 복귀 체크리스트(§4.5) |
| 마일스톤=튜토리얼(§11.5) | 별도 튜토리얼 모드 없음, 코치마크 점진 공개(§8) |

## 2. 정보 구조(IA)와 내비게이션 모델

### 2.1 계층 지도 (두 축)

게임의 엔티티 계층(§3.1)은 **두 개의 소유 축**으로 갈린다. IA는 이 이분을 물리적으로 반영한다.

```
[경영자 축 — 계정 전역]                 [회사 축 — 활성 회사 스코프]
 경영자(그룹)                            회사 (활성 1곳)
  ├─ 골드 원장                            ├─ 대시보드(요약·재무 상태·목표)
  ├─ 회사 슬롯 0..10                      ├─ 부서 1..3
  ├─ 마일스톤 M1~M15 / 완주               │    └─ 팀 0..T_max
  ├─ 알림 우선순위 큐(전 회사)            │         ├─ 팀장/팀원(직원)
  └─ 상점 · 설정                          │         └─ 담당 프로젝트
                                          ├─ 미배치 인력 풀
                                          ├─ 의뢰 보드(부서별)
                                          └─ 재무 원장 · 월말 결산
```

- **경영자 축**은 회사를 **가로지르는** 결정(어느 회사를 챙길지, 언제 설립·청산할지, 마일스톤·완주)을 담는다.
- **회사 축**은 하나의 회사 **내부**로 드릴다운하는 운영(채용·편성·하달·훈련·재무)을 담는다.

### 2.2 전역 내비게이션 — 하단 5탭 + 상단 컨텍스트 바

**설계 결정: 하단 탭바 5개 + 상단 컨텍스트 바를 전역 내비게이션으로 둔다. 탭 ①은 경영자(그룹) 스코프, 탭 ②~⑤는 "활성 회사" 스코프다.** 근거: 한 손 조작에서 하단 탭은 엄지 도달 최적 표면이며 5개가 상한이다. 두 축(경영자/회사)을 물리적으로 분리하되, 회사 축 내부는 **단일 활성 컨텍스트**로 통일해 "지금 이 회사"를 항상 명료히 한다. 회사마다 별도 탭바를 두는 대안은 최대 10사에서 내비가 폭증한다.

**하단 탭 (좌→우, 엄지 우세손 가정 시 우측이 주 액션):**

| 탭 | 이름 | 스코프 | 담는 것 |
|---|---|---|---|
| ① | **그룹** (홈) | 경영자 | "오늘 할 일" 큐, 회사 카드 리스트/스위처, 골드·슬롯, 마일스톤/완주 진입, 그룹 월말 횡단 결산 |
| ② | **회사** | 활성 회사 | 회사 대시보드(요약·재무 상태·다음 승급/복귀 체크리스트) |
| ③ | **조직** | 활성 회사 | 부서→팀→직원 드릴다운, 채용, 훈련, 자율 주행 설정 진입 |
| ④ | **사업** | 활성 회사 | 의뢰 보드, 진행 중 프로젝트 현황, 착수·취소 |
| ⑤ | **재무** | 활성 회사 | 자금 원장, 월말 결산 리포트, 미지급/재무 상태 상세 |

**상단 컨텍스트 바 (상시):**

- **좌:** 회사 스위처 칩 — 활성 회사명 + 업종 아이콘 + 등급 배지 + 재무 상태 신호점 + 미처리 알림 배지. 탭하면 스위처 오버레이(§2.3). *(그룹 탭에서는 "그룹 전체"로 표시)*
- **중:** 활성 회사 자금(₩) 요약 *(그룹 탭에서는 골드 잔액)*
- **우:** 알림 벨(배지 수) → 알림 센터(§5.1) · 메뉴(⋯) → 설정·상점·도움말

**설계 결정: 탭 ①(그룹)은 앱 콜드 스타트의 첫 착지 화면이다.** 근거: 첫 화면은 "지금 어디를 챙길지"를 답해야 하며(UX-1·§10.7), 그것은 회사 축이 아니라 경영자 축의 질문이다. 단일 회사만 보유한 창업기에는 그룹 탭이 사실상 그 회사의 관문으로 축약되어 부담이 없다(§8 점진 공개).

### 2.3 회사 전환기 (스위처 — 최대 10사)

상단 좌측 칩을 탭하면 **스위처 오버레이**(바텀시트 또는 전체 오버레이)가 열린다. 멀티 컴퍼니의 "어느 회사를 챙길지" 결정의 **1차 표면**이다.

**회사 카드(1장) 요소:**
- 회사명 · 업종 아이콘 · 등급 배지(스타트업~그룹)
- **재무 상태 신호** — 건전 / 주의(오버레이) / 부실 / 파산 임박 (아이콘+텍스트+위치, 색 단독 금지 — §7.1)
- **미처리 예외 배지 수** (이 회사가 발신한 큐 항목 수)
- 자금 요약 · 이번 달 순이익 추세(↑/→/↓)
- 자율/직접 운영 비율(예: 부서 3 중 2 자율) — "얼마나 맡겨 두었나"의 한눈 지표

**설계 결정: 스위처 기본 정렬은 "주의 필요도(exception priority)" 내림차순이다.** 개입이 필요한 회사가 위로 떠오른다. 근거: §10.7 위성 점검은 "이상 신호만 확인"이므로, 정렬 자체가 순회 순서를 제안해야 한다. 보조 정렬(등급순·설립순·업종순)은 토글로 제공하되 기본은 예외 우선. 이름 고정 순서를 원하는 후반 플레이어를 위해 "고정 순서" 옵션을 남긴다.

- **빈 슬롯:** 카드 리스트 끝에 "＋ 새 회사" 어포던스(해금된 빈 슬롯이 있을 때). 탭 → 설립 플로우(§4.4).
- **잠긴 슬롯:** 흐리게 표시 + 해금 조건 힌트(예: "중기업 1곳 더 필요"). 골드 구매 해금 없음(§10.3) — 조건은 역량 검증임을 카피로 지지.
- 카드 탭 → 해당 회사를 활성으로 설정하고 회사 대시보드(탭 ②)로 이동. 활성 전환은 즉시(읽기 컨텍스트 스왑, 규칙 처리 아님).

### 2.4 계층 드릴다운 항해 규칙

회사 축 내부(조직 탭)의 드릴다운은 **스택 푸시 내비게이션**이다: 회사 → 부서 → 팀 → 직원/프로젝트.

- 각 레벨 상단에 **브레드크럼**(예: `한길상사 › 소싱부 › 2팀`)을 두어 현 위치와 상위 복귀를 명시.
- **뒤로가기:** 상단 좌 back + OS/제스처 back(안드로이드) 모두 스택 pop. 홈(그룹)까지 pop되면 앱 종료 확인 없이 그룹 탭 유지.
- **교차 계층 점프:** 직원 상세 → 소속 팀, 프로젝트 → 수행 팀 등은 인라인 링크로 이동(드릴다운 재수행 불필요).
- **예외 딥링크(핵심):** 알림/큐 항목은 **드릴다운을 건너뛰고 해당 노드로 직접 진입**한다. 예 — "팀장 부재" 알림 → 그 팀의 편성 화면으로 직행(회사 활성 전환 포함). 이것이 UX-1의 실행 경로이며, 순회 시간을 압축한다.

**설계 결정: 예외 딥링크는 항상 "행동 화면"으로 착지한다(정보 화면이 아니라).** 근거: 예외 알림은 기대 개입이 1:1로 정의돼 있다(§9.6). 딥링크가 대시보드가 아니라 곧바로 조치 가능한 화면(편성/보드/설정)에 도착해야 "한 결정, 완결"(UX-2)이 성립한다.

### 2.5 두 축을 잇는 규칙

- 회사 축 어디에 있든, 상단 스위처로 **다른 회사로 옆걸음(lateral)** 이동 가능 — 현재 탭 위치를 유지한 채 회사만 교체(예: A사 조직→편성 상태에서 B사로 스위치하면 B사 조직→편성으로). 근거: 순회 시 "같은 관점으로 여러 회사 훑기"가 잦다.
- 경영자 축(그룹 탭)에서 회사 카드/큐 항목을 탭하면 회사 축으로 **하강(dive)**.
- 회사 축에서 그룹 탭을 탭하면 경영자 축으로 **상승(surface)**.


- **설계 결정: FTUE는 "게이트형 코치마크 + 점진 공개"다.** M1~M6 동안 아직 무의미한 표면(회사 스위처의 다중 회사·자율 설정·상점 강조)은 흐리거나 숨긴다. 근거: §11.4에서 기본 도구는 전부 개방이나, 한 번에 하나씩 배우게 하려면 시각적 노출은 점진적이어야 한다. 규칙을 잠그는 것이 아니라 시선을 좁힌다.
- **설계 결정: 온보딩은 스킵 가능하되, 스킵해도 마일스톤 체인은 그대로 흐른다.** 근거: 마일스톤이 곧 튜토리얼이므로(§11.5) 별도 스킵 상태를 만들 필요가 없다 — 리아 코멘트만 접히고 M1~M6은 정상 조건으로 자동 달성된다.

### 4.2 코어 루프 1사이클 (채용→배치→하달→완료→급여)

```
[S5 채용] 지원자 카드 비교(등급·스탯·계약금 공개) → 확정
   ⟳ 계약금 즉시 지출(1단계), 신규 직원 미배치 풀 편입   [자금 부족/총원 상한 → 거부 토스트 §7.3]
→ [S4 편성] 미배치 풀 드로어에서 팀에 배치, 필요 시 팀장 임명
   ⟳ 배치 반영(1단계). 팀 역량·k 상한 즉시 재계산 표시
→ [S6 보드] 게시물 선택 → 수행 팀 지정 → 착수(직접 하달)
   ⟳ C₀>0이면 선불 차감. 착수 태그=직접
→ [S7 진행 현황] 진행바·경과일/마감 추적 (자동 사이클 진행)
   일 처리 3단계: 일일 진척 누적, 컨디션 소모 반영(컨디션 낮으면 경고)
→ 완료 판정(4단계) → 수익 토스트(자금·XP·명성). 게임개발 자체 개발이면 [S17 흥행 롤]
→ [월말] [S11 결산] 급여·유지비 지급 → 순이익·재무 상태 갱신
   💬 리아 한 줄 소감(좋은 달/빠듯한 달, narrative §6.5)
→ 강화(훈련/레벨업 확인) → 여유 시 확장(승급 예약/설립) → 루프 회귀
```

- 모든 조직·지출 명령은 **예약**되며 UI는 "예약됨 · 내일 반영" 배지로 표시, 커밋 전 취소 가능(§7.2).
- 완료·레벨업·컨디션 변화는 사이클 진행 시 **토스트/뱃지**로 가볍게 피드백(세션을 끊지 않음).

### 4.3 자율 주행 설정·전환

```
[전제] M7(소기업 승급) 이전에는 [S10] 진입 시 자율 토글이 잠금 + 해금 조건 힌트.
  💬 (해금 순간, 대연출) "이제 부서에 재량을 맡길 수 있어요. 믿고 맡기는 법을 배울 시간이죠."

[S2 회사 대시보드/부서 뷰] → [S10 자율 주행 설정]
 → 부서별 토글: 수동 ⇄ 자율 (전환 즉시 ⟳ 1단계, 비용·쿨다운 없음)
    · 진행 중 건은 기존 태그로 계속(전환 무영향) — UI로 명시
 → 정책 설정(자율 부서):
    P1 위험 성향: 안정 / 균형 / 도전  (툴팁: 마감 여유를 얼마나 둘지)
    P2 우선 목표: 수익 / 성장(XP) / 명성  (툴팁: 어떤 일감을 우선할지)
    P3 컨디션 보호선: 혹사 / 표준 / 보호  (툴팁: 지치면 쉬게 할지)
 → 회사 기본 정책 1세트(신규 부서 상속) 편집
 → [회사 일괄 토글] 매크로: 소속 전 부서 한 번에 자율/수동
 → 하단: "이 부서 월간 요약 보기" → 착수/완료/실패·획득·페널티 소실분·가동률(§5.3)
```

- **톤:** 자율은 "AI 로봇"이 아니라 "믿고 맡긴 유능한 팀"(narrative §2.2, §토운 헌장 6). 라벨·툴팁은 신뢰·위임의 언어로.
- **설계 결정: 자율/직접은 "부서 배지"로 모든 상위 화면(부서 뷰·회사 대시보드·스위처 카드)에 상시 노출한다.** 근거: 주의 배분(§10.7)은 "무엇을 맡겼는지"의 지속 인지를 요구한다. 배지가 없으면 위임 상태가 보이지 않아 포커스 결정이 흐려진다.
- **직접 하달은 자율 부서에도 항상 가능**(§9.2) — 보드에서 개별 착수 시 페널티 없는 직접 태그. UI는 "이 건만 직접 챙기기"로 표현(모드 전환과 구분).

### 4.4 신규 회사 설립 & 청산

**설립:**
```
[S1 스위처] 빈 슬롯 "＋ 새 회사"  (또는 [S13] 확장 판단에서)
→ [S14] 업종 선택(중복 허용) → 회사명(추천 생성기) → 부서 1개 선택
→ 지불 수단 택일:
    (a) 스폰서 자금: 보유 회사 1곳 지정, 자금 ≥ F_found(업종)  [스폰서 여력 경고 표시]
    (b) 골드: 경영자 골드 ≥ F_found_G(업종)
    · 첫 회사·보유 0 재설립이면 설립비 면제 배너
→ 창립 선발(창립 풀, 계약금 면제, 리더십 보유자 1인 보장)
→ 설립 확정  ⟳ 1단계: 설립비 소멸(싱크), 시드 C_seed 시스템 지급, 신규 회사 '건전' 생성
→ 새 회사 대시보드 착지 (신생 회사 J커브 → 초기 강제 포커스 안내)
   💬 (M10 등) "두 번째 회사를 세울 자격이 생겼어요. 여럿을 거느리는 사람으로."
```

- **설계 결정: 지불 수단 선택 화면은 두 트레이드오프를 나란히 보여준다** — 스폰서 자금(선택 회사의 급여·유지비 여력 훼손 경고)과 골드(과거 청산 회수분의 재투자). 근거: §10.4가 둘을 대등한 전략 선택으로 정의했으므로 UI가 한쪽으로 유도하지 않는다.

**청산:**
```
[S2 회사 대시보드/S13 횡단 결산] → "회사 정리(청산)"
→ [S15 청산 확인] 반환 골드 G_liq 미리보기 + 산정 내역 투명 표시:
    잔액 − 미지급/미납 − 시드 C_seed  → ×γ_cash
    + Σ승급비 × γ_up
    소멸 목록 경고: 직원 전원 · 활성 꼬리 · 명성 · 잔여 자금(환산 제외분)
→ 강한 확인(되돌릴 수 없음, 텍스트 확인 또는 홀드 제스처)
   💬 담담하게: "다 키운 회사를 정리하고, 자본을 다음 판에 다시 쓰는 거예요."  ← 비극 아님(narrative §2.2)
→ ⟳ 1단계: 정리 절차 → 슬롯 반환(빈 슬롯), 골드 지급. 해금·마일스톤·골드 보존
```

- **설계 결정: 청산은 항상 "골드 미리보기 → 강한 확인"의 2스텝이며, 파산 임박 회사에서는 "지금 청산하면 골드라도 남습니다"를 담담히 안내한다.** 근거: §10.5는 파산 전 청산을 의도된 손절로 정의했다(파산=반환 0). UI가 이 타이밍 판단을 지지하되 공포·죄책감을 얹지 않는다(narrative §8-3).

### 4.5 위기·부실 대응 (복귀 체크리스트)

```
[트리거] 재무 상태 '부실' 전이(월말) 또는 '주의' 오버레이(매일 예측)
→ 표면화: 스위처 카드 신호점, 회사 대시보드 상단 배너, 알림 큐(위기 티어)
   💬 담담·격려: "미지급이 생겼어요. 조급해하지 마세요 — 길은 있어요."

[S16 복귀 체크리스트]
 · 해제 조건 진행: "미지급 잔액 0 → 전액 지급 월말이면 건전 복귀"
 · 복귀 4수단(§11.6) 각각 진입 CTA:
   ① 상비 의뢰 돌리기 → [S6 보드] 상비 의뢰(게이트 면제·C₀=0) 착수  ← 수입의 바닥
   ② 자진 강등(부실 한정) → 유지비·상한 축소, 명성 보존 안내 → ⟳ 월말 4단계 적용  ← 지출의 바닥
   ③ 인건비 축소 → [S8] 고급여 직원 해고(무비용·즉시, 강한 확인)  ← 즉시 현금 흐름 개선
   ④ 최후 수단 → [S15 청산] 후 재설립  ← 재시작 아닌 복귀
```

- **설계 결정: 위기 화면의 위계는 "경고 배지 → 복귀 체크리스트 → 개별 수단"이며, 어떤 단계에도 카운트다운·긴급 과장·"지금 안 하면 큰일" 카피를 두지 않는다.** 근거: narrative §8-1·2 죄책감/FOMO 금지, §5.6 게임오버 없음. 위기는 처벌이 아니라 안내된 회복이다.
- 자진 강등 버튼은 **부실 상태에서만** 활성(§7.1). 평시에는 비노출.

### 4.6 흥행 롤 결과 확인 (게임개발 성과 등급)

```
[개발부 자체 개발 완료(4단계)] → [S17 흥행 롤 결과]
 · 리빌 시퀀스: 품질 점수(0~1) 표시 → 성과 등급 4단계 확정 애니메이션
   (실패작 / 평작 / 성공작 / 히트작 — 게임 내 유일 대형 RNG, §12.3)
 · 히트작 = 최대 축하 연출  💬 "히트작입니다!! 이거... 대박이에요. 꼬리 수익이 한동안 들어옵니다."
 · 실패작 = 비난 없이  💬 "이번 작품은 조용히 묻혔어요. 배운 게 있으니, 다음에 살리죠."
 · 결과 카드: 일시 보상 + 꼬리 스케줄(D_tail 일간 일 지급, 단조 감소) 시각화
→ 이탈 경로: 꼬리 트래커([S7]) / 신작 착수([S6]) — "운영으로 연장할까, 신작에 돌릴까"
```

- **설계 결정: 리빌은 "노력의 결실 공개"이지 슬롯머신형 도박 연출이 아니다.** 품질 점수(플레이어가 만든 값)를 먼저 보여주고 → 롤 결과를 얹는 순서로, 결과가 실력에 근거함을 시각적으로 전한다. 근거: narrative §8-6 조작적 연출 금지 + §3.1 유능감이 지배 감정. RNG는 분산의 원천일 뿐 도박 심리를 겨냥하지 않는다.
- 모션 민감 사용자를 위해 리빌 연출은 **모션 감소 설정**을 존중(즉시 결과 표시, §10).

## 5. 멀티 컴퍼니 & 예외 기반 UX

### 5.1 알림 · 배지 · 우선순위 큐

**설계 결정: 알림은 3단 우선순위 큐로 통합한다 — 위기 > 개입 요청 > 정보.** 근거: §9.6은 즉시 알림을 예외로 한정했고, §5.6·§11.6은 재무 위기를 별도 축으로 둔다. 이 둘을 하나의 정렬된 큐로 합쳐 "무엇부터 볼지"를 결정론적으로 제시한다.

| 티어 | 항목(예) | 출처 | 시각 강도 |
|---|---|---|---|
| **위기** | 미지급 발생·부실 전이·파산 임박, 마지막 회사 위기 | 경제 §5.6 | 최강조(회사 태그+아이콘+텍스트) |
| **개입 요청** | 자율 프로젝트 실패, 팀장 부재(자동 승계 실패 포함), 이탈 위험 | 자율 §9.6 / 직원 §6.9 | 강조 |
| **정보** | 장기 저가동, 승급 가능, 마일스톤 달성, 월말 결산 대기 | 자율/회사/진행 | 보통(물지 않음) |

**큐 항목 1개 구조:** `[회사 태그] · 상황(리아, ≤40자) · 기대 개입 CTA(딥링크)`. 예 — `[새벽별] 자율 프로젝트가 실패했어요. → 위험 성향 낮추기`.

**배지 표면(다중 고도):**
- 그룹 홈 "오늘 할 일" 카운트 · 상단 벨 카운트
- 스위처 회사 카드의 예외 배지(회사별 미처리 수)
- 하단 탭 배지(해당 회사 축 탭에 예외가 있을 때)
- 조직 드릴다운 노드 배지(부서/팀 단위)

**설계 결정: 알림은 "물지 않는다" — 자율 정상 진행은 무보고, 중복 알림 금지, FOMO/카운트다운 없음.** 근거: §9.6(정상 무보고·중복 금지) + narrative §6.4/§8. 푸시 알림도 위기·개입 티어만 옵트인 대상으로 하고, 방치를 벌하는 문구는 금지.

### 5.2 요약·경고 표면화 (어느 회사·부서를 챙길지)

주의 배분(§10.7)을 세 고도에서 지원한다:

1. **그룹 고도 (S0/S1):** 스위처 "주의 필요도" 정렬 + 회사 카드 요약(재무 신호·예외 배지·자율비율·순이익 추세). "위성 점검"을 스크롤 한 번으로.
2. **회사 고도 (S2):** 회사 대시보드 배너가 이 회사의 **단일 최우선 신호**(부실/승급 가능/저가동 등)를 한 줄로. 부서 요약 3줄(정상=접힘, 예외=펼침·강조).
3. **부서 고도 (S3):** 정상 부서는 접힌 1줄(역량·자율 배지), 예외 부서(표류·저가동·자율 실패)만 펼쳐 강조.

**설계 결정: "정상은 접히고 예외는 펼쳐진다"를 전 계층 공통 렌더링 규칙으로 한다.** 근거: 예외 기반 보고(§9.6)를 정보 밀도 규칙으로 승격 — 화면 공간이 예외에 비례 배분되어, 최대 10사에서도 세로 화면이 "챙길 것"으로만 채워진다.

### 5.3 자율 부서 월간 요약

월말 결산 리포트(S11) 내 **자율 부서 섹션**과 자율 설정(S10) 하단에서 조회. 표시 항목(§9.6 월간 요약):
- 착수/완료/실패 건수, 획득 자금·XP·명성, 팀별 가동률, 월말 평균 컨디션
- **페널티 소실분** — 자금·명성의 `α_auto` 미적용 가정치와의 차액. UI 라벨: "직접 챙겼다면 +N" → **"이 부서를 직접 챙길 가치"의 판단 근거**.

**설계 결정: 페널티 소실분은 "손실"이 아니라 "직접 챙김의 잠재 가치"로 프레이밍한다.** 근거: narrative §6.5는 이를 리아가 "다음 달엔 여기 좀 볼까요?"로 가볍게 짚는 판단 근거로 규정. 위임의 대가를 보여주되 위임을 후회하게 만들지 않는다.

## 6. 세션 구조

### 6.1 앱 진입 첫 화면 · "오늘 할 일"

**설계 결정: 콜드 스타트 착지 = 그룹 홈(S0)의 "오늘 할 일" 큐.** 근거: 짧은 세션의 첫 질문은 "지금 뭘 하면 되지?"이며, 예외 우선 큐가 그 답을 즉시 준다(UX-1·UX-2). 큐가 비어 있으면(모두 정상) "오늘은 조용하네요" 상태로 방치 플레이를 존중.

"오늘 할 일" 구성: 위기·개입 큐 상위 N개 + 승급 가능 + 월말 결산 대기 + (있으면) 마일스톤 달성 축하. 각 항목은 딥링크 CTA.

### 6.2 짧은 세션 완결성

- **한 결정 = 한 완결:** 큐 항목 하나를 처리하면 목록에서 사라지고 세션이 자연 종료 가능. 여러 개를 이어 처리해도, 하나만 하고 나가도 손해 없음.
- **예약 모델과 완결:** 명령은 예약(다음 사이클 반영)이므로, 세션 중 "즉시 결과"를 기다릴 필요 없이 예약하고 나갈 수 있다. UI는 "예약됨 · 내일 반영"으로 세션을 닫아준다.
- **깊은 작업 저장:** 편성·설립 등 다단계 작업은 중간 이탈 시 초안 보존(다음 진입에 이어서).

### 6.3 재진입 / 복귀 처리 (귀환)

```
[재진입] → 오프라인 경과 시뮬레이션(백그라운드) 
→ [오프라인 요약 시트]: 경과 일수, 그동안의 완료·수익·자율 부서 성과, 새로 쌓인 예외 큐
   💬 나무라지 않음(narrative §8-1): "오셨네요. 자, 어디부터 볼까요?"
→ 닫으면 [S0 오늘 할 일]로. 위기 발생 시 위기 티어가 큐 최상단
```

**설계 결정: 복귀는 "요약 후 큐"의 2스텝이며, 오프라인 동안의 손실(예: 자율 실패)은 사실로 담담히 전하되 플레이어를 탓하지 않는다.** 근거: 방치는 설계된 플레이(§9·P1), narrative §8-1 죄책감 금지. 요약 시트는 "무슨 일이 있었나"를 압축하고, 큐는 "이제 뭘 할까"로 연결한다.

### 6.4 사이클 진행 조작

**설계 결정: 시간은 실시간 매핑 자동 진행이다. 1 게임일 = 고정 실시간 길이(값은 `balance.md`/`liveops-analytics.md` 소관), 오프라인 경과는 재진입 시 시뮬레이션·요약된다. 플레이어 명령은 예약 명령으로 다음 사이클 일 처리 1단계에 반영된다.** 근거: P1 방치 플레이 + §2.1 사이클 기반("사이클 사이 개입") + §2.2-1(1단계=지시 반영)의 자연스러운 결합. 수동으로 매일 버튼을 눌러 진행시키는 모델은 짧은 세션·방치 전제와 충돌한다.

- **전역 배속(선택):** 능동 플레이어를 위해 전역 "빨리 감기"를 제공하되, **회사별 개별 배속·일시정지는 없다**(§2.1 전 회사 동시 진행 원칙). 배속은 전역에만 적용.
- **사이클 경계 가시성:** 상단 또는 대시보드에 "다음 정산까지 D-일" 표시. 월말은 결산 이벤트로 명확히 구획.
- **설계 결정: 결과가 다음 사이클에 확정되는 조작(하달 결과·승급·설립·청산)은 항상 "예약됨" 상태를 거친다.** 근거: §2.2가 모든 지시를 1단계에 일괄 반영하므로, UI가 즉시 완료로 속이면 규칙과 어긋난다. 예약 표시는 되돌리기(§7.2)의 기반이기도 하다.

## 7. 상태 가시성 · 피드백

### 7.1 위험 신호 표면화 규칙

| 신호 | 원천 | 표면화 위치 | 규칙 |
|---|---|---|---|
| 재무 상태(건전/주의/부실/파산 임박) | §5.6 | 스위처 카드·대시보드 배너·큐 | **색 단독 금지** — 아이콘+텍스트+위치 병용 |
| 이탈 위험(충성도<임계) | §6.9 | 직원 상세·팀 편성·큐(개입) | 직원 카드 배지 + 명부 정렬 상위 |
| 컨디션 저하 | §6.6 | 팀 편성·진행 현황 | 팀 평균 + 개인, 과로 경고 |
| 팀장 부재/표류 | §7.3 | 부서 뷰·팀·큐(개입) | 팀 카드 "표류" 라벨 + 진척 0 표시 |
| 장기 저가동 | §9.6 | 부서 뷰·큐(정보) | 연속 저가동 일수 표시 |
| 미지급 예측(주의) | §5.6 | 대시보드·재무·큐 | "다음 달 빠듯" 담담한 경고 |

**설계 결정: 모든 위험 신호는 "색 + 아이콘 + 텍스트 + 배치"의 4중 부호로 전달하며, 색은 보조 채널이다.** 근거: 색값은 `art-direction.md` 소관이고 색맹·명도 대비·현지화를 고려하면 색 단독 신호는 접근성 위반이다(§10, accessibility 소관). 이는 아트·접근성이 준수해야 할 UX 계약이다.

### 7.2 확인 / 취소 / 되돌리기 (예약 명령)

- **자연 되돌리기 = 예약 커밋 전 취소:** 명령은 다음 사이클 1단계에 반영되므로, 현재 사이클 내에는 "예약됨" 항목을 취소·수정할 수 있다. UI: 명령 후 "예약됨 · 취소" 스낵바 + 예약 목록.
- **강한 확인(2스텝):** 되돌릴 수 없거나 무거운 결과 — 해고, 청산, 파산 임박 회사의 승급, 대량 재배치. 텍스트 확인 또는 홀드 제스처.
- **프로젝트 취소:** 언제든 예약 가능(자율 건 포함), 다음 사이클 확정(§8.9). UI가 `C₀` 비환불·축소 XP를 사전 고지.
- **승급 예약:** "승급 가능" 표시 → 예약 → 다음 사이클 원자 처리(재검증·차감·상한 갱신). 실패(잔액 경합) 시 "승급 보류" 사유 안내(§7.3).

**설계 결정: 게임에 범용 "undo 버튼"은 없다 — 되돌리기는 예약 커밋 전 취소로 표현된다.** 근거: 규칙상 명령은 원자적으로 1단계에 반영·확정되며(§2.2), 반영 후 임의 롤백은 자원 정합을 깬다. UI는 "반영 전"이라는 안전 구간을 명시적으로 제공해 실수를 흡수한다.

### 7.3 빈 / 에러 / 로딩 / 엣지 상태

| 상태 | 상황 | UX |
|---|---|---|
| **빈: 미배치 풀** | 배치할 직원 없음 | "지원자를 모셔올까요?" → 채용 CTA |
| **빈: 지원자 풀** | 이달 채용 소진 | "다음 달 새 지원자가 옵니다"(월 갱신 안내) |
| **보드(사실상 안 비는 상태)** | 게시물 만료 | **상비 의뢰 상시 노출**(§8.4) → "보드가 텅 비는 일은 없어요" |
| **빈: 부서 없음(신생)** | 첫 부서만 개설 | 개설 CTA + `D_max` 안내 |
| **에러: 명령 거부** | 자금 부족·총원 상한·불변식 위반 | 리아가 **사유 명시** 토스트: "자금이 모자라요(계약금 ₩N 필요)" — 무엇을·왜 |
| **로딩: 오프라인 catch-up** | 재진입 시뮬 | 진행 표시 + 요약 시트(§6.3) |
| **엣지: 보유 회사 0** | 전 회사 파산/청산 | 재기 화면 → 무료 재설립 유도(§10.4), 게임오버 아님 |
| **엣지: 잠긴 슬롯** | 해금 전 | 조건 힌트, 골드 구매 없음 명시 |
| **엣지: 파산** | 몰수 소멸 | 담담한 통지 + 재기 경로(반환 0 사실 전달, 비난 없음) |

**설계 결정: 명령 거부는 절대 침묵하지 않고 항상 "무엇이·왜·다음 수"를 리아 보이스로 반환한다.** 근거: 선불·불변식 규칙(§5.4·§7.5)상 명령은 조용히 거부될 수 있는데, 이유 없는 실패는 미드코어 사용자에게 가장 큰 이탈 요인이다. 거부 사유가 곧 학습이다.

## 8. 온보딩 · 튜토리얼 UX (FTUE 원칙)

**설계 결정: 별도 튜토리얼 모드를 두지 않는다. 마일스톤 M1~M6이 튜토리얼이며(§11.5), 실제 게임 표면 위에서 리아의 코치마크로 진행한다.** 근거: 시스템 중심 게임에서 격리된 튜토리얼은 실플레이로의 전이가 약하다. 마일스톤은 실제 조건 충족으로 달성되므로, "가르치기"와 "플레이"가 분리되지 않는다.

FTUE 원칙:
1. **한 번에 한 개념(one concept per step):** M1~M6 각 걸음은 정확히 하나의 코어 동사(채용·편성·하달·완료·정산·훈련)를 다룬다(narrative §6.1).
2. **코치마크 + 점진 공개:** 현재 걸음의 표면만 스포트라이트, 아직 무의미한 표면은 흐림/숨김(규칙은 잠그지 않고 시선만 좁힘, §4.1).
3. **작은 축하로 성취 심기:** 각 걸음 끝에 리아의 짧은 축하 → 유능감(narrative §3.1).
4. **개념 재프레이밍:** "등급=잠재력"(M1), "자율=위임"(M7 해금)을 결정적 순간에 심는다(narrative §2.2).
5. **스킵 안전:** 스킵해도 마일스톤 체인은 조건으로 자동 흐름(§4.1). 앞질러 달성해도 막히지 않음(§11.5).
6. **비강제·비처벌:** 온보딩은 시간 압박·실패 처벌이 없다. 첫 월급일 전 현금 압박은 "긴장"이되 "절망"이 아니다(narrative §1.3).

전환점 대연출(코스메틱, 규칙 불가침): M7(자율 해금)·M9(슬롯 2)·M12(쌍두)·M15(완주)은 상한 완화된 축하 연출(narrative §6.2).

## 9. UX 라이팅 원칙

**단일 화자 = 리아(narrative §3.1).** 모든 안내·경고·축하·리포트 소감이 리아의 존댓말·유능·따뜻·가벼운 위트로 통일. 호칭 대표님 → (그룹 보유 시) 회장님(narrative §1.2).

**길이 예산(narrative §7.1 준수, KO 기준):**

| 표면 | 상한 | UI 적용 |
|---|---|---|
| 알림/큐 항목 | ≤40자·1행 | 회사 태그 + 상황 + 행동 힌트 |
| 버튼·라벨·스탯명 | ≤6자 | 아이콘 병기 전제 |
| 프로젝트 플레이버 | ≤24자·1행 | 기능명 별도 표기 |
| 툴팁 | 1~2문장 | 용어·규칙 설명(등급=잠재력 등) |
| 온보딩 스텝 | 1~2문장 | 한 걸음 한 개념 |
| 리포트 소감 | 1문장 | 데이터에 얹는 한 줄 |
| 마일스톤/완주 | 1~2문장/제한 없음 | 전환점·엔딩만 완화 |

**마이크로카피 가이드:**
- **숫자:** 자금 `₩`, 골드 아이콘 병기. 대형 수는 로케일별 축약(만/억 ↔ K/M) — 규격은 accessibility/현지화 소관, 원칙만: **가독 우선·정렬 일관**. 증감은 부호+색+아이콘(색 단독 금지).
- **툴팁:** 처음 등장하는 용어·게이트에 인라인 "?" 툴팁. 특히 잠재력·`α_auto`(페널티)·상비 의뢰·미지급 이월을 재프레이밍(narrative §2.2).
- **금지(P2·narrative §8):** 결제 압박·FOMO·거짓 카운트다운·죄책감 유발·직원 비하 카피 금지. 위기·해고·퇴사·청산 텍스트는 존엄과 회복 경로를 담는다.
- **현지화 여백:** UI 문자열은 KO 기준 +40%까지 레이아웃이 견디도록(§10, narrative §7.1).

**설계 결정: 리아 코멘트는 "조용한 달" 규칙을 둔다 — 정상·반복 상황에서는 코멘트를 생략하거나 변주 풀에서 회전한다.** 근거: 알림·리포트마다 코멘트가 붙으면 반복 피로(narrative 열린 질문 9). 예외 기반 원칙과 정합 — 리아도 "예외적으로" 말할 때 무게가 산다.

## 10. 접근성 훅 (상세는 `accessibility-localization.md` 소관)

레이아웃·플로우가 접근성을 위해 확보하는 **대응 지점**만 표시(수치·프로세스는 접근성 문서가 확정):

- **터치 타깃:** 모든 인터랙티브 요소는 최소 터치 타깃 이상, 엄지 도달 구역(하단·중앙)에 주 액션 배치. 촘촘한 편성·보드 카드는 간격·히트영역 확보.
- **한 손·세로:** 상단 도달 어려운 요소(설정·상점)는 보조 액션으로만, 주 흐름은 하단 탭·바텀시트로.
- **제스처 대체:** 모든 제스처(스와이프 스위처, 홀드 확인)에 **탭 대체 경로** 제공 — 제스처 단독 필수 금지.
- **폰트 스케일 / 다이나믹 타입:** 텍스트 확대 시 레이아웃 리플로우(잘림·겹침 금지), KO 기준 +40% 팽창 흡수(현지화 여백과 공유).
- **색 비의존:** 재무 상태·증감·위험 신호는 색 외 아이콘·텍스트·위치 병용(§7.1) — 아트가 준수할 계약.
- **모션 감소:** 흥행 롤 리빌·승급·완주 축하 연출은 "모션 감소" 설정 시 즉시/저자극 대체(§4.6).
- **알림 절제:** 물지 않는 알림·조용한 달(§9)은 인지 부하·강박 완화의 접근성 측면도 겸한다.

## 11. 열린 질문

화면·플로우 정본으로 확정하되, 프로토타입·플레이테스트 단계에서 답할 UX 미결 사항.

1. **사이클 실시간 매핑 값** — 1 게임일 = 몇 분/시간인지, 배속 배율, 오프라인 catch-up 상한. 짧은 세션(1~5분)에 몇 사이클이 지나야 "완결감"이 나는지 플레이테스트 필요(값은 balance/liveops 소관, UX는 리듬 요구만).
2. **스위처 확장성(10사)** — "주의 필요도" 정렬 카드 리스트가 10장에서도 세로 1스크롤에 훑기는지, 그룹핑(업종/등급)·검색이 필요한지.
3. **"오늘 할 일" 큐 상한·묶음** — 다회사 위기 동시 발생 시 큐 폭증을 어떻게 묶을지(회사별 접기? 티어별 상한?).
4. **예약/취소 UI의 명료성** — "예약됨·내일 반영" 모델이 즉시 반영을 기대하는 사용자에게 혼란스럽지 않은지, 예약 목록의 노출 강도.
5. **부서 뷰 접기/펼치기 자동화** — "정상 접힘·예외 펼침"의 자동 판정을 사용자가 수동 오버라이드하고 싶어 하는지.
6. **온보딩 코치마크 강도** — 미드코어 타깃(P3)에서 코치마크가 과잉 간섭인지 과소인지, 스킵 유도 시점.
7. **월말 결산·횡단 결산의 정보 밀도** — 세로 화면에서 회사별 비교표를 어디까지 압축할지, 페널티 소실분을 얼마나 전면에 둘지.
8. **흥행 롤 리빌 연출 길이** — 대형 순간의 만족과 반복 시 스킵 욕구의 균형(모션 감소 대체와 함께).
9. **상점 진입 표면 위치** — 비침해 원칙(P2) 하에서 상점 아이콘을 그룹 홈/메뉴 중 어디에 둘지(정본은 monetization과 협의).
10. **리아 아바타의 화면 점유** — 코멘트 말풍선의 위치·지속·해제(narrative §4.1 "상시 점유 안 함"과 세로 공간 절약의 접합점).
11. **재무 상태 신호의 시각 어휘** — 색 외 아이콘·형태 체계(art-direction과 공동 정의, 접근성 계약 §7.1·§10).
12. **회사 축 옆걸음(lateral) 전환의 상태 보존** — 다른 회사로 스위치 시 현재 탭·드릴다운 깊이를 어디까지 유지·리셋할지.
