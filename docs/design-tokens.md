## 1. 토큰 계층 체계

색은 3계층 참조로 구성한다. 하위 계층은 상위 계층을 **참조**만 하며 원시 값을 직접 쓰지 않는다. 이로써 리브랜딩·테마 스왑·업종 추가가 원시/시맨틱 한 지점의 변경으로 전파된다.

```
① 원시(Primitive)      "무슨 색인가"         teal.600 = #0F7C77
        │              색 그 자체. 의미 없음. 램프(50~900).
        ▼
② 시맨틱(Semantic)      "무엇을 뜻하는가"     color.state.danger = teal? no → red.600
        │              역할·의미에 원시를 배정. 라이트/다크 쌍. 대비 책임 계층.
        ▼
③ 컴포넌트(Component)   "어디에 쓰는가"       color.button.primary.bg = brand.primary
                       UI 부품이 시맨틱을 소비. 값 미보유(참조만).
```

- **라이트/다크 이중 테마.** 모든 시맨틱·컴포넌트 토큰은 `{ light, dark }` 쌍을 갖는다(`accessibility §2.5`). 두 테마는 **의미 항상성**을 유지하되(같은 뜻=같은 인상) 각 테마에서 대비를 **독립 만족**한다(§9). 원시 램프는 테마 무관 단일 값이며, 테마별 배정은 시맨틱 계층에서 일어난다.
- **대비 책임은 시맨틱 계층.** 원시 색은 대비 대상이 아니고, "이 색을 저 배경 위에 쓴다"는 결정(=시맨틱/컴포넌트)에서 대비가 성립해야 한다. CI 게이트(`accessibility §1.4`)는 시맨틱·컴포넌트 조합을 검사한다.
- **틴트 원칙(`art §3.3`).** 업종 색은 헤더·프레임·배경 액센트만 물들이고 **본문 텍스트·데이터·시맨틱 색은 물들이지 않는다** — 본문은 항상 중립 텍스트 토큰을 쓴다. 따라서 업종 액센트는 "대형/헤딩/아이콘"(≥3:1) 용도이며 본문(≥4.5:1) 채널이 아니다.

## 2. 원시(Primitive) 팔레트 — 램프

의미 없는 순수 색 램프. 시맨틱이 여기서 골라 쓴다. 굵게 표시한 스텝이 v0에서 실제 배정된 스텝이다. (순백 `#FFFFFF`·순흑 `#000000`은 램프에 두되 지면/텍스트로는 직접 쓰지 않는다 — `art §3.1` 눈부심·눌림 방지.)

| HEX | `#FBF9F5` | `#F2EFE9` | `#E9E5DC` | `#D6D0C4` | `#8C8478` | `#636975` | `#4C525E` | `#22262E` | `#1C2028` | `#12151A` |
| 용도 | L 표면 | L 배경 | L 침강 | L 보더-subtle | 보더-strong | L 텍스트3 | L 텍스트2 | L 텍스트1 | D 표면 | D 배경 |

### 9.3 색맹(CVD) 구분 가능성 코멘트
색맹 4프로파일(1형 적색맹·2형 녹색맹·3형 청황·전색맹) 시뮬레이션 검수는 `accessibility §1.4`가 소유하며, 아래는 팔레트 설계 시점의 위험 페어와 완화책이다. **전제: 색은 4채널 중 하나일 뿐이므로(§10) 모든 아래 페어는 형태·라벨·위치로 이미 변별된다 — 색 구분은 "추가 편의".**

| 위험 페어 | CVD 유형 | 색만으로 | 완화(비색 채널) |
|---|---|---|---|
| 재무 주의(앰버) ↔ 부실(오렌지) | 1·2형 | 온도차 뭉개짐 | **부실/파산 전용 보더 패턴**(§6.2) + 라벨 + 배치 위계 |
| 자금(민트그린) ↔ 컨디션(옐로그린) ↔ 성공(그린) | 1·2형 | 근접 | 아이콘 형태(지폐 vs 배터리 vs 체크) + 맥락(자원 카운터 vs 직원 미터) |
| XP(블루시안) ↔ 다이아(틸시안) | 1·2형 | 근접(둘 다 쿨) | 형태(상승 셰브론 vs 크리스탈 컷) + 맥락(직원 vs 상점) + 다이아는 더 채도 높음 |
| 명성(바이올렛) ↔ S등급(바이올렛) | 3형·전색맹 | 유사 | 형태(별+월계 vs S 문자 배지) + 배치(자원 바 vs 카드 모서리) + 등급 문자 상시 노출 |
| 위험 레드 ↔ 파산 레드브라운 | 1·2형 | 유사 적색 | 파산은 채도 낮은 브라운 + 정리 아이콘 + "파산 임박" 라벨 + 큐 최상단 배치 |
| 건전(그린) ↔ 파산(레드브라운) | 전색맹(명도만) | 명도 근접 위험 | 파산 명도를 건전보다 낮게 배치 + 아이콘/라벨/패턴 |

- **적록(1·2형):** 가장 위험한 축. 재무 위계는 보더 패턴이, 자원은 형태·맥락이 색을 대체한다.
- **청황(3형):** 블루/앰버 구분은 유지되나 퍼플 계열(명성/S)이 근접 → 형태·문자로 변별.
- **전색맹(모노):** 명도만 남으므로 텍스트1(14:1대)·명도 계단·아이콘 실루엣이 정보를 전달. 순수 색 정보에 기댄 조합은 §10 4중 부호로 이미 금지.

## 10. 색 비의존 원칙 — 위험 신호 4중 부호

`ux §7.1`·`accessibility §2.1` 계약: **색은 의미를 실어 나르는 유일 채널이 될 수 없다.** 색을 완전히 제거해도 나머지 3채널로 신호가 성립해야 한다. 본 팔레트는 이 원칙의 "①색" 채널만 제공하며, 나머지 3채널은 아트(아이콘·패턴)·UX(라벨·배치)가 소유한다.

| 신호 | ① 색(본 문서) | ② 아이콘/형태·패턴 | ③ 텍스트 라벨 | ④ 배치 |
|---|---|---|---|---|
| 재무 건전 | `finance.healthy` 그린 | 체크/정상 마크 | "건전" | 스위처·대시보드 신호점 |
| 재무 주의 | `finance.caution` 앰버 | 옅은 느낌표 | "주의 · 다음 달 빠듯" | 배너 오버레이 |
| 재무 부실 | `finance.poor` 오렌지 | 경고 마크 **+ 보더 패턴** | "부실" | 대시보드 상단 배너 |
| 재무 파산 | `finance.bankrupt` 레드브라운 | 정리 마크(해골·폭발 금지) **+ 보더 패턴** | "파산 임박" | 큐 최상단 |
| 직원 등급 | `grade.*` | 프레임 재질 | **C/B/A/S 문자 상시** | 카드 모서리 배지 |
| 자율/직접 태그 | 위임/포커스 색 | 위임·포커스 아이콘 | "자율"/"직접" | 부서·프로젝트 배지 |
| 증감(±) | 상승/하강 색 | +/− 부호 + ↑/↓ | 수치 | 잔액 옆 |

- **파괴적 액션 색(`state.danger`)은 위험 신호가 아니라 "신중한 확정" UI 색**이며, 확정은 색이 아니라 2스텝 확인·미리보기(`accessibility §3.4`)로 방어한다.
- **CI 게이트 연동:** 위 조합 중 "색이 유일 채널"인 항목이 발견되면 `accessibility §1.4` 리던던시 리뷰에서 반려. 본 팔레트의 어떤 토큰도 단독 정보 전달을 전제하지 않는다.

## 12. 업종 추가 시 색 확장 규칙 (`game-design.md §12.8` · `art §9.5` 미러)

**설계 결정: 신규 업종 색 추가 = `color.industry.<신규키>` 슬롯 1행 추가 + 무드 팔레트 1행. 시스템·시맨틱·중립·자원·등급 토큰은 전량 재사용(신설 금지).** 근거: `game-design.md §12.8`(업종=데이터 팩)·`art §9.5`(아트 팩) 계약을 색 계층에서 이행 — 성립하지 않으면 그것은 업종이 아니라 토큰 시스템 개정 안건이다.

신규 업종 1종이 제공해야 할 색 슬롯(체크리스트):

| # | 슬롯 | 제약 |
|---|---|---|
| 1 | `industry.<key>.tint` (라이트/다크) | 그 위 본문 텍스트(text.primary) ≥ 4.5:1 — CI 게이트 매트릭스에 자동 편입 |
| 2 | `industry.<key>.accent` (라이트/다크) | 자기 틴트 위 헤딩/아이콘 ≥ 3:1, 표면 위(다크) ≥ 4.5:1 |
| 3 | 무드 온도·채도 | `narrative §4.3` 무드 표 신규 행과 정합(따뜻/차가움/파스텔 등) |
| 4 | hue 충돌 회피 | 브랜드 틸·기존 3업종·시맨틱·자원 색과 **명도+hue로 구별**(색맹 시뮬 포함) |
| 5 | 공통 영업부 | `industry.sales.*` **불변 재사용**(전 업종 동일 색, 학습 전이 — 신규 업종도 예외 없음) |
| 6 | 시맨틱/재무/등급/자원 | **전량 재사용**. 업종 색은 틴트·액센트 2슬롯으로 닫힌다 |

- **완주 비소급 정합**(`game-design.md §11.2·§12.8`): 신규 업종 색은 기존 팔레트 검증을 무효화하지 않으며, 추가 슬롯만 신규 CI 게이트 대상.
- **닫힘 보장:** 업종 확장이 `tint`+`accent` 2슬롯(×2테마)으로 닫히므로, 색 시스템 개정 없이 데이터 팩 확장만으로 신규 업종이 성립한다.

## 열린 질문

프로덕션·플레이테스트·아트 리뷰에서 확정할 미결(값은 v0 확정 후보이되 아래는 캘리브레이션·검증 대상).

1. **무드 채도 캘리브레이션** — 화장품 파스텔(`#F3E7EE`/`#9C4A72`)이 "우아·청결"로 읽히는 채도 상한, 게임개발 인디고(`#3D3A8C`)의 "네온·몽환"을 틴트가 아닌 VFX/글로우에서 어디까지 밀지. 플레이테스트로 업종 무드 변별 확인.
2. **S 등급 광채 vs C 폄하 방지**(`art §11-5` 연동) — `grade.s`(`#7A57A8`) 바이올렛 시머와 `grade.c`(`#8A7A5C`) 브론즈의 명도·채도 간격이 "C가 초라해 보이지 않으면서 S가 특별한" 지점인지. 색 자체보다 프레임 재질이 주 채널이나 색 보조 톤도 검증.
3. **명성(자원) ↔ S등급 퍼플 근접**(§9.3) — `resource.reputation`(`#7A4FB0`)과 `grade.s`(`#7A57A8`)가 거의 동일 hue. 형태·배치·문자로 변별되나, 한 화면 동시 노출(직원 카드) 시 혼동 여부를 색맹 시뮬로 확인 후 필요 시 명성을 더 마젠타로, S를 더 인디고로 분기.
4. **XP ↔ 다이아 시안 근접**(§9.3) — 쿨 계열 두 자원의 색 간격 확대 필요 여부(다이아를 더 밝은 아이스로). 상점·직원 맥락 분리로 충분한지 무음/색맹 테스트.
5. **자원 아이콘 3:1 하한 마진** — 라이트 다이아(3.20)·골드(3.82)·컨디션(3.81)·등급 A(3.53)가 3:1 근처. 아이콘이 소형(16px)에서도 실루엣 변별되는지(`art §7.5`) + 필요 시 미세 다크닝.
6. **리아 시그니처 세부** — 브랜드 틸(`brand.primary`)을 리아 시그니처로 겸용(`art §4.6`)할 때 말풍선·버스트에서 CTA 틸과 구분이 필요한지(동일 상수 유지 vs 리아 전용 톤 분기).
7. **고대비 모드 팔레트**(`accessibility §2.4` 고대비 A1) — 본 v0는 표준 AA. 고대비 토글용 별도 오버라이드 토큰 세트(더 강한 텍스트/보더)를 언제 산출할지.
8. **다크 테마 필 전략** — 재무/시맨틱 필을 다크에서 라이트와 동일 진한 필(백색 라벨) 재사용 중. 다크 네이티브 필(밝은 필+근흑 라벨)로 갈지 무드 리뷰.
9. **CI 대비 게이트 자동화 연동**(`accessibility §1.4`) — 본 문서 §11 JSON을 게이트 입력으로 소비하는 파이프라인 포맷·실패 임계(경고 vs 차단)를 `technical-architecture.md`와 확정.
