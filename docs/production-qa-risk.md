# 회사 경영 시뮬레이션 — 개발 로드맵 · QA/테스트 계획 · 리스크 레지스터 (Production · QA · Risk) v1.0

> 본 문서는 문서 세트의 **마지막 통합 문서**다. 앞선 12개 문서의 MVP 스코프·열린 질문·개정 태그·게이트를 종합해 **실제 프로덕션 플래닝·QA 착수·리스크 관리**가 가능한 수준으로 정리한다.
> 소유권(README §2.3): **일정·QA·리스크의 정본은 본 문서**다. 다른 문서가 "[요구사항 → §production-qa-risk]"로 넘긴 항목(예: `liveops-analytics.md §11.2` 롤백 절차·SLA)을 본 문서가 받는다.
> 규약: 규칙 자체를 바꾸는 결정은 임의 확정하지 않고 **[game-design 개정 필요]** 안건으로만 제기한다(README §0 범위 경계). 본 문서가 내리는 프로덕션/QA 결정은 "**설계 결정:**"으로 표기하고 근거를 단다.

## 0. 문서의 지위와 의존 전제

### 0.1 지위와 소유권
- **소관(정본):** 개발 단계·마일스톤·일정·크리티컬 패스 / 테스트 전략·플레이테스트·QA 프로세스·릴리스 체크리스트 / 통합 리스크 레지스터 / 런치 준비도(DoR/DoD) / 라이브 헬스 임계 초과 시 롤백 절차·책임자·SLA(`liveops-analytics.md §11.2`가 위임).
- **비소관(참조만):** 게임 규칙(`game-design.md`) / 수치(`balance.md`) / 구현 스펙(`mechanics-spec.md`) / 표현(`art`·`audio`·`ux`) / 사업(`monetization`·`marketing`) / 운영 지표·CI 훅 정의(`technical`·`liveops`). 본 문서는 이들의 **게이트를 일정·QA에 배치**할 뿐 내용을 재정의하지 않는다.

### 0.2 의존 전제 (README §1)
- **P1** 모바일 우선(iOS/Android), 세로·짧은 세션+방치. 크로스플랫폼은 아키텍처만 열어둠(`technical §12`).
- **P2** F2P + IAP, 비-P2W. 결제는 시간 단축·편의·확장·코스메틱 한정.
- **P3** 미드코어·밝은 스타일라이즈드.
- **P4** 1차 출시 ko/en, 확장 ja→zh-Hans(`accessibility §12`).
- **P5** **소규모 팀(인디~부티크) 전제.** MVP → 소프트런치 → 글로벌 런치 → 라이브 파이프라인. **본 절이 P5의 실제 조직·일정·QA 규율을 정의한다.**

### 0.3 정합성 계약 (본 문서가 지키는 것)
1. 로드맵의 각 게이트는 앞선 문서가 정의한 게이트를 **인용**한다(임의 신설 금지). 새 게이트는 "설계 결정"으로 표기.
2. **결정론이 최우선 아키텍처 불변식**(`mechanics-spec §1`, `technical §11`)이므로 로드맵·CI·리스크 모두 이를 최상위 제약으로 둔다.
3. 규칙 개정이 필요하면 §A5로 수집하고 game-design 개정 선행을 명시한다.

# Part A — 개발 로드맵 / 프로덕션

## A1. 프로덕션 원칙 · 팀 구성

### A1.1 프로덕션 5원칙 (P5 소규모 팀 지속가능성)
1. **결정론 코어 우선(determinism-first).** 엔진·표현·사업 계층 이전에 엔진 비의존 순수 시뮬 코어(`technical §0.2` L1)를 세운다. 코어가 헤드리스로 값싸게 테스트되고(`technical §11`), 표현·플랫폼 결정을 뒤로 미룰 수 있어(`technical §14-9`) P5의 병목을 줄인다.
2. **데이터/코드 분리 = 민첩성의 전제**(`technical §7.1`, `liveops §6.1`). 업종·밸런스·이벤트·오퍼를 스토어 재심사 없이 조정. **업종 추가 = 데이터 팩 추가**(`GD §12.8`, `art §9.5`, `audio §8.4`).
3. **예외 기반 운영(management by exception).** 라이브 단계에서 "정상"은 대시보드로 조회, 개입은 경보(`liveops §4.4`) 발생 시에만(`liveops §6.1`). 상시 대기 부담을 구조적으로 낮춤.
4. **스코프 규율 = 컷 우선순위 사전 합의**(§A4.3). MVP는 `GD §13` 범위로 동결하고, 지연 시 정해진 우선순위로만 컷.
5. **게이트로 스케일한다.** 소프트런치 리텐션·페이백 게이트(`marketing §4.5·§5.2`) 통과 전 글로벌 대규모 지출 금지. 게이트를 마케팅 압박으로 앞당기지 않음(`marketing §5.2` 설계 결정).

### A1.2 역할 구성 (부티크 코어 팀 기준선)
**설계 결정: 코어 6~9인 + 외주 리소스 풀로 구성한다.** 근거: `GD §13` MVP 스코프(3업종×3부서 카탈로그 전량, 7시스템, 22화면, ~11 음악 스템·55~75 SFX·~120~160 캐릭터 파츠)와 `liveops §6.2` 운영 케이던스를 P5가 지속가능하게 소화하려면 시뮬 엔지니어링·데이터·QA에 인하우스를 집중하고 대량 에셋·번역을 외주로 스케일해야 한다.

| 역할 | 인원(기준선) | 핵심 책임 | 주 소관 문서 |
|---|---|---|---|
| **PM/프로듀서** | 1 | 로드맵·게이트·백로그·리스크 오너, 외주 관리, 스토어 관계 | 본 문서, `marketing §5.3` |

## A2. 개발 단계(Phase) 로드맵

각 단계는 **목표 · 산출물 · Exit 게이트**를 가지며, Exit 게이트는 앞선 문서의 게이트를 인용한다. 게이트 미충족 시 다음 단계로 넘어가지 않는다(P5는 병렬 스코프를 감당 못 하므로 게이트 규율이 곧 일정 방어선).

### Phase 0 — 프리프로덕션
- **목표:** 정본 문서 세트 정합 확정, 기술 스파이크, 스코프·컷 우선순위 동결.
- **산출물:** 확정 문서 세트(본 문서 포함), 기술 스파이크 결과(해시 PRNG·고정소수 스케일·코어 언어·엔진 후보, `technical §14-1·2·3·9`), 스타일 가이드·색 토큰 v0(`art 열린1`), 리아 캐스팅 착수, 통합 백로그(§A3).
- **Exit 게이트:**
  - [ ] `technical §13-①~⑦` 7개 인계 항목 중 **리플레이 비호환 유발 항목(해시 PRNG·고정소수 스케일)의 런치 전 동결 계획 확정**(`technical §14-1` "런치 전 동결 필수").
  - [ ] §A4 MVP 스코프 표 승인 + §A4.3 컷 우선순위 합의.
  - [ ] §A5 게임 규칙 개정 안건의 **런치 전/후 분류** 승인.
  - [ ] DoR 체크리스트(§C10.1) 통과.

### Phase 1 — 프로토타입 (코어 루프 검증)
- **목표:** 결정론 코어로 **코어 루프 1사이클**(`GD §2.2` 5단계) + 월말 정산(`GD §2.3`)을 헤드리스로 성립. "재미"보다 **결정론·시간 모델**을 먼저 증명.
- **산출물:** 엔진 비의존 L1 시뮬(채용→편성→하달→진행→완료→급여, `GD §2.6`), 골든 리플레이 하니스(`technical §11`), 회사 순서 무관성 프로퍼티(DD-f), 최소 UI(디버그).
- **Exit 게이트:**
  - [ ] **결정론 골든 리플레이** green: `(master_seed, 시작 스냅샷, 명령 로그)` → 상태 해시 고정(`mechanics-spec §1.1` 불변식 D, `technical §11`).
  - [ ] **회사 순서 무관성(DD-f)** green: slot_idx 임의 순열에도 상태 해시 동일(`MS §9.6`, `technical §11`).
  - [ ] **부동소수 금지** 애널라이저 green(코어에 `float/double/System.Random/DateTime.Now` 없음, `technical §11`).
  - [ ] **사이클↔실시간 매핑 프로토 결정**(§A5-2 의존성): 1사이클=실시간 얼마 + 오프라인 상한 `DAY_OFFLINE_CAP`의 1차안 확정, 설계 리뷰에서 `GD §2.1` 턴제 의도와의 상충 여부 판정(상충 시 §A5-2 개정 격상).

### Phase 2 — 버티컬 슬라이스 (1개 업종 풀스택)
- **목표:** **무역 1업종**을 규칙+수치+표현+사운드까지 관통(권장 튜토리얼 업종, `GD §12.5`, `balance §3.1`). 재미·페이싱·톤을 처음으로 체감.
- **산출물:** 무역 3부서 카탈로그 + 고유 메커닉(시세 `μ`, `GD §12.2`/`balance §5.2`), 대표 화면 세트(S0/S2/S5/S6/S7/S11 등 `ux §3`), 무역 L2 음악 레이어(MUS-03, `audio §8.1`), 강도 4단계 VFX(`art §8.1`), 리아 기본 표정 세트(`art §4.6`).
- **Exit 게이트:**
  - [ ] 코어 루프가 **소리·시각·햅틱으로 판독 가능**(무음 플레이 통과 테스트 초판, `accessibility §4.3`, `audio §8.3-5`).
  - [ ] 무역 가드레일 1·2·4(양의 마진/자율 생존/초기 자본, `balance §8`) 헤드리스 시뮬 통과.
  - [ ] 온보딩 M1~M6 튜토리얼리스 플로우 성립(`ux §4.1·§8`).
  - [ ] 강도 4단계 연출 예산(0.6/1.0/1.5s, `art §8.1`) 준수.

### Phase 3 — MVP (3업종 · 피처 컴플리트)
- **목표:** `GD §13` MVP 범위 **전량** 구현. 3업종×3부서, 7시스템, 자율 주행, 멀티 컴퍼니(슬롯 10), 완주.
- **산출물:** §A4 "MVP 포함" 전 항목, i18n 인프라(외부화·ICU·폰트 커버리지, `accessibility §8`), ko/en 문자열·이름 풀·용어집, 3업종 고유 메커닉 최소형(시세/꼬리+흥행 롤/라인 감쇠, `GD §12.7`), IAP 뼈대(비-P2W SKU, `monetization §10`).
- **Exit 게이트:**
  - [ ] §A4 "MVP 포함" 항목 = 기능/콘텐츠 컴플리트.
  - [ ] CI 3대 게이트 상시 green: 골든 리플레이 · DD-f · 세이브 마이그레이션 라운드트립(`technical §11`, `liveops §11.2`).
  - [ ] **i18n 인프라 완성**(하드코딩 문자열 빌드 차단, `accessibility §8.1`) — "1차 런치 전 완성 필수"(`accessibility §12`).
  - [ ] `balance §8` 9개 가드레일 전항 헤드리스 시뮬 검증.

### Phase 4 — 알파 (콘텐츠·밸런스 컴플리트, 내부)
- **목표:** 밸런스 1차안 튜닝, 접근성/현지화 게이트 도입, 내부 드라이브 테스트.
- **산출물:** `balance` 1차안 계수 적용 + 헤드리스 회귀 세트, 접근성 3게이트 CI 도입, 색맹/대비/길이 예산 자동 검사(`accessibility §1.4·§2.2·§10.3`), 텔레메트리 이벤트 카탈로그(`liveops §2.4`) 계측.
- **Exit 게이트:**
  - [ ] **접근성 3게이트 통과**(§B1.5): 무음 완전 플레이 · 대비 4.5:1/3:1(라이트·다크 독립) · 길이 예산 오버플로우 0.
  - [ ] `balance §8` 가드레일 + `liveops §3.1` 밸런스 실측 항목 텔레메트리로 관측 가능.
  - [ ] 크래시/불변식 위반 0(헤드리스 퍼즈·롱런, `technical §11`).
  - [ ] 성능 예산 내(만재 10사 캐치업, `technical §9.2`).

### Phase 5 — 베타 / CBT (외부 클로즈드)
- **목표:** KO 우선 클로즈드 베타로 코어 루프·페이싱·현지화·온보딩 검증 + 커뮤니티 시드(`marketing §5.1`).
- **산출물:** TestFlight/Play 내부·비공개 테스트 빌드, 온보딩 퍼널 계측(M1~M6, `liveops §3.2`), 플레이테스트 설문·세션 관측(§B2).
- **Exit 게이트:**
  - [ ] **CBT 크리티컬 이슈 해소**(`marketing §5.2` 소프트런치 진입 게이트).
  - [ ] 온보딩 M6 완료율 ≥ 경보선(≥45~55%, `liveops §4.4`)·튜토리얼 마찰 진단 완료.
  - [ ] 결제 플로우·영수증 검증·복원 E2E green(`monetization §8.2`, `technical §10.1`).
  - [ ] 스토어 리스팅(ASO 자산) 라이브 준비(`marketing §3`).

### Phase 6 — 소프트런치 (이중 트랙)
- **목표:** (A) 영어권 tier-2로 EN 리텐션·수익화·크리에이티브 튜닝 + (B) 한국 제한 소프트런치로 KO 검증(`marketing §4.2` 설계 결정). 리텐션·페이싱·튜토리얼 마찰 진단이 최우선(`marketing §4.2` 우선순위 ①→②→③).
- **산출물:** 라이브 대시보드 D1~D7(`liveops §4.1`), 알람 임계 가동(`liveops §4.4`), 소프트런치 게이트 지표 실측(`marketing §4.2`).
- **Exit 게이트(= 스케일 테스트 진입, `marketing §5.2` 2단계):**
  - [ ] 소프트런치 게이트(`marketing §4.2`) 통과: 튜토리얼 완료율·D1/D7/D30 리텐션·세션·CPI·ARPDAU/전환·ROAS 궤적이 기준선 방향 충족. **정량 목표치는 `liveops`·`balance`와 소프트런치 실측으로 확정**(§열린 질문, 현재 미확정).

### Phase 7 — 글로벌 런치 (KO/EN)
- **목표:** 볼륨·피처링·PR 집중. 리텐션·페이백 게이트 통과를 **하드 전제**(`marketing §5.2` 설계 결정).
- **산출물:** 글로벌 스토어 라이브, 피처링 피치(`marketing §5.3`), 런치 크리티컬 게이트 통과 빌드.
- **Exit 게이트:**
  - [ ] **ROAS/리텐션 스케일 게이트**(`marketing §4.5`): 페이백 윈도 내 회수 전망 + 리텐션 하한 + CPI 상한 동시 충족.
  - [ ] **런치 준비도 DoD 체크리스트**(§C10.2) 전항 통과.
  - [ ] 스토어 정책 준수(`monetization §8.3`) + 동의 문구 전 로케일(`accessibility §11.3`).

### Phase 8 — 지역 확장 (JP → CN)
- **목표:** 신규 시장 로컬라이즈드 런치. ja 먼저, zh-Hans는 배포 전략·규제 결정 후.
- **Exit 게이트:**
  - [ ] ja: 전 문자열+이름 풀+가챠 자율규제 점검(`accessibility §11.2·§12`), 일본 시장 지표(`marketing §7.2`).
  - [ ] zh-Hans: 배포 전략 분기(글로벌 중화권 vs 본토). **본토는 판호·실명·미성년 시간제한 별도 고비용 규제 트랙**(`accessibility §12` 설계 결정, `monetization §열린9`) — 언어 확장을 규제 리스크에 묶지 않음.

### Phase 9 — 라이브옵스 (Live)
- **목표:** 지속 운영. 예외 기반 운영(`liveops §6.1`).
- **케이던스(`liveops §6.2`):** 일간(자동+경보) · 주간(리텐션·오퍼·CRM) · 시즌 6주(시즌 패스·코스메틱 로테이션, `monetization §3.6`) · 분기~반기(**신규 업종 팩** 배포 `GD §12.8`/`liveops §7.3`, 밸런스 회귀·마이그레이션).
- **상시 게이트:** 릴리스·회귀 게이트(§B3.5, `liveops §11.2`) 매 릴리스 통과. 라이브 헬스 임계(`liveops §11.1·§4.4`) 초과 시 §B3.6 롤백 절차.

### A4.3 컷 우선순위 (지연 시 순차 컷)
**설계 결정: 아래 순서로만 컷한다(코어·게이트 불변).** 근거: 결정론 코어·경제 가드레일·접근성 3게이트·비-P2W는 게임의 정합성·규제·신뢰 기반이므로 컷 불가. 컷은 "표현 물량 → 콘텐츠 폭 → 편의"로만.

1. **1순위(먼저 컷):** 표현 물량 축소 — 오피스 시간대·활기 표현(`art §5.6`), 완주 엔딩 컷신(텍스트 회고로 대체, `art 열린8`/`narrative 열린7`), VFX 변주 폭, MUS-09.
2. **2순위:** 코스메틱 SKU 폭·시즌 로테이션 초기 물량(핵심 수익 SKU는 유지).
3. **3순위:** 업종 3종 중 1종을 소프트런치 후로 이연(단 최소 2업종 유지 — 멀티 컴퍼니·업종 서열 검증에 2종 필요, `balance §5.5`). **단 결정론·경제 가드레일·3게이트·비-P2W·코어 루프는 절대 컷 금지.**
4. **컷 금지(하드):** L1 결정론 코어, `balance §8` 가드레일, 접근성 3게이트, i18n 인프라, IAP 영수증 서버 검증, 세이브 마이그레이션.

### B1.5 접근성 / 현지화 3게이트 (A0 — 출시 차단)
`accessibility` 3게이트를 QA 필수 게이트로 배치(무음 테스트는 `audio §8.3-5`와 **단일 테스트로 통합 운영**, 중복 방지).

- **게이트 A — 무음 완전 플레이(Silent Play, `accessibility §4.3`):** 마스터 볼륨0 + 시스템 무음 + 햅틱 off에서 온보딩 M1~M6·코어 루프 1사이클·위기 복귀·흥행 롤 결과 인지·청산/설립·월말 결산을 **시각(필요시 햅틱)만으로 완주 가능**. 오디오 리던던시 계약(`audio §5.1`: 대응 시각 없는 사운드 이벤트는 반려) 위반 검출.
- **게이트 B — 명도 대비(Contrast, `accessibility §2.2·§1.4`):** 본문 ≥4.5:1, 큰 텍스트 ≥3:1, 아이콘·경계·UI 컴포넌트 ≥3:1. **라이트·다크 각각 독립 만족**(한쪽만 통과 토큰 불합격). 업종 틴트 배경 위 텍스트도 4.5:1. **CI 자동 대비 검사**(색 토큰 확정 후). 색맹 4중 부호(색+아이콘+텍스트+배치, `ux §7.1`)·부실/파산 패턴 부호(`accessibility §2.1`) 검증.
- **게이트 C — 길이 예산(Text-Length Budget, `accessibility §8.4·§10.3`):** 알림/큐 ≤40자·1행, 버튼·라벨·스탯명 ≤6자, 프로젝트 플레이버 ≤24자·1행 — **3개 문서 단일 기준**(`ux §9`=`narrative §7.1`=`accessibility §8.4`). **CI 자동 회귀:** 각 로케일 빌드에서 예산 초과·잘림(…)·오버플로우 검출, 1행 상한 위반 우선. 최대 텍스트 크기 × 최장 로케일 곱집합 검증(`accessibility §10.3`). KO 기준 +40% 흡수.
- **부수 게이트:** 글리프 누락(두부 □) 0 출시 게이트(`accessibility §8.3`), 하드코딩 문자열 빌드 차단(`§8.1`), 모션 감소·플리커(초당 3회 초과 금지, `§2.6`), 터치 타깃 48dp/44pt(`§3.1`), 제스처 전면 탭 대체(`§3.3`), 강한 확인 2스텝·명령 거부 사유 명시(`§3.4`, `ux §7.2·§7.3`), 확률 공시 문구(`§11.2` — §B3.7 규제 체크와 연동).

### B1.6 결제 · 안티치트
- **결제 E2E:** 구매 시작→영수증→검증→엔타이틀먼트→복원, 실패/취소/환불/구독 갱신·이탈 경로(`monetization §8.2`, `liveops §3.2` 결제 퍼널). 서버 영수증 검증·트랜잭션 유니크·엔타이틀먼트 원장(`technical §6.1·§10.1`) — 클라 신뢰 0.
- **안티치트(위협별 방어 수위, `technical §10.1`):** 결제 우회=**강**(서버 권위), 세이브 변조=경~중(로컬 HMAC), 시계 조작=중(서버 시각·상한), 클라우드 세이브 롤백=중(버전 카운터). **MVP는 상시 서버 검증 불필요**, 분쟁·어뷰징 샘플 재실행 옵션 보유(결정론 코어 서버 재실행, `§3.2`). post-MVP 경쟁 콘텐츠 도입 시 해당 부분만 서버 권위 승격(§A5-4).

### B1.7 디바이스 매트릭스 · 성능

### B3.1 버그 트래킹 · 결정론 재현
- **필수 첨부(결정론 재현):** 모든 크래시/버그 리포트에 `master_seed`+`day`+세이브 스키마 버전+명령 로그 첨부 → 로컬 결정론 재현(`technical §11`, `MS §11`). 이것이 P5 QA의 최대 레버리지.
- **트래커 필드:** 심각도·재현율·플랫폼/기종·빌드·밸런스 버전·A/B 그룹·첨부(seed/로그/세이브).

### B3.2 심각도 등급 (라이브 헬스 임계 정합)
`liveops §4.4` 2단계 알람(경보/주의)과 정합.

| 심각도 | 정의 | 예 | 대응 |
|---|---|---|---|
| **S1 Critical(차단)** | 진행 불가·데이터 손실·결정론 붕괴·결제 손실·규제 위반 | 골든 리플레이 실패, 세이브 손상, 영수증 검증 실패, 확률 공시 누락 | **릴리스 차단/롤백**, 핫픽스 |
| **S2 Major** | 핵심 기능 손상·심한 밸런스 붕괴·접근성 게이트 위반 | 파산율 급증, 대비/무음/길이 게이트 위반, 온보딩 급락 | 다음 릴리스 필수 |
| **S3 Minor** | 국소 오작동·경미 표현 결함 | 표현 어긋남, 드문 엣지 | 백로그 우선순위화 |
| **S4 Trivial** | 미관·오탈자 | 카피·정렬 | 여력 시 |

### B3.3 리그레션
- **자동 리그레션(상시):** §B1.1 CI 게이트 + 접근성 3게이트 CI + 성능 벤치. 세이브 마이그레이션 골든이 **구버전 픽스처를 영구 보관**(스키마 진화 회귀).
- **수동 리그레션(릴리스 전):** 핵심 플로우 6종(`ux §4`) 스모크 + 결제 E2E + 디바이스 팜.

### B3.4 릴리스 체크리스트 (매 빌드)
- [ ] CI 3대 게이트 green(골든 리플레이·DD-f·마이그레이션, `technical §11`/`liveops §11.2`).
- [ ] 부동소수 금지·정수 항등·불변식 스위트 green.
- [ ] 접근성 3게이트(무음·대비·길이) + 글리프 0 + 하드코딩 차단 green.
- [ ] 성능 벤치 예산 내(`technical §9.2`).
- [ ] 결제 E2E + 복원 green, 스토어 정책 준수(`monetization §8.3`).
- [ ] 콘텐츠 팩·리모트 config **스키마 호환 검사** 통과(앱 빌드와 분리 배포, `technical §7`/`MS §11`).
- [ ] 밸런스 버전 변경 시 헤드리스 가드레일 회귀 통과(`liveops §11.2`).

### B3.5 라이브 릴리스·회귀 게이트 (`liveops §11.2` 위임 수령)
- 결정론 골든·DD-f·세이브 마이그레이션 통과 = 릴리스 필수 조건. 실패는 Critical(`liveops §4.4`).
- 밸런스 회귀 게이트: 밸런스 버전 변경 시 만재 세이브×N사이클 헤드리스 시뮬로 가드레일 실측 사전 재검증 후 마이그레이션/코호트 배포.

### B3.6 라이브 핫픽스 QA (밸런스 결정론 경계 준수)
**설계 결정: 라이브 밸런스 핫픽스는 결정론 세이브 핀 경계를 준수한다.** 근거: 진행 중 세이브는 밸런스 버전 핀으로 불변(`technical §7.3`, `liveops §6.3`). 밸런스 값(`α_auto`·`Cap_ref`·보상 커브)은 **신규 코호트/명시적 마이그레이션 경계에만** 반영.
- **롤백 절차(본 문서 소관, `liveops §11.2` 위임):**
  1. 라이브 헬스 임계 초과 감지(`liveops §4.4` 경보) → 온콜 PM/엔지니어.
  2. **리모트 config 즉시 조정 가능 범위**(오퍼·이벤트·CRM·A/B 비율, `liveops §6.3`)는 코드 배포 없이 롤백.
  3. **실행 코드/규칙**은 스토어 재심사 필요 → 이전 빌드 채널 롤백 + 핫픽스 파이프라인.
  4. **밸런스 긴급 마이그레이션(치명적 exploit·소프트락):** 밸런스 핀 불변 원칙의 예외로, "긴급 마이그레이션" 경계 절차 적용(`technical §14-6`, **절차 미확정 — §열린 질문**). 결정론 리플레이 비호환을 유발하지 않도록 명령 로그·세이브 버전 승급 골든 재검증 필수.
  - **SLA/책임자:** 온콜 로테이션·심각도별 대응 시간·에스컬레이션 경로를 라이브 진입 전 확정(P5 겸직 전제, 예외 기반 운영).

### B3.7 스토어 심사 대비 체크리스트
`monetization §8.3` + `accessibility §11` 종합.

## 열린 질문

본 문서는 앞선 문서의 게이트·개정 태그·열린 질문을 일정·QA·리스크로 종합했다. 아래는 **프로덕션/QA/리스크 확정을 위해 타 파트와 함께 답할 미결 사항** 및 **교차 문서 미결 안건**이다.

1. **사이클↔실시간 매핑·오프라인 상한**(§A5-2) — 1사이클=실시간 얼마, `DAY_OFFLINE_CAP` 값·초과분 처리(버림/이월). `GD §2.1` 턴제 의도와 상충 여부. 이것이 시간 단축 상품 가치·완주 활성시간·방치 소구·리텐션을 동시에 좌우(`monetization §열린1`·`technical §14-5`·`balance §10-12`·`ux §11-1`·`marketing §11` 공동). **런치 전 필수, 상충 판정 시 game-design 개정 격상.**
2. **소프트런치 게이트 정량 목표치**(R-M5) — 리텐션·CPI·ROAS·페이백 윈도 수치가 marketing→liveops→balance→소프트런치 실측으로 **상호 이연**되어 현재 어디에도 확정값 없음. 소프트런치 개시 전 기준선 방향으로 운영하고 실측 후 확정하는 절차의 명문화 필요.
3. **밸런스 긴급 마이그레이션 예외 절차**(R-O1, §B3.6) — 결정론 세이브 핀 불변 원칙과 치명적 exploit·소프트락 핫픽스 사이의 "긴급 마이그레이션" 경계 절차(`technical §14-6`). 리플레이 비호환을 유발하지 않는 승급 골든 재검증 방법.
4. **확률 공시 적용범위**(R-O2, §B3.7) — 채용 지원자 풀 등급 분포(명성 연동 GradeDist)가 KR 게임산업진흥법 확률 공시 대상인지. `accessibility §11.2·§열린8`(대상 후보)와 `monetization §9.1`(적용 대상 아님)의 **교차 문서 판단 불일치** — 법무 클리어런스 필요.
5. **`liveops-analytics.md`의 marketing 부재 전제 스테일**(R-M 계열) — `liveops §12-C·§열린11`은 "marketing.md 부재"를 전제로 §1.3·§10.1 경계를 인터페이스 요구로만 남겼으나 **marketing.md는 이미 존재**한다. liveops의 UA 지표·커뮤니티 채널 소유권 경계를 marketing 확정 반영으로 **동반 갱신** 필요.
6. **외주 vs 인하우스 경계**(R-O5, §A1.3) — `art`·`audio` 문서가 정의하지 않은 외주 범위. 본 문서 잠정안(캐릭터 파츠·음악·번역·크리에이티브 외주)을 각 파트 리드와 확정, 발주 규격·스케줄 확정.
7. **엔진·코어 언어 최종 결정 시점**(R-T3) — Unity/Godot·C#/Rust 결정을 코어 프로토타입 이후로 미룰 때 표현 계층 착수 지연이 P5 일정에 주는 실제 영향(`technical §14-9·3`). 코어 격리의 지연 흡수량.
8. **런치 전 동결 항목 확정 스파이크**(R-T2) — 해시 PRNG(SplitMix64 vs xxHash64 vs PCG)·고정소수(`FP=10⁶` vs Q32.32)·세이브 포맷(FlatBuffers vs MessagePack)의 스파이크 완료 시점(`technical §14-1·2·8`). 전부 리플레이 비호환 유발이므로 크리티컬 패스.
9. **리아 캐스팅 통합 트랙**(R-X2) — `narrative 열린1`=`art 열린2`=`audio 열린1` 단일 미결이 마케팅 브랜드 보이스(`marketing §열린9`)까지 블로킹. 통합 확정 회의 일정.
10. **밸런스·규칙 열린 질문의 플레이테스트 소진 계획** — `GD §15`(13항)·`balance §10`(12항)·`MS §12`(9항)·`technical §14`(11항) 등 문서별 열린 질문을 어느 Phase의 플레이테스트/스파이크에서 소진할지의 매핑(본 문서가 §A2·§B2에 배치했으나 정량 목표·담당 확정 필요).
11. **README 상태 표 정합** — `README §0` 문서 맵이 #12(본 문서)·#8(marketing)을 ✅로 선표기했으나, game-design은 가장 먼저 확정되어 이후 개정 태그(§A5)를 미반영. 문서 세트 버전·상태의 일관 관리 규약 필요.
12. **whale 상한 vs 매출 목표 정합**(R-M2) — 성능 미판매로 낮아진 고과금 상한을 코스메틱 폭·시즌 로테이션이 메우는지, 매출 목표와의 정합(`monetization §열린6`·`liveops §열린5` 공동, 소프트런치 실측).
